# 상품 정보 도구

`/product-images`의 별도 메뉴에서 LF몰 상품코드로 이미지를 조회하고 가공한다. 관리자와 상품 담당자에게 제공한다. 기존 단독 이미지 도구를 현재 앱의 로그인·권한·CSRF·응답 규약과 모듈 경계에 맞춰 통합했다.

## 사용 흐름

1. 브랜드와 상품코드를 입력해 조회한다.
2. 사진을 끌어 순서를 바꾸거나 휴지통으로 제외한다. 첫 사진이 대표이며, 제외한 사진은 복구할 수 있다.
3. 우측 상품정보 위의 사이즈 영역에서 표기 사이즈·치수를 입력해 공용 사이즈 표본을 추가하거나, 선택한 상품 사진에 치수선을 배치해 사이즈 이미지를 만든다. 좁은 화면에서는 같은 영역을 상품정보 바로 위에 세로 배치한다.
4. 우측 상품정보의 값을 편집하고 제목 옆 ‘상품정보 이미지 추가’를 누른다. 짧은 항목 두 칸·긴 항목 전체 폭 배치는 최종 이미지 렌더러와 같은 계산을 사용한다. 상품코드와 A/S 책임자 항목은 편집 목록과 생성 이미지에서 제외한다. 조회용 상품코드는 유지한다.
5. 사이즈·상품정보를 추가하면 해당 시점의 PNG가 이미지 순서에 들어간다. 원본과 함께 끌어 순서를 바꾸거나 휴지통 이동·복구할 수 있다. 하단 공통 ‘저장용 상품코드’는 조회 성공 시 조회 코드로 채워지며 수정할 수 있다. ‘다운로드’를 누르면 이 코드로 이름과 루트 폴더를 정한 ZIP을 받는다. 사이즈 이미지는 `사이즈.png`, 상품정보 이미지는 `상품정보.png`로 저장한다. 여러 장이면 종류별로 `사이즈_2.png`, `상품정보_2.png`처럼 중복 번호를 붙인다.
6. ‘업로드’를 누르면 같은 저장용 상품코드와 공개 경로를 확인한다. 확인창은 선택한 코드를 읽기 전용으로 보여주며, 코드를 바꾸려면 취소 후 공통 입력을 수정한다. 예를 들어 조회 코드 `HIHO6F861W2`를 유지하면서 저장 코드를 `HIHO861W2`로 지정할 수 있다. 확인하면 휴지통을 제외한 현재 이미지 목록을 공개 R2 버킷에 순서대로 저장하고, 결과에 파일별 공개 주소를 표시한다. 다운로드 시작 또는 업로드 확인창을 여는 시점에 코드와 목록을 고정하고 처리 중에는 조회·편집·정렬·생성·다른 내보내기를 잠근다. 저장용 코드 입력의 Enter는 다운로드나 업로드를 실행하지 않는다.

추가한 이미지는 독립 스냅샷이다. 이후 치수·표기 사이즈·상품정보 값을 바꿔도 이미 추가한 PNG는 바뀌지 않는다. 바꾼 값으로 새 이미지를 추가하고 이전 것은 제외한다. 사진 기반 사이즈 이미지를 다시 편집하면 그 이미지의 생성 당시 치수·표기 사이즈·배치를 사용한다. 상품정보 편집은 이 페이지의 이미지 준비에만 적용하며 조회 원본을 수정하지 않는다.

상품컷에는 원본 도구의 하단 흰 여백 10px 처리를 유지한다. 사진 기반 사이즈 이미지는 미리보기·저장 모두 2880×1880px로 직접 렌더링한다. 일반 실루엣 사이즈·상품정보 이미지는 기존 780px 폭을 유지한다. 사진과 비교 대상은 원본에서 단계적으로 리샘플링해 축소 시 계단 현상과 투명 가장자리 손실을 줄인다. 원본 자체의 낮은 해상도나 압축 손실을 복원하지는 않는다. 상품정보는 최종 출력 기준으로 글씨를 이전보다 2px 줄이고 카드 안팎·줄 사이의 여백을 줄였다. 긴 값은 필요한 높이로 늘어나며 잘리지 않는다. 이는 수동 작업용 산출물이며 판매 마켓 등록 요청이나 공통 상품·매입처·보유 재고 저장을 수행하지 않는다.

웹서버의 Downloads 폴더에 저장하거나 서버의 Finder를 실행하지 않는다. 사용자의 PC·휴대전화가 ZIP을 내려받는다. 새 조회·페이지 새로고침은 편집 중 순서와 휴지통 상태를 초기화한다. 생성 이미지·다운로드 결과는 임시 보관이며 서버 재시작이나 보관 기간 만료 후에는 다시 만들어야 한다.

공개 상품 이미지의 R2 저장 위치는 `molebutter` 버킷의 `products/{저장할 상품코드}/{분류}/{파일명}`다. 조회 사진은 `official`, 서버에 보관된 사이즈·상품정보 PNG는 `processed`로 분류한다. `processed`는 작업 결과 폴더이며, 직접 촬영 원본용 `original`은 이번에 생성하거나 사용하지 않는다. UUID 중간 폴더는 생성하지 않는다. 저장 코드는 영문·숫자·밑줄·하이픈 4~40자이며 대문자로 정규화한다. 최종 저장 경로·파일명·확장자가 같은 파일만 중복 제외하고 없는 파일을 추가한다. 분류 폴더가 다르면 다른 파일이며 과거 평면·UUID 경로는 해당 최종 키와 다르면 차단하지 않는다. 기존 파일은 이동·삭제·덮어쓰기하지 않는다. 결과에는 업로드·중복 제외 수와 파일 목록을 나누어 표시한다. 모두 중복이면 공개 이미지 쓰기 없이 종료한다. 일반 사진 번호는 현재 선택 순서 기준이며 기존 번호로 자동 대응하지 않는다. 조회나 PNG 추가만으로 업로드하지 않고, 업로드 확인 버튼을 눌렀을 때만 저장한다. 상품 사진·상품정보는 ZIP과 같은 가공 바이트를 사용한다. 사이즈 이미지는 R2 업로드용 복사본만 가로 750px, 세로는 비율을 유지해 반올림한 크기로 변환한다. 편집 프리뷰·확정 원본·ZIP은 기존 해상도를 유지하며, 확장자는 실제 이미지 형식을 따른다. [저장 경로와 공개 URL 규칙](r2-storage.md#상품-이미지-경로)을 참고한다.

일부 파일만 성공하면 저장된 파일 목록과 오류를 표시하고 이후 전송을 멈춘다. 결과 확정 후 새 요청에서는 기존 파일을 제외하고 남은 파일을 업로드할 수 있다. 응답 유실은 ‘결과 확인 필요’로 표시하며 새 업로드를 막고 같은 요청 ID를 조회한다. 서버는 R2의 크기·형식·SHA-256·작업 ID가 일치하는 경우에만 저장을 확정한다. 객체가 아직 조회되지 않아도 실패로 단정하거나 이미지 쓰기를 자동 반복하지 않는다. 새로고침 후 같은 탭의 보류 요청은 `sessionStorage`에서 복원해 조회하며, 서버 기록이 없을 때의 명시적 재시도도 같은 ID와 입력을 사용한다. 대상 키별 조회 실패는 빈 경로로 해석하지 않고 공개 파일 쓰기 전에 작업 실패로 표시한다. 진행 중 예약의 명시적 거절은 확인창과 입력을 유지한다.

## 사진 사이즈 편집의 비교 대상

상품 사진은 별도의 불투명도 감소 없이 원래 색상으로 표시한다. 원본 이미지 자체의 투명 배경은 흰 캔버스에 합성하며, 편집 미리보기와 최종 PNG에 동일하게 적용한다. 치수선·숫자는 사진 위에 그린다.

비교 이미지 안쪽 하단에는 `삼다수 500ml`, `iPhone 16`처럼 핵심 모델명만 표시한다. 반투명 바탕과 자동 줄바꿈으로 본체 안에서 표시하며 캡션용 외부 공간 때문에 추가 축소하지 않는다. 기준 높이 문구는 최종 이미지에 넣지 않으며, 편집기의 기준 치수 안내와 배율 계산에는 그대로 사용한다.

사진 편집의 ‘비교 대상 추가’에서 중복 없이 최대 8개를 함께 선택한다. 기본 선택은 비어 있으며, 선택 목록에서 각각 제거하거나 전체 제거할 수 있다. 추가한 대상은 기존 대상 오른쪽에 배치하고 각각의 ◆ 핸들로 독립 이동한다. 삼다수 500ml(사용자 제공 높이 21cm), iPhone 16, Galaxy S26 기본형, iPad Air 11·13(M4), MacBook Air 13·15(M5), MacBook Pro 16(M5)을 제공한다. 휴대폰·태블릿은 세로 정면, 노트북은 닫힌 상판을 위에서 본 모습이다. 인치나 화면 대각선이 아닌 본체 가로·세로 치수를 사용한다. 현재 모델 8종은 로컬 누끼 PNG(v2)다. 삼다수는 투명 여백을 제외한 병 본체 비율과 높이만 교정하며 가로 실측값은 표시하지 않는다. 과거 삼다수 v1 그림(가로/높이 0.30)은 기존 편집본 복원용으로 보존한다. 전자기기 v1 편집본도 기존 치수·좌표를 유지하며 사진으로 표시한다. [사진 출처·편집 및 검증](verification/2026-10-19-comparison-product-photos.md)을 참고한다.

배율은 1440×940 작업 좌표의 높이 점선 길이(px)를 상품 높이(cm)로 나눈다. 높이 10cm·점선 100px이면 물병 높이는 210px, 점선 200px이면 420px다. 사용자는 높이 점선을 실제 상품의 세로 범위에 맞춰야 한다. 물병 가로 실측값은 높이 배율 계산에 필요하지 않다. 비교 대상 사용 중 높이 선은 수직으로 고정하며 기존 기울어진 선은 중간 X좌표로 정렬하고 Y좌표는 유지한다. 높이·선이 없거나 길이가 0이면 비교 이미지 생성을 거절한다.

상품 배율은 최종 출력의 `layout.photo.scale`이다. 슬라이더는 비교 선택 전후 항상 0.01~2.5 범위이며 현재 배율과 현재 배치의 최대 배율을 별도로 표시한다. 상품·모든 점선·비교 대상을 공통 확대·축소하고, 최대값을 넘는 입력은 표시된 최대 배율에서 제한한다. 원본 사진의 흰색·투명 배경 여백은 맞춤 대상에서 제외한다. 현재 상품 본체·치수선과 숫자·비교 대상·캡션이 표 위 공간을 실제로 넘을 때만 공통 축소·이동한다. 미래 최대 배치의 공간을 미리 확보하지 않는다. 맞춤 결과를 출력 좌표와 실제 사진 배율에 반영해 돌려주므로 숨은 배율이 없고 재편집·생성에서도 같은 크기를 사용한다. 비교 해제 시 현재 상품 배율은 유지하며 새로 생긴 여유 공간만 최대 배율 계산에 반영한다. 아래 사이즈 표는 고정한다. 비교 대상과 실제 상품 중심의 이동 핸들은 마우스·터치와 방향키(Shift는 큰 이동)를 지원한다.

프리뷰·생성 요청은 `layout.comparisons` 배열에 `{presetId, version, centerXRatio, baseYRatio}`를 보관한다. 명시적인 빈 배열은 전체 해제이며, 배열이 없으면 과거 `layout.comparison` 단일 값을 복원한다. 응답의 `comparison`은 첫 번째 대상의 호환 표시다. 배열 전체를 생성 스냅샷에 보존한다. 위치 두 값은 함께 생략/null로 보내면 서버가 실제 상품 본체·치수 숫자 오른쪽에 배치하고 높이 선 아래쪽에 밑면을 맞춘다. 응답의 선택적 `layout.outputSpace=true`는 맞춤을 반영한 출력 좌표임을 뜻하며 저장·재편집 시 그대로 보존한다. 원본의 배경 여백이나 편집 중 이동 때문에 사진 중심·점선의 가상 좌표는 0~1 밖에 있을 수 있으나 유한한 ±10000 범위로 제한한다. 출력 좌표의 사진 배율은 0.01~2.5이고, 과거 입력(`outputSpace` 생략/false)의 0~1 좌표·0.3~2.5 배율 검사와 생성자는 유지한다. 모델 ID·버전·좌표를 서버가 검사하고 치수는 클라이언트에서 받지 않는다.

`GET /api/product-images/size-guide/comparisons`는 기존 상품 업무 권한으로 `{id, version, name, widthCm, heightCm, aspectRatio, kind}` 목록을 반환한다. `widthCm=null`은 가로 실측 근거가 없는 비교 대상이다. 기존 프리뷰 응답의 `sceneTransform`은 유지하되 새 출력 좌표 응답에서는 항등 변환이다. `photoView={maximumScale, subjectOffsetXRatio, subjectOffsetYRatio}`는 현재 배치의 출력 배율 상한과 실제 상품 중심의 사진 중심 대비 오프셋이다. 사진 이동 핸들이 원본 배경 중앙에 놓이지 않도록 사용한다. 프리뷰와 최종 PNG는 동일한 렌더러로 만들고, 생성 이미지의 편집 스냅샷에 비교 설정과 출력 좌표를 포함한다. 최종 PNG·ZIP·R2 이미지에 비교 대상이 그대로 들어간다. 실행 중 모델 규격이나 이미지를 외부에서 다운로드하지 않는다.

[고해상도·다중 비교 검증](verification/2026-10-21-size-multi-comparison.md)을 참고한다. 기존 비교 없는 레이아웃과 일반 실루엣 이미지는 유지한다. 선택 해제는 비교 대상만 제거하고 초기화는 비교를 끈 기본 배치로 돌아간다. 목록·프리뷰 실패 시 편집값을 보존하며 닫힌 모달·이전 편집의 응답은 현재 입력을 덮어쓰지 않는다. 모델 규격 변경은 새 ID/버전으로 추가하고 기존 버전은 보존한다. 신규 DB 구조나 이미지 업로드 정책 변경은 없다.

## 구현 경계

- `molebutter-imaging`: LF몰 조회, 응답 해석, 치수·템플릿, 이미지 렌더, 임시 캐시·생성 이미지·다운로드 작업과 소유권이 확인된 파일 내보내기를 소유한다. 공개 계약은 `imaging.api`, 구현은 `imaging.internal`에 둔다.
- `molebutter-app`: Thymeleaf 화면, 정적 자원, 현재 사용자 확인, HTTP 응답·오류 변환, ZIP 첨부 응답과 R2 업로드 작업을 담당한다. `imaging.api.ImageExportPlan`과 `storage.api.ObjectStorage`를 조합하며 이미지 모듈은 저장 모듈에 의존하지 않는다.
- `MenuSection.PRODUCT_IMAGES`: 화면 `/product-images`와 API `/api/product-images/**`의 권한을 연결한다.

다른 사용자의 생성 이미지·작업·ZIP에 접근할 수 없게 사용자 ID를 서버에서 전달한다. 클라이언트가 제공한 사용자 ID를 소유권 판단에 사용하지 않는다. 명시적으로 조회할 때 사용자·상품·브랜드별 목록 스냅샷을 보관하고 편집·다운로드에서 사용한다. 다운로드 작업은 접수 시 그 목록을 고정한다. 새 화면은 원본 순번과 함께 조회 당시 URL도 보내므로 같은 사용자의 다른 탭에서 목록이 바뀌어 순번과 URL이 달라지면 재조회를 안내하고 전송을 거절한다. 이미지 URL과 리디렉션은 HTTPS LF몰 호스트 경계로 검사하고, 외부 응답과 이미지 디코딩 크기·작업 수·보관량을 제한한다. 로컬 파일 경로는 API 입력이나 결과에 포함하지 않는다.

LF몰 조회는 원본 도구의 비공식 조회 경로를 사용한다. 판매 마켓 API와 분리되어 있으며 외부 응답 변경 시 파서 조정이 필요할 수 있다. 통합 검증은 모의 응답을 사용한다.

## HTTP 계약

| 메서드·경로 (`/api/product-images` 하위) | 기능 |
|---|---|
| `GET /products/{code}?brand=` | 상품 이미지·가격·고시·치수 조회 |
| `GET /size-guide/templates` | 지원 사이즈 템플릿 |
| `GET /size-guide/comparisons` | 고정 비교 대상 모델·버전·본체 치수 |
| `POST /products/{code}/size-guide/preview` | 사진·치수 배치 미리보기 |
| `POST /products/{code}/size-guide/images` | PNG 스냅샷 생성 |
| `POST /products/{code}/notice-image/preview` | 편집한 상품정보의 카드 배치 계산 |
| `POST /products/{code}/notice-image/images` | 편집한 상품정보 PNG 스냅샷 생성 |
| `POST /products/download` | 순서대로 ZIP 생성 작업 접수 (`202`) |
| `GET /products/download/jobs/{id}` | 본인 작업의 상태·파일 목록 |
| `GET /products/download/jobs/{id}/archive` | 완료한 본인 ZIP 다운로드 |
| `POST /products/upload` | 공개 R2 업로드 작업 접수 (`202`) |
| `GET /products/upload/jobs/{id}` | 본인 업로드 상태·공개 주소·결과 확인 |

새 화면은 `images: [{imageIndex: 2, sourceImageUrl: "https://..."}, {generatedImageId: "..."}, {imageIndex: 0, sourceImageUrl: "https://..."}]`처럼 원본 인덱스와 사이즈·상품정보 생성 ID를 섞어 보낸다. 서버는 ZIP 항목의 순서를 유지하며 원본 사진은 목록 위치의 번호를, 생성 이미지는 종류별 `사이즈.png`·`상품정보.png`와 중복 번호를 파일명으로 사용한다. 같은 파일명을 ZIP과 R2의 분류 폴더에 적용하고 최종 객체 키별 중복 검사·진행 작업의 비공개 예약과 개별 조건부 생성으로 기존 파일을 보호한다. 생성 종류는 서버에서 보관하므로 브라우저가 파일 종류를 지정하지 않는다. 개별 항목은 원본 인덱스 또는 생성 ID 하나만 허용한다. `sourceImageUrl`은 원본 목록 일치 검사에 사용하며 클라이언트 주소를 그대로 다운로드하지 않는다. 새 화면은 `includeNoticeImage=false`로 자동 별도 파일 생성을 끄고, 목록에 추가한 상품정보 이미지만 보낸다. 이전 호출자의 `includeNoticeImage` 옵션은 호환성을 유지한다.

다운로드 입력은 기존 항목에 선택적 `downloadProductCode`를 받는다. 생략하면 조회 코드를 사용하며, 명시한 빈 값·잘못된 경로는 거절한다. 업로드의 `uploadProductCode`는 유지하고 두 값 모두 화면의 공통 입력에서 보낸다. 저장 코드는 ZIP 이름·내부 경로·R2 목적지에만 사용하며 원본 `productCode`·`brandCode`를 대신하지 않는다. `ExportImageDto.fileName`은 폴더 없는 파일명이고 서버가 결정한 `OFFICIAL`·`PROCESSED` 분류를 별도로 제공한다. 브라우저가 임의 분류나 폴더를 지정할 수 없다.

| 파일 종류 | ZIP 항목 (`WBBA162W3.zip`) | 공개 R2 키 |
|---|---|---|
| 조회 사진 | `WBBA162W3/official/01.jpg` | `products/WBBA162W3/official/01.jpg` |
| 사이즈 이미지 | `WBBA162W3/processed/사이즈.png` | `products/WBBA162W3/processed/사이즈.png` |
| 상품정보 이미지 | `WBBA162W3/processed/상품정보.png` | `products/WBBA162W3/processed/상품정보.png` |

사진의 순번은 혼합 목록의 위치를 유지하며 실제 MIME에 따른 확장자를 사용한다. 생성 이미지 추가 번호도 유지한다. 같은 상품에 없는 결과물을 나중에 추가할 수 있다. 기존 파일 교체는 제공하지 않는다.

상품정보 준비 입력은 `{brandCode, fields: {항목명: 편집값}}`이다. 서버는 사용자가 조회한 상품의 항목에만 덮어쓰기를 허용하며 알 수 없는 항목은 거절한다. 배치 응답 `cards`의 `fullWidth`로 화면의 두 칸·전체 폭을 결정한다. 빈 값은 이미지에서 제외하지만 화면의 입력란은 유지한다. 사이즈 준비 입력의 선택적 `sizeLabel`은 해당 이미지의 표기 사이즈만 바꾸며, 생략하면 조회 원본 값을 사용한다.

업로드 입력은 `{requestId, productCode, brandCode, uploadProductCode, images}`다. `productCode`는 관찰 목록과 소유권 확인에, `uploadProductCode`는 공개 폴더에 사용한다. 접수 시 원본 목록과 본인 생성 PNG를 고정하며 전체 파일 준비·크기·형식 검사를 끝낸 뒤 첫 R2 쓰기를 실행한다. 보관 중인 동일 ID·동일 입력은 기존 작업을 반환하고, 입력이 다르면 충돌로 거절한다. 다른 작성자의 작업은 조회할 수 없다. 오류 결과에는 외부 원문·자격 증명을 포함하지 않는다.

## 임시 보관과 설정

조회 캐시는 기본 10분이다. 사용자별 조회 목록과 생성 PNG는 4시간, 완료한 ZIP 작업은 기본 1시간 보관하고 매분 만료 항목을 정리한다. 사용자별 조회 목록은 전체 64개·사용자당 4개·추정 메모리 합계 16MiB까지 보관한다. 목록이 만료되거나 보관 한도를 넘으면 재조회를 안내한다. 생성 이미지는 전체 32개·16MiB, 사용자당 16개·8MiB까지 보관한다. 다운로드 작업은 전체 32개, 사용자당 동시 진행 2개까지 허용한다. 완료한 ZIP의 전체 보관량은 64MiB이다.

한 번에 최대 64개 사진을 요청할 수 있고, 이미지 파일당 10MB, 원본 픽셀 2천만 개, 다운로드 원본 합계 64MiB, ZIP 32MiB로 제한한다. 제한을 넘으면 이미지를 나누어 내려받도록 안내한다.

업로드 작업은 메모리에 확정 완료 후 4시간 보관하며 `UNKNOWN`은 시간 경과만으로 정리하지 않는다. 작업은 전체 32개·동시 실행 2개·작성자별 동시 실행 1개로 제한한다. 가공한 파일은 `cloudflare.r2.max-object-bytes` 이내, 전체 64MiB 이내여야 한다. 서버 재시작·만료로 결과 기록이 사라져도 저장된 R2 파일과 비공개 예약은 남는다. 기존 공개 파일은 최종 키가 같은 파일만 중복 제외하며 진행·미확인 예약이 있으면 해당 상품의 새 업로드를 보류한다. 재시작으로 결과 조회가 불가능해진 미확인 예약은 자동 해제하지 않으며 [잔존 예약 복구](r2-storage.md#업로드-결과와-잔존-예약-복구)를 따른다. 이 보호는 영구 실행 이력이나 미전송 파일의 자동 재개 기능과 구분한다.

| 설정 | 기본값 |
|---|---|
| `imaging.lfmall.api.base-url` | `https://nxapi.lfmall.co.kr` |
| `imaging.lfmall.api.affiliate-code` | `2000` |
| `imaging.http.connect-timeout` / `read-timeout` | `3s` / `30s` |
| `imaging.lookup.cache.ttl` | `10m` (최대 1시간) |
| `imaging.job.retention` | `1h` (최대 4시간) |
| `imaging.cleanup-delay-ms` | `60000` |
| `imaging.render.font.family` / `photo-family` / `notice-family` | `Malgun Gothic` (설치된 한글 폰트로 대체) |
| `imaging.render.font.number-family` | `Segoe UI` (설치된 폰트로 대체) |

설정은 기존 앱 설정 방식으로 전달하며 다른 기능의 HTTP·폰트·다운로드 설정과 분리한다. [테스트 안내](testing.md)에 통합 검증 결과를 기록한다. 원본 `is` 프로젝트는 수정하지 않는다.

상품 정보 도구의 신규 등록 자동 입력·계정 기본설정·직사각형 경고와 V51은 [등록 준비 안내](./coupang-registration-prefill.md)를 따른다.
