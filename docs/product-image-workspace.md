# 상품 이미지 도구

`/product-images`의 별도 메뉴에서 LF몰 상품코드로 이미지를 조회하고 가공한다. 관리자와 상품 담당자에게 제공한다. `/Users/lee/workspace/is`의 단독 도구를 현재 앱의 로그인·권한·CSRF·응답 규약과 모듈 경계에 맞춰 통합했다.

## 사용 흐름

1. 브랜드와 상품코드를 입력해 조회한다.
2. 사진을 끌어 순서를 바꾸거나 휴지통으로 제외한다. 첫 사진이 대표이며, 제외한 사진은 복구할 수 있다.
3. 우측 상품정보 위의 사이즈 영역에서 표기 사이즈·치수를 입력해 공용 사이즈 표본을 추가하거나, 선택한 상품 사진에 치수선을 배치해 사이즈 이미지를 만든다. 좁은 화면에서는 같은 영역을 상품정보 바로 위에 세로 배치한다.
4. 우측 상품정보의 값을 편집하고 제목 옆 ‘상품정보 이미지 추가’를 누른다. 짧은 항목 두 칸·긴 항목 전체 폭 배치는 최종 이미지 렌더러와 같은 계산을 사용한다. 상품코드와 A/S 책임자 항목은 편집 목록과 생성 이미지에서 제외한다. 조회용 상품코드는 유지한다.
5. 사이즈·상품정보를 추가하면 해당 시점의 PNG가 이미지 순서에 들어간다. 원본과 함께 끌어 순서를 바꾸거나 휴지통 이동·복구할 수 있다. ‘다운로드’를 누르면 현재 목록을 ZIP으로 받는다. 사이즈 이미지는 `사이즈.png`, 상품정보 이미지는 `상품정보.png`로 저장한다. 여러 장이면 종류별로 `사이즈_2.png`, `상품정보_2.png`처럼 중복 번호를 붙인다.
6. ‘업로드’를 누르면 저장할 상품코드와 공개 경로를 확인한다. 예를 들어 조회 코드 `HIHO6F861W2`를 유지하면서 저장 코드를 `HIHO861W2`로 지정할 수 있다. 확인하면 휴지통을 제외한 현재 이미지 목록을 공개 R2 버킷에 순서대로 저장하고, 결과에 파일별 공개 주소를 표시한다. 업로드 중에는 조회·편집·정렬·생성·다운로드를 잠근다.

추가한 이미지는 독립 스냅샷이다. 이후 치수·표기 사이즈·상품정보 값을 바꿔도 이미 추가한 PNG는 바뀌지 않는다. 바꾼 값으로 새 이미지를 추가하고 이전 것은 제외한다. 사진 기반 사이즈 이미지를 다시 편집하면 그 이미지의 생성 당시 치수·표기 사이즈·배치를 사용한다. 상품정보 편집은 이 페이지의 이미지 준비에만 적용하며 조회 원본을 수정하지 않는다.

상품컷에는 원본 도구의 하단 흰 여백 10px 처리를 유지한다. 사이즈·상품정보 이미지는 780px 폭으로 생성한다. 상품정보는 최종 출력 기준으로 글씨를 이전보다 2px 줄이고 카드 안팎·줄 사이의 여백을 줄였다. 긴 값은 필요한 높이로 늘어나며 잘리지 않는다. 이는 수동 작업용 산출물이며 판매 마켓 등록 요청이나 공통 상품·매입처·보유 재고 저장을 수행하지 않는다.

웹서버의 Downloads 폴더에 저장하거나 서버의 Finder를 실행하지 않는다. 사용자의 PC·휴대전화가 ZIP을 내려받는다. 새 조회·페이지 새로고침은 편집 중 순서와 휴지통 상태를 초기화한다. 생성 이미지·다운로드 결과는 임시 보관이며 서버 재시작이나 보관 기간 만료 후에는 다시 만들어야 한다.

공개 상품 이미지의 R2 저장 위치는 `molebutter` 버킷의 `products/{저장할 상품코드}/{파일명}`다. UUID 중간 폴더는 생성하지 않는다. 저장 코드는 영문·숫자·밑줄·하이픈 4~40자이며 대문자로 정규화한다. 해당 상품 경로 아래에 파일이 하나라도 있으면 중복 업로드를 거절한다. 기존 UUID 하위 폴더와 부분 성공 파일도 포함하며 기존 파일은 이동·삭제·덮어쓰기하지 않는다. 중복 안내 후에도 이미지 선택과 입력은 유지하고 다른 저장 상품코드를 입력할 수 있다. 조회나 PNG 추가만으로 업로드하지 않고, 업로드 확인 버튼을 눌렀을 때만 저장한다. ZIP과 같은 가공 바이트를 사용하며 확장자는 실제 이미지 형식을 따른다. [저장 경로와 공개 URL 규칙](r2-storage.md#상품-이미지-경로)을 참고한다.

일부 파일만 성공하면 저장된 파일 목록과 오류를 표시하고 이후 전송을 멈춘다. 같은 상품의 재업로드도 차단한다. 응답 유실은 ‘결과 확인 필요’로 표시하며 새 업로드를 막고 같은 요청 ID를 조회한다. 서버는 R2의 크기·형식·SHA-256·작업 ID가 일치하는 경우에만 저장을 확정한다. 객체가 아직 조회되지 않아도 실패로 단정하거나 이미지 쓰기를 자동 반복하지 않는다. 새로고침 후 같은 탭의 보류 요청은 `sessionStorage`에서 복원해 조회하며, 서버 기록이 없을 때의 명시적 재시도도 같은 ID와 입력을 사용한다. 접수 전 경로 조회 실패는 쓰기 전 거절로 구분해 확인창과 입력을 유지한다.

## 구현 경계

- `molebutter-imaging`: LF몰 조회, 응답 해석, 치수·템플릿, 이미지 렌더, 임시 캐시·생성 이미지·다운로드 작업과 소유권이 확인된 파일 내보내기를 소유한다. 공개 계약은 `imaging.api`, 구현은 `imaging.internal`에 둔다.
- `molebutter-app`: Thymeleaf 화면, 정적 자원, 현재 사용자 확인, HTTP 응답·오류 변환, ZIP 첨부 응답과 R2 업로드 작업을 담당한다. `imaging.api.ImageExportPlan`과 `storage.api.ObjectStorage`를 조합하며 이미지 모듈은 저장 모듈에 의존하지 않는다.
- `MenuSection.PRODUCT_IMAGES`: 화면 `/product-images`와 API `/api/product-images/**`의 권한을 연결한다.

다른 사용자의 생성 이미지·작업·ZIP에 접근할 수 없게 사용자 ID를 서버에서 전달한다. 클라이언트가 제공한 사용자 ID를 소유권 판단에 사용하지 않는다. 명시적으로 조회할 때 사용자·상품·브랜드별 목록 스냅샷을 보관하고 편집·다운로드에서 사용한다. 다운로드 작업은 접수 시 그 목록을 고정한다. 새 화면은 원본 순번과 함께 조회 당시 URL도 보내므로 같은 사용자의 다른 탭에서 목록이 바뀌어 순번과 URL이 달라지면 재조회를 안내하고 전송을 거절한다. 이미지 URL과 리디렉션은 HTTPS LF몰 호스트 경계로 검사하고, 외부 응답과 이미지 디코딩 크기·작업 수·보관량을 제한한다. 로컬 파일 경로는 API 입력이나 결과에 포함하지 않는다.

LF몰 조회는 원본 도구의 비공식 조회 경로를 사용한다. 판매 마켓 API와 분리되어 있으며 외부 응답 변경 시 파서 조정이 필요할 수 있다. 통합 검증은 모의 응답을 사용한다.

## HTTP 계약

| 메서드·경로 (`/api/product-images` 하위) | 기능 |
|---|---|
| `GET /products/{code}?brand=` | 상품 이미지·가격·고시·치수 조회 |
| `GET /size-guide/templates` | 지원 사이즈 템플릿 |
| `POST /products/{code}/size-guide/preview` | 사진·치수 배치 미리보기 |
| `POST /products/{code}/size-guide/images` | PNG 스냅샷 생성 |
| `POST /products/{code}/notice-image/preview` | 편집한 상품정보의 카드 배치 계산 |
| `POST /products/{code}/notice-image/images` | 편집한 상품정보 PNG 스냅샷 생성 |
| `POST /products/download` | 순서대로 ZIP 생성 작업 접수 (`202`) |
| `GET /products/download/jobs/{id}` | 본인 작업의 상태·파일 목록 |
| `GET /products/download/jobs/{id}/archive` | 완료한 본인 ZIP 다운로드 |
| `POST /products/upload` | 공개 R2 업로드 작업 접수 (`202`) |
| `GET /products/upload/jobs/{id}` | 본인 업로드 상태·공개 주소·결과 확인 |

새 화면은 `images: [{imageIndex: 2, sourceImageUrl: "https://..."}, {generatedImageId: "..."}, {imageIndex: 0, sourceImageUrl: "https://..."}]`처럼 원본 인덱스와 사이즈·상품정보 생성 ID를 섞어 보낸다. 서버는 ZIP 항목의 순서를 유지하며 원본 사진은 목록 위치의 번호를, 생성 이미지는 종류별 `사이즈.png`·`상품정보.png`와 중복 번호를 파일명으로 사용한다. 같은 이름을 R2 상품코드 바로 아래에도 적용하고 상품 단위의 중복 검사·비공개 예약과 개별 조건부 생성으로 기존 파일을 보호한다. 생성 종류는 서버에서 보관하므로 브라우저가 파일 종류를 지정하지 않는다. 개별 항목은 원본 인덱스 또는 생성 ID 하나만 허용한다. `sourceImageUrl`은 원본 목록 일치 검사에 사용하며 클라이언트 주소를 그대로 다운로드하지 않는다. 새 화면은 `includeNoticeImage=false`로 자동 별도 파일 생성을 끄고, 목록에 추가한 상품정보 이미지만 보낸다. 이전 호출자의 `includeNoticeImage` 옵션은 호환성을 유지한다.

상품정보 준비 입력은 `{brandCode, fields: {항목명: 편집값}}`이다. 서버는 사용자가 조회한 상품의 항목에만 덮어쓰기를 허용하며 알 수 없는 항목은 거절한다. 배치 응답 `cards`의 `fullWidth`로 화면의 두 칸·전체 폭을 결정한다. 빈 값은 이미지에서 제외하지만 화면의 입력란은 유지한다. 사이즈 준비 입력의 선택적 `sizeLabel`은 해당 이미지의 표기 사이즈만 바꾸며, 생략하면 조회 원본 값을 사용한다.

업로드 입력은 `{requestId, productCode, brandCode, uploadProductCode, images}`다. `productCode`는 관찰 목록과 소유권 확인에, `uploadProductCode`는 공개 폴더에 사용한다. 접수 시 원본 목록과 본인 생성 PNG를 고정하며 전체 파일 준비·크기·형식 검사를 끝낸 뒤 첫 R2 쓰기를 실행한다. 보관 중인 동일 ID·동일 입력은 기존 작업을 반환하고, 입력이 다르면 충돌로 거절한다. 다른 작성자의 작업은 조회할 수 없다. 오류 결과에는 외부 원문·자격 증명을 포함하지 않는다.

## 임시 보관과 설정

조회 캐시는 기본 10분이다. 사용자별 조회 목록과 생성 PNG는 4시간, 완료한 ZIP 작업은 기본 1시간 보관하고 매분 만료 항목을 정리한다. 사용자별 조회 목록은 전체 64개·사용자당 4개·추정 메모리 합계 16MiB까지 보관한다. 목록이 만료되거나 보관 한도를 넘으면 재조회를 안내한다. 생성 이미지는 전체 32개·16MiB, 사용자당 16개·8MiB까지 보관한다. 다운로드 작업은 전체 32개, 사용자당 동시 진행 2개까지 허용한다. 완료한 ZIP의 전체 보관량은 64MiB이다.

한 번에 최대 64개 사진을 요청할 수 있고, 이미지 파일당 10MB, 원본 픽셀 2천만 개, 다운로드 원본 합계 64MiB, ZIP 32MiB로 제한한다. 제한을 넘으면 이미지를 나누어 내려받도록 안내한다.

업로드 작업은 메모리에 완료 후 4시간 보관하며 전체 32개·동시 실행 2개·작성자별 동시 실행 1개로 제한한다. 가공한 파일은 `cloudflare.r2.max-object-bytes` 이내, 전체 64MiB 이내여야 한다. 서버 재시작·만료로 결과 기록이 사라져도 저장된 R2 파일과 비공개 예약은 남는다. 공개 상품 prefix 또는 진행·미확인 예약이 있으면 새 요청으로 중복 업로드할 수 없다. 재시작으로 결과 조회가 불가능해진 미확인 예약은 자동 해제하지 않는다. 이 보호는 영구 실행 이력이나 미전송 파일의 자동 재개 기능과 구분한다.

| 설정 | 기본값 |
|---|---|
| `imaging.lfmall.api.base-url` | `https://nxapi.lfmall.co.kr` |
| `imaging.lfmall.api.affiliate-code` | `2000` |
| `imaging.http.connect-timeout` / `read-timeout` | `3s` / `30s` |
| `imaging.lookup.cache.ttl` | `10m` (최대 1시간) |
| `imaging.job.retention` | `1h` (최대 4시간) |
| `imaging.cleanup-delay-ms` | `60000` |
| `imaging.render.font.family` / `photo-family` / `notice-family` | `Malgun Gothic` (설치된 한글 폰트로 대체) |
| `imaging.render.font.number-family` | `Segoe UI` (설치된 폰트로 대체) |

설정은 기존 앱 설정 방식으로 전달하며 다른 기능의 HTTP·폰트·다운로드 설정과 분리한다. [테스트 안내](testing.md)에 통합 검증 결과를 기록한다. 원본 `is` 프로젝트는 수정하지 않는다.
