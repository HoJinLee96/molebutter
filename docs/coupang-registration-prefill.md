# 상품 정보 도구에서 쿠팡 등록 준비

기존 쿠팡 등록 권한이 있는 관리자에게 **상품 등록** 버튼을 표시한다. 상품 정보 도구에서 조회한 뒤 저장용 상품코드를 확인하고 버튼을 누른다. 현재 상품의 서버 조회값, 계정별 기본설정, 기존 추천 계산, 공개 R2 파일로 신규 등록 입력을 준비해 새 탭에 표시한다. 이 버튼은 작업본 저장·이미지 업로드·쿠팡 등록을 실행하지 않는다. 실패·팝업 차단 시 원래 화면의 이미지 순서와 입력은 유지되고, 팝업 차단 시 준비한 화면을 여는 링크가 남는다.

자동 입력 확인 영역에서 입력 출처, 이전 정상 확인 시각, 누락과 확인 필요 항목을 펼쳐 볼 수 있다. 명확하지 않은 항목은 직접 입력한다. 필수 인증·서류·카테고리·이미지 오류는 기존 입력 검증과 전송 준비 검증을 통과해야 한다.

## 입력과 격리

- `POST /api/coupang/working-copies/prefill`: 원래 조회 상품코드·브랜드·저장용 코드·소유한 이미지 선택만 받는다. 상품명·가격·이미지 메타데이터는 브라우저 값으로 채우지 않는다. imaging의 사용자별 4시간 서버 관측이 만료되면 다시 조회해야 한다.
- `GET /api/coupang/working-copies/prefill/{token}`: 동일 사용자·쿠팡 계정의 동일한 준비 결과만 10분 동안 복원한다. 서버 재시작 후에는 다시 준비한다. 토큰은 메모리에만 보관하며 임시 작업본 행을 만들지 않는다.
- 편집 세션도 저장 전 CREATE로 생성하며 서버의 기준 문서에 준비값을 포함한다. 일반 신규 작성 캐시 및 다른 준비 토큰과 섞지 않는다. 새로고침으로 사용자가 수정한 값을 덮어쓰지 않는다.
- 토큰 만료·서버 재시작 후 브라우저 보관 입력이 있다면 본인 정보와 현재 계정의 빈 CREATE 세션을 새로 확인한다. 소유 사용자와 계정이 모두 일치할 때만 입력을 표시한다. **보관한 입력으로 계속**을 직접 눌러야 편집·저장을 계속할 수 있으며, 날짜나 추천값은 자동 갱신하지 않는다. 다른 사용자·계정의 입력은 복구하지 않는다.
- 실제 전송은 기존 작업본 저장 → 전송 미리보기 → 명시적 확인이다. 기존 중복 SKU·revision·권한·계정·UNKNOWN·ACCEPTED·호출 간격 및 제한된 재시도 보호를 사용한다.

브랜드는 정확히 같은 이름의 유일한 쿠팡 후보만 사용한다. 카테고리는 추천 SUCCESS 뒤 유효성 true 및 규격 조회까지 확인해야 자동 적용한다. 전체 후보를 확인하지 못한 브랜드나 애매한 고시유형은 추정하지 않는다. 고시는 명시적 항목명·고정 별칭만 대응하고 전체 상세페이지 참조로 자동 변경하지 않는다. 조회의 기본 FREE 사이즈를 확인된 옵션으로 간주하지 않는다.

상품명은 서버에 보관한 **원래 조회 상품명·고시·분류**에서 확인한 브랜드 → 성별 → 소재 → 특징 → 카테고리 순서로 만든다. 화면 표시용 이름에 들어간 코드 기반 성별 추정은 재사용하지 않는다. 명시된 `천연가죽(소)`는 `천연 소가죽`으로 정리하며, 확인되지 않은 항목은 생략하고 준비 안내에 표시한다. 등록상품명에만 저장용 판매자상품코드를 마지막에 붙인다. 추가 상품 정보의 제품명(`generalProductName`)은 자동 입력하지 않고 빈칸으로 둔다. 길이 초과를 임의로 잘라 우회하지 않는다.

제조사는 제조사·제조자·제조자(수입자)·제조사(공식수입/병행수입) 등 확인된 고시 항목명의 공백·괄호 표기를 정리해 조회한다. 상품의 제조사 입력과 고시 제조자 항목은 같은 유일한 확인값을 사용한다. 값이 없거나 서로 다르면 확인을 안내하고 임의 제조사를 넣지 않는다. 제조국을 제조사로 사용하지 않는다. 제목·제조사를 사용자가 수정한 뒤에는 재렌더링이나 토큰 복원으로 다시 자동 조합하지 않는다.

정상가·판매가는 앞뒤 공백과 쉼표만 제거한 숫자 문자열로 저장·미리보기·전송한다. 등록/수정 및 개별/일괄 가격 수정이 같은 규칙을 쓰며, 숫자가 같은 서식 변경은 새로운 수정 의도를 만들지 않는다. 원·통화기호·소수·음수·지수 표기는 기존 입력 검증으로 거절한다. 수정하지 않은 쿠팡 원문과 실행된 증거는 재작성하지 않는다.

### 검색어

신규 등록 준비에서 노출상품명의 띄어쓰기 단위 → 확인한 색상 → 브랜드 표기 변형 → 상품 종류 → 성별·수령 대상 → 소재 → 직장 관련 → 공통 용도·스타일 순서로 검색어를 만든다. 판매자상품코드 접미사는 검색어에 넣지 않는다. 공백·표기를 정리하고 대소문자를 무시해 중복을 제거하며 최대 20개·각 20자를 넘는 후보는 자르지 않고 제외 사유를 표시한다.

가방은 가방·핸드백·백 및 실제 종류, 지갑은 지갑·카드와 실제 종류를 사용한다. 명함은 카드지갑·명함지갑에서만 확장한다. 남성은 남자·남성·아버지 및 가방/지갑의 회사원·직장인·정장, 여성은 여자·여성·어머니를 추가한다. 성별이 상충하거나 미확인이면 확장하지 않는다. 확인된 소가죽만 소가죽·가죽으로 확장하고 합성가죽·나일론 등을 소가죽으로 만들지 않는다. 가방·지갑에는 선물·캐주얼·데일리·모던·클래식을 후보로 사용한다. 루이까또즈의 루이까또쯔·루이까도쯔·루이까도즈 표기 변형은 해당 브랜드에만 적용한다.

편집기의 **검색어 다시 만들기**는 같은 서버 생성기를 사용한다. 현재 제목·명시적인 색상 입력을 우선하고 직접 변경·제거한 색상에 과거 색상을 다시 붙이지 않는다. 직접 편집한 검색어나 옵션별 값은 교체 확인을 거친다. 취소·실패·생성 중 관련 입력 변경은 기존 값을 유지한다. 제목·색상 변경과 재렌더링만으로 검색어를 덮어쓰지 않는다. 기존 상품·작업본에는 최초 자동 입력을 소급 적용하지 않는다.

`POST /api/coupang/working-copies/search-tags`는 편집 권한·CSRF 검사를 거치는 비저장 제안 API다. 입력은 `{title, brand, context: {gender, material, category, colors}}`, 출력은 `{tags, excluded: [{value, reason}]}`이며 제외 코드는 `OVER_COUNT`·`OVER_LENGTH`다. 제목 500자·브랜드 100자·성별 근거 200자·소재/분류 근거 각각 500자·색상 최대 32개/각 100자로 제한한다. 브라우저 입력은 검색어 제안에만 사용하고 상품 조회 사실이나 권한 근거로 취급하지 않는다. 쿠팡·R2 조회나 DB 저장을 실행하지 않는다.

기존 준비 응답에는 선택적 `searchTagContext`가 추가된다. 이 근거와 색상 변경 여부·직접 검색어 편집 여부는 사용자/계정별 기존 브라우저 캐시에 함께 보관한다. 서버 작업본에는 기존 `registration.searchTags`만 저장한다. 근거가 없는 기존 작업본을 재생성할 때는 현재 입력에서 확인할 수 있는 값만 사용한다. 테이블·마이그레이션은 추가하지 않는다.

판매가·재고는 활성 내부 상품의 정규화된 정확한 단일 코드와 기존 선정 매입 근거를 사용한다. 공통 계산기의 배송비·수수료·마진·가격 단위 조정을 재사용한다. 매입 불가/미발견·이전 정상 근거·보유 재고는 기존 추천 포트의 판정을 사용하며, 조회 실패나 미확인을 0으로 만들지 않는다. 다중 옵션의 수량은 합산·반복 배정하지 않고 후보 및 직접 입력 안내를 제공한다.

## 검색필터 색상계열

검색필터는 검색어와 별도인 카테고리 `attributes[].exposed=NONE` 속성이다. 카테고리 조회 성공 시 아직 값이 없는 검색 속성도 입력칸을 표시한다. 표시용 빈 행은 저장 문서와 수정 의도에서 제외하고 직접 입력한 행만 포함한다. 조회 중·실패·규격 미조회·API에서 검색 속성을 제공하지 않는 경우를 구분한다. 조회 실패 시 기존 입력을 유지하고 재조회할 수 있다.

`패션 의류/잡화 색상계열`은 사용자가 제공한 14개 값으로 선택한다: 그린 톤, 다색, 레드 톤, 메탈릭 톤, 밝은 톤, 브라운 톤, 블랙 톤, 블루 톤, 어스 톤, 중성 톤, 파스텔 톤, 핑크 톤, 화이트/오프 화이트 톤, 회색 톤. 같은 이름이어도 `EXPOSED` 구매 속성에는 적용하지 않는다. 목록 밖 기존 값은 보존·안내하고 자동 교체하지 않는다.

신규 등록 준비는 카테고리가 해당 검색 속성을 지원할 때 현재 노출상품명, 상품 정보 도구의 원문 제목 순서로 명확한 색상을 확인해 자동 입력한다. 편집기의 **제목으로 색상계열 선택**은 현재 노출상품명, 등록상품명 순서로 판단한다. 예를 들어 브라운/갈색은 브라운 톤, 네이비/블루는 블루 톤, 아이보리/오프화이트는 화이트/오프 화이트 톤으로 연결한다. 명시적인 다색/멀티컬러/배색은 다색으로 연결한다. 서로 다른 색상계열이 충돌하거나 베이지·카키 등 모호한 색상은 직접 선택한다. 상품코드·사진으로 추정하지 않는다.

기존 상품·작업본을 열거나 제목을 바꾸기만 해서는 자동 선택하지 않는다. 직접 선택·비운 값은 유지하며 버튼으로 다른 값을 제안할 때 기존 값의 교체를 확인한다. 실제 쿠팡 반영은 기존 명시적 저장·미리보기·전송 절차다. 새 API·테이블·마이그레이션은 없다.

## 계정별 기본설정

공통 설정의 **쿠팡 등록 기본설정**에서 주소록을 명시적으로 조회·선택하고 배송비, 반품비, 출고 소요일, 지역/합배송, 구매 제한, 상품 상태, 세금·연령·수입 구분을 저장한다. 미설정 주소나 다른 상품의 값은 선택하지 않는다. 택배사는 쿠팡 코드 목록에서 선택한다.

인당 최대구매수량은 **미설정 / 설정함 / 설정안함**으로 선택한다. 미설정은 등록 준비에 구매 제한을 자동 입력하지 않는다. 설정함일 때만 양수 수량·기간 입력을 표시하며, 설정안함은 수량 `0`·기간 `1`을 저장한다. 선택을 바꿔도 미저장 수량·기간과 다른 설정 입력을 유지한다. 저장한 기본값은 다음 신규 등록 준비부터 적용하며 기존 작업본·준비 토큰은 변경하지 않는다.

무료배송은 기본배송비(`deliveryCharge`)와 무료배송 기준(`freeShipOverAmount`)을 `0`으로 사용한다. 공통 설정에서 무료를 선택하면 두 입력을 0원으로 표시하고 비활성화하며, 명시적인 저장 시 서버도 같은 값을 보관한다. 과거 설정에 두 값이 없거나 유료 금액이 남아 있어도 새 등록 준비에서는 무료배송의 0원 규칙을 적용한다. 초도·반품 배송비는 사용자가 저장한 값을 유지하며 자동으로 0원 처리하지 않는다. 기존 상품·작업본·미저장 입력은 바꾸지 않는다.

- `GET /api/settings/coupang-registration`
- `PUT /api/settings/coupang-registration`: 조회한 revision을 보내며 충돌 시 입력을 보존하고 재조회를 요구한다.

선택적 인증 기본 유형·번호는 해당 카테고리의 정확한 유형 및 CODE/NONE 규격에 맞을 때만 적용한다. 필수 인증이 있는 카테고리에 대상 아님/상세페이지 참조로 대체하지 않으며 필수 서류를 생략하지 않는다.

판매기간은 준비 버튼 실행 시점의 한국 시각부터 `2099-12-31T23:59:00`까지 한 번만 채운다. 조회·재진입·새로고침·브라우저 입력 복구에서는 새 날짜를 만들지 않는다.

### 상세설명 앞 이미지

공통 설정의 **상세설명 앞 이미지**에서 공개 R2 `common/` 경로의 URL을 최대 20개 추가하고 위로/아래로 이동해 순서를 정한다. 예: `https://assets.molebutter.link/common/first_guide.png`. 이 주소는 예시이며 자동 저장하지 않는다. URL 입력의 Enter는 설정을 저장하지 않으며 **등록 기본설정 저장**을 직접 누른다. 출고지·반품교환지를 등록마다 직접 선택하려면 관련 기본값은 비워 둔다.

저장한 공통 이미지는 **공통 이미지 → 기존 상품별 상세설명** 순서로 새 등록 준비에만 넣는다. 대표/추가 상품 사진으로는 넣지 않는다. 기존 작업본이나 이미 준비한 토큰의 입력에 추가 삽입하지 않는다. 빈 목록을 명시적으로 저장하면 다음 등록 준비부터 공통 이미지를 넣지 않는다.

설정 GET/PUT의 `descriptionPrefixImages`는 순서가 있는 URL 배열이다. 이전 JSON에 필드가 없으면 빈 목록으로 읽으며, 이전 클라이언트의 PUT에 필드가 없으면 기존 목록을 보존한다. 명시적인 `[]`는 해제다. 계정별 revision 검사를 유지하고 기존 V51 JSON에 저장하므로 추가 마이그레이션은 없다.

저장 시 서버가 설정된 공개 버킷의 실제 파일·형식·상세설명 규격과 중복을 확인한다. 임의 외부 도메인·비공개 경로·경로 이동을 허용하지 않는다. 실패하면 기존 설정과 입력을 보존한다. 저장 후 파일이 삭제되거나 조회가 실패해도 등록 준비에서 해당 행을 조용히 생략하지 않으며, 전송 전 상세설명 이미지 검사에서 차단한다. 공통 이미지의 업로드·변환·삭제는 수행하지 않는다.

## R2 배치와 이미지 규격

공개 버킷의 `products/{저장용 상품코드}/` 정확한 경로만 읽는다. 실제 파일과 형식·픽셀·용량을 확인한다. 최근 완료 업로드 연결은 사용자·원래 조회 상품·브랜드·저장용 코드가 같아야 하며, 현재 선택에 대응하는 R2 바이트가 업로드 준비 당시 SHA-256과 일치해야 현재 순서로 사용한다. 삭제·내용 변경·미업로드 선택은 별도로 안내한다.

연결이 없으면 기존 R2 파일을 `official/숫자.확장자` 숫자 순 → `processed/사이즈*.png` → `processed/상품정보*.png` 순서로 사용하고 **기존 R2 파일 순서**라고 표시한다. 중복 사진 번호는 추정하지 않고 제외 사유를 표시한다. 평면/UUID/다른 상품 경로는 현재 상품 사진으로 추정하지 않는다.

확인한 사진 첫 장을 대표, 다음 9장까지 추가에 배치한다. 사이즈·상품정보 이미지를 대표로 대신 쓰지 않는다. 사진 한도 초과분과 사이즈·상품정보를 포함한 전체 순서는 상세설명 IMAGE 블록에 보존한다. 파일이 없거나 일부 조회가 실패해도 확인된 부분으로 진입하되, 실패를 파일 없음으로 표시하지 않는다. 원본 재업로드·변환·삭제는 하지 않는다.

대표·추가는 JPG/PNG, 3MiB 이하, 가로·세로 **각각 500~5000px**을 차단 기준으로 사용한다. 직사각형은 원본을 유지하고 비차단 경고를 표시한다. 상세설명은 별도의 앱 안전 제한(10MiB·2,500만 픽셀)을 적용한다. 새 등록/이미지 변경 전송 미리보기의 `target.warnings`는 `issues`와 구분하며 실행 가능 여부를 막지 않는다. 가격·재고만 바꾸는 준비에 이미지 경고 검사를 추가하지 않는다.

[쿠팡 API 문서](https://developers.coupang.com/ko/api/products/product-creation)의 정사각형 안내와 [Wing 등록 안내](https://cloud.mkt.coupang.com/Product-registration-landing-page-20200731)의 자동 리사이징 안내는 구분한다. 앱의 경고 허용은 실제 계정/API의 수용을 보장하지 않는다. 거절하면 기존 민감정보 제거 상세 사유를 확인하고 사용자가 수정한다. 자동 변환·재전송하지 않는다. 상세설명 원본의 CDN 복제를 전제하지 않고 R2 파일을 보존한다.

## V51 적용

V1~V50은 변경하지 않는다. `V51__coupang_registration_defaults`는 계정별 revision·JSON 기본설정 테이블만 추가하며 기존 행을 수정하거나 계정 기본값을 임의 생성하지 않는다. 데이터가 있는 DB는 앱 자동 기동 전환을 거절한다.

운영 적용은 별도 작업으로 앱·워커를 중지한 뒤 실행한다.

```sh
bash scripts/upgrade-coupang-registration.sh --apply /새로운/전체백업경로
```

기존 오프라인 전환기의 전체 DB 백업 → 격리 복원 → 행·판매 증거·이미지 파일 지문 대조를 거친다. V50 적용이 선행되어야 한다. 실패 기록의 자동 repair나 실행 중 앱의 전환은 지원하지 않는다. 모의 실행 검증은 `scripts/test-coupang-registration-upgrade.sh`에서 수행한다. 구현 중 운영 적용은 하지 않았다.

## 브랜드별 상세설명 로고

공통 설정의 **브랜드별 상세설명 로고**에서 브랜드명, 쉼표로 구분한 별칭, 공개 R2 `common/` 이미지 URL을 저장한다. 기존 브랜드 목록은 이름 입력 후보이며 직접 입력도 가능하다. 닥스 예시는 `https://assets.molebutter.link/common/daks_logo.png`이며 자동 저장하지 않는다. 같은 브랜드는 하나만 저장하고 공통 앞 이미지와 로고에 같은 URL을 중복 지정하지 않는다. R2 실제 파일·형식·용량 검사를 통과한 정규 URL만 저장한다. 조회·저장 실패나 revision 충돌은 입력을 유지한다.

상품 정보 도구의 신규 등록 준비에서 노출상품명을 NFKC·대소문자·공백 정리 후 브랜드명/별칭의 독립된 단어·구절과 비교한다. 유일한 브랜드만 선택하며 미일치·복수 일치는 수동 확인으로 안내한다. **공통 안내 이미지 → 로고 → 상품 이미지** 순서로 배치하고 대표/추가 이미지에는 로고를 넣지 않는다. 로고 조회 실패 시 해당 설명 행을 조용히 누락하지 않고 전송 전 검증 대상으로 유지한다.

등록 화면의 **브랜드 로고**에서 저장 로고 선택, 직접 URL 적용, 로고 없음, 제목으로 로고 찾기, 목록 다시 조회를 제공한다. 현재 옵션만 변경하며 기존 로고 교체/제거는 확인한다. 제목 수정·재렌더링·설정 재조회만으로 적용하지 않는다. R2 검사 실패·취소·늦은 응답·옵션/작업본/계정 변경 시 다른 입력을 덮지 않는다. 이미 다른 일반 설명 행에 있는 같은 URL을 로고로 추정하거나 중복 삽입하지 않는다. 해당 일반 행은 직접 확인하도록 안내한다.

기존 계정 설정 GET/PUT에 선택 필드 `brandLogos: [{brandName, aliases, imageUrl}]`를 사용한다. 요청에서 생략하면 저장된 목록을 유지하고, 명시적 빈 배열은 해제한다. `POST /api/coupang/working-copies/brand-logo`의 `{title}` 요청은 `status`(MATCHED/NOT_FOUND/AMBIGUOUS), `logo`, `matches`, `accountKey`, `revision`만 반환한다. 권한을 확인한 현재 계정의 저장 설정으로만 판별하며 이 API는 작업본/설정을 저장하거나 쿠팡 HTTP를 호출하지 않는다.

작업본 Content의 선택 필드 `purpose: "BRAND_LOGO"`는 로컬 행 구분용이다. 옵션당 하나의 IMAGE/IMAGE 행만 허용하며 행 UUID와 함께 저장·불러오기·미저장 복원·옵션 상속에서 보존한다. 원문에서 조회한 일반 행은 같은 URL이어도 표시를 붙이지 않는다. 쿠팡 전문은 기존 contentsType/contentDetails만 생성하므로 purpose를 전송하지 않는다. 새 테이블이나 마이그레이션은 없고 기존 V51 설정 JSON과 작업본 JSON을 사용한다. 기존 상품/작업본은 자동 변경하지 않는다.
