# 문서와 코드 정합성 정리

2026-10-05 작업. 시작 기준은 `e1708aa`이며 이후 문서와 재고 검색 안내의 정합성 정리 범위·판단 기준·검증 결과를 기록한다. 운영 DB 적용과 외부 마켓 호출은 수행하지 않았다.

## 판단 기준

- 코드 기준: 현재 구현이 합의한 업무 의도에 맞으면 문서를 수정한다.
- 문서·합의 기준: 유효한 요구를 코드가 표현하지 못하면 코드를 수정한다. 과거 문구만으로 현재 정책을 되돌리지 않는다.
- 과거 기록: 당시 조사·실측·적용 결과를 유지하고 현재 안내와 연결한다. 개인 경로나 무시된 target 자료의 현재 존재를 보장하지 않는다.
- 미구현 제안: 향후 모듈·외부 연동 제안을 완료된 기능으로 기술하지 않는다.

## 확인한 불일치와 결정

| 대상 | 결정 | 반영 |
|---|---|---|
| 상품 조회의 네이버 지원 범위 | 코드 기준 | 매장 정보 전용·옵션 활성화는 과거 기록, 현재 WINDOW 전용은 채널 정책으로 명시 |
| 공식몰·새 매장 입력 | 코드 기준 | 백화점 지점 입력과 별도 공식몰 확인을 구분; 과거 판매자 종류·식별자 호환 유지 |
| 공통 설정의 결제 수단 누락 | 코드 기준 | ADMIN 전용 탭·CRUD·버전 검사·과거 주문 이름 보존 추가 |
| 새 NO_MATCH 생성 설명 | 코드 기준 | 정상 검색의 대상 없음은 SOLD_OUT, 과거 NO_MATCH는 읽기 호환으로 구분 |
| 검색 복구의 선정 기준 | 코드 기준 | 원래 선호·선정 스냅샷을 함께 확인하는 현재 복구 계약 명시 |
| 복구 설계의 옛 재조회 대상 | 과거 기록 | 당시 건수는 보존하고 현재 재시도 정책 연결 |
| 외부 마켓 infra/service 패키지 제안 | 미구현 제안 | 향후 업무 모듈의 api/internal과 app 조립 방향으로 변경; 모듈명·의존 관계 미확정 |
| settings 잠금 표현 | 코드 기준 | catalog 일관성 가드와 procurement 설정·실행 상태 소유권 구분 |
| app의 모든 JSON 작성 금지 | 코드 기준 | catalog 저장 JSON과 app 감사 스냅샷 조합을 구분 |
| 재고 화면 입력 순서·크기 | 코드 기준 | 등록과 상세 순서를 별도로 기술하고 고정 픽셀 명세 제거 |
| 재고의 공통 검색 레이블 | 문서·합의 기준 | 탭별 실제 검색 대상을 표시하도록 JS·템플릿 수정; 검색 알고리즘은 유지 |
| 화면 100개와 API 기본 크기 | 코드 기준 | 화면 기본값과 size 생략 시 API 기본값을 구분 |
| 멀티모듈 선택 테스트 명령 | 코드 기준 | failIfNoSpecifiedTests 옵션 추가, 개인 Mockito 에이전트 경로 제거 |
| Python 역할·live-check 산출물 | 코드 기준·과거 기록 | 기본 포트 탐색과 선택적 JAR 검증을 구분; 제거된 실조회 도구 산출물은 과거 자료 |
| 과거 테스트 건수·운영 적용 결과 | 과거 기록 | 당시 수치·대상 환경은 보존하며 현재 실행 결과와 분리 |
