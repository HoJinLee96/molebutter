# V49 등록상품 저장소 보존 전환

V1~V48과 역사적 SalesSchema를 변경하지 않는다. V49는 등록상품·옵션·원문 버전·변경 이력·조회 기록·수집 작업/대상·수정 기준값·이미지 참조 보호 테이블 9개를 추가한다. 기존 데이터와 ID·작업본·실행 전문·감사 자료는 수정하지 않는다. 작업본을 최신 쿠팡값으로 전환하지 않는다.

앱·워커 중지 → 전체 DB·전용 파일 백업 → 격리 복원과 지문 대조 → 사전 검사 → V49 → 기존 모든 테이블과 이미지 대조 → 새 앱 재기동 순서다. 실행 중 작업과 활성 계정 임대가 있으면 중단한다. 데이터가 있는 설치의 일반 기동 마이그레이션은 거절한다.

```sh
COUPANG_ASSETS_DIRECTORY=/absolute/path/to/coupang-assets \
  bash scripts/upgrade-coupang-products.sh --apply /absolute/path/to/new-backup-directory
```

기존 런타임 설정을 사용하며 비밀 파일을 직접 열거나 수정하지 않는다. V48 적용을 요구한다. 앞선 전환의 중단 표식이 있으면 거절한다. 검증된 전체 dump·격리 복원, 이미지 파일, 전후 지문·불변 실행 증거, `UPGRADE_COMPLETE`를 백업 디렉터리에 남긴다. 이미 적용된 V49는 데이터를 변경하지 않는다.

일반 기동에서 V49의 오프라인 전환이 필요하면 Flyway 실행 전에 거절하여 실패 기록을 남기지 않는다. 이전 기동 시도가 `Detected failed migration to version 49`를 남겼다면 같은 전환 명령으로 복구한다. 실패 이력이 정확히 V49 하나이고 새 테이블 9개가 모두 없으며 뒤따른 이력이 없는 경우만 허용한다. 전체 백업·격리 복원 후 복원 DB에서 그 실패 기록 하나를 제거하고 validation·V49 적용·기존 행 보존을 먼저 검증한다. 검증 성공 후에만 원본 DB의 해당 실패 기록 하나를 제거하고 적용한다. 성공 이력·checksum은 수정하지 않는다. 복구 근거는 `V49_FAILED_RECORD_RECOVERY.txt`에 남긴다. 다른 실패나 일부 생성된 V49 테이블이 있으면 변경 전에 거절한다.

DDL 이후 실패하면 새 앱을 시작하거나 무조건 repair하지 않는다. 보존한 전체 DB·파일과 이전 JAR을 함께 복원한다. 새 입력이 생겼으면 별도 보관한다. 전환 후 첫 수동 전체 가져오기로 등록상품 DB를 채운다. 실제 쿠팡 쓰기와 운영 DB 전환은 일반 테스트에서 실행하지 않는다.
