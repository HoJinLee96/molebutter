# 비선호 추천 조회 실패 처리

> 문서 유형: 현재 구현 안내. 2026-10-05 로컬 코드와 대조했다. 날짜가 붙은 적용·검증 문단은 당시 기록이며 현재 정책과 구분한다.

선정·선호 조회 후 수행하는 비선호 추천 상세 요청의 실패는 상품 전체 실패로 처리하지 않는다. 선정 여부와 선호 여부가 불명확한 초기 매장 확인 요청은 기존 정책을 따른다.

- 일반 오류는 다음 후보를 계속 조회한다.
- `SupplierAccessRestricted`만 추천 단계에서 처리한다. 네이버 브라우저 검색의 `SearchBlocked`는 기존 워커 중단·로그인 재개 정책을 따른다.
- 접속 제한을 받은 쇼핑몰은 같은 작업의 추가 추천 요청을 생략한다. V19 진단 테이블의 제한 기록으로 서버 재시작과 작업 재개 후에도 유지하며, 새 작업에서는 다시 시도한다.
- 이후 같은 쇼핑몰이 선정·선호 조회에 필요하면 요청 전에 중단한다. 개별 재고 조회도 같은 작업의 제한을 우회하지 못한다.
- 작업 결과 API는 `recommendationDiagnostics`, `recommendationFailed`, `recommendationSkipped`를 제공한다. 완료 결과 JSON에도 진단 목록을 저장하며 과거 누락·null은 빈 목록이다.
- 추천 실패·제한 생략은 상품 상태와 기존 재고 실패 수에 합산하지 않는다. 작업 결과의 원인·검색 가격·판매글 링크로 수동 판단한다. 추천 실패만 있는 성공 상품은 기존 실패 재조회 대상이 아니므로 필요하면 상품을 선택하여 새 최신화를 실행한다.
- 진단 기록은 요청마다 짧은 트랜잭션으로 저장하며 기존 작업 점유권·상품 조회 버전을 재검사한다. 네트워크 중 DB 트랜잭션을 유지하지 않는다.

배포 시 서버 재시작으로 V19를 적용한다. 중단된 작업은 자동 재개하지 않고, 사용자가 재개하면 새 오류 분리 정책을 적용한다. 과거 결과와 실패 원인은 소급 변경하지 않는다.

검증: RecommendationFailureTest, ProductFlowIT의 recommendation* 및 stockQueue*, MigrationUpgradeIT 및 JavaScript 비동기 회귀 테스트. 브라우저는 대표 상품 흐름만 유지한다([테스트 안내](testing.md)).
