# 쇼핑윈도 동일 매장 자동 재고 조회 생략 실험

2026-09-28 검증. 운영 최신화 로직·선정·이력은 변경하지 않았다.

## 결론

사용자가 제시한 현대백화점 목동점 두 판매글은 검색 결과만으로 같은 채널·매장 후보로 묶을 수 있다. 첫 글의 상세 응답으로 채널·지점·구매 가능·재고를 확인한 뒤, 같은 후보 묶음의 나머지 자동 상세 요청을 생략하는 방식이 가능하다. 모든 쇼핑몰·모든 검색 응답에 일반화한 검증은 아니다.

## 실제 조회와 모의 검증의 구분

- 검색 전용 Chrome에서 `HIBA113K2`를 조사했다. 탐색 과정에서 검색을 3회 수행했으며, 최종 캡처는 낮은 가격순·80개 보기의 1~2페이지 응답이다. 로그인·차단은 발생하지 않았다. 같은 목동점 채널의 세 번째 글도 발견했지만 실험은 첨부 이미지의 두 글만 사용했다.
- 기존 상세 API `https://shopping.naver.com/v2/channel-products/{id}`를 두 상품에 각각 한 번 호출했다. 첫 호출은 대표 글 확인, 두 번째 호출은 생략한 글의 개별 수동 조회에 해당하는 요청 가능성 확인이다. 실제 수동 조회 UI는 구현하지 않았다.
- 저장한 최소 공개 필드로 오프라인 시제품을 실행했다. 자동 요청 횟수는 기존 방식 2회 대비 1회이며, 두 번째 글은 `NOT_CHECKED`, 수량 `null`이다. 개별 조회를 요청하면 추가 1회가 필요하다.
- 재고 0·누락, 판매 불가, 상품 ID·채널 ID 충돌, 단순 본상품 재고로 처리할 수 없는 옵션, 다른 채널, 일반 스마트스토어 URL, 채널 근거 누락, 요청 예외에서는 다음 글 조회를 생략하지 않는 조건을 검증했다. 운영 워커·DB·동시성 검증은 아직 수행하지 않았다.

별도 시제품 실행기는 테스트 정리 시 제거했다. 현재 회귀 검증은 `SupplierGroupStockTest`와 `NaverSearchChannelTest`를 사용한다.

입력: `test-fixtures/product/supplier-group/`의 정제된 실제 응답. 회귀 검증은 네트워크를 사용하지 않는다.

## 적용할 때 필요한 변경

1. 현재 검색 파서가 버리는 `chnlSeq`, `comNm`, `wdTp`, `wdNm`, 채널 교차 확인 필드를 보존한다. 숫자 `chnlSeq`와 상세 `channel.id`를 연결하며, 기존 외부 식별자인 `channelUid`와 혼동하지 않는다.
2. 검색 단계에서는 같은 채널·같은 매장 후보로만 묶는다. 첫 상세 응답의 상품 ID, WINDOW 유형, 채널 ID, 실제 백화점·지점이 일치해야 조회 생략을 허용한다. 표시명이 같다는 이유만으로 채널을 합치지 않는다.
3. 낮은 가격부터 확인하되 현재 선정 글은 별도로 반드시 최신 확인한다. 확인된 구매 가능 재고를 가진 글을 확보하면 같은 확인된 묶음의 나머지를 미조회로 기록한다. 품절·실패·미확인이면 다음 글을 확인한다. 조합형 옵션의 구매 가능 판정은 기존 검증된 집계 규칙을 사용해야 한다.
4. 생략은 재고 공유가 아니다. 가격·상품 ID·사진·링크를 각각 유지하고, 수량은 복사하거나 합산하지 않는다. UI에는 ‘재고 미조회’와 개별 ‘재고 조회’를 제공하며 의도적 생략을 조회 실패 건수에 넣지 않는다.
5. 개별 조회 API에는 기존 권한·소유 업무 확인, 상품/판매글 연결 검증, 중복 요청 방지, 접속 제한 정책을 적용한다. 사용자 지정 URL을 그대로 요청하지 않는다. 미조회 판매글 선정 시 최신 확인을 필수로 할지는 구현 시 정해야 한다.

같은 지점이라도 채널 번호가 다르거나 검색 근거가 누락된 경우에는 이번 방식으로 자동 생략하면 안 된다. 현재 UI의 매장별 묶음보다 생략 단위를 보수적으로 잡아야 한다. 이번 예시는 서로 다른 모델명과 재고를 가진 판매글이므로, 모든 판매글의 재고를 확보하는 대신 구매 가능한 대표 글 하나를 확보하는 운영 방식으로의 변경이다.
