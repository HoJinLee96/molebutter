# 네이버 검색 간격과 대기·재개

> 문서 유형: 현재 구현 안내. 2026-10-06 로컬 코드와 대조했다. 날짜가 붙은 적용·검증 문단은 당시 기록이며 현재 정책과 구분한다.

## 처리 기준

- 실제 검색 종료 후 `next_search_at`에 60초 뒤 시각을 저장한다. 재고 조회 시간은 이 간격에 포함된다. 재고 조회가 60초를 넘어도 해당 상품의 처리를 마친 뒤 다음 검색을 시작한다. 같은 실행의 검색 캐시는 재사용하며 재시도 횟수를 초기화하지 않는다.
- 다음 실제 검색은 기존 네이버 탭을 정리하고 새 탭에서 홈 검색으로 시작한다. 최대 3페이지, 클릭 간 3초, 화면 안정화 2초를 유지한다. 정상 3페이지 종료는 별도 안내나 실패가 아니다.
- 실제 로그인과 현재 가격 검색 API의 로그인 리다이렉트, 요청 없음·응답 지연·통신 실패는 연속 5분 → 30분 → 60분 → 120분 대기 후 재개한다. 다섯 번째에는 수동 중단한다. 원인이 번갈아도 연속 횟수를 공유한다.
- 정상 브라우저 검색 완료(결과 없음 포함)만 연속 횟수를 초기화한다. `loginRetryCount`는 실제 로그인 감지 횟수로 유지하고 `searchRetryCount`에 공통 횟수를 제공한다.
- 응답 검증 불일치·형식 오류·필수 화면 요소 누락은 5분 뒤 한 번 재확인하고 같은 문제가 반복되면 수동 중단한다.
- HTTP 403·418·429, 보안 확인, 인증 세션, 탭 정리 실패, 브라우저 실행 불가는 수동 확인한다. 쿠키 삭제·로그인·대체 조회를 추가하지 않는다.

## 저장과 동시 처리

- V21의 `product_search_attempt`에 실제 검색 시작과 종료, 단계·원인·HTTP 상태·안전한 진단·재개 예정 시각을 저장한다. 응답 전문·쿠키·검색어·내부 예외 문구는 진단에 저장하지 않는다.
- 작업의 `RETRY_WAIT`와 공통 `search_cooldown_until`/`search_manual_resume_required`를 함께 사용한다. 작업 취소는 자동 예약을 취소하지만 공통 휴식은 유지한다. 새 작업이나 개별 재고 요청으로 우회할 수 없다.
- 자동 재개 중단은 PAUSED로 남기며 예정 시각 전 재개는 서버가 거부한다. 공통 수동 차단 해제는 화면에 표시된 버전으로 명시적으로 요청한다.
- 기존 DB 잠금·워커 소유권·조회 버전을 검사한다. 취소·소유권 상실·검색 기준 변경 후 도착한 결과를 현재 상품에 반영하지 않는다.
- 프로세스 종료로 남은 RUNNING 검색 시도는 점유 만료 후 INTERRUPTED로 기록하고 5분 휴식을 적용한다. 재시작을 로그인 감지로 세지 않는다.
- 대기는 기존 워커의 5초 폴링으로 처리한다. 대기 진입은 가격·재고 관측이 아니므로 선정·확인 시각·변동 검토 기준을 갱신하지 않는다.
- 추천 쇼핑몰 제한과 네이버 검색 제한은 구분한다. 추천 제한의 작업별 생략과 별도 진단 정책은 유지한다.

## API와 화면

- 작업 목록·상품 상태의 `searchGate`: `version`, `untilAt`, `manualResumeRequired`, `runId`, `attemptId`.
- `GET /api/product-refresh/{id}/search-attempts`: page, code, product 필터. 관리자·상품 담당자만 접근한다.
- `POST /api/product-refresh/search-gate/resume`: `{version}`. 기존 권한·CSRF·감사 기록과 버전 충돌 검사를 적용한다.
- 작업 화면에 공통 휴식과 원인별 검색 시도 이력을 표시한다. 상품 상세는 대기 중 스피너를 멈추고 예정 시각과 작업 링크를 제공한다.
- 재조회 대상은 실패·일부 확인 필요·비교 결과 없음·기타로 나눈다. 추천 실패·생략 건수는 별도 표시한다. 비교 결과 없음은 오류 없는 정상 검색일 수도 있다.

## 적용

새 코드와 Flyway V21을 함께 적용한다. 적용 전에 활성 작업을 확인하고 실행 중 요청이 없는 안전한 경계에서 서버를 재시작한다. 기존 BLOCKED/PAUSED 작업은 자동으로 깨우지 않는다. V21은 기존 활성 로그인 대기의 횟수·시각을 이관한다.

이번 작업에서는 운영 서버 재시작·운영 DB 마이그레이션·실제 네이버 반복 조회를 수행하지 않았다. 과거 실패 원인과 가격·재고·선정·조회 이력도 소급 수정하지 않았다.

## 검증 기록 (2026-09-29)

- 임시 MySQL·Redis에서 상품/검색 관련 282개 테스트: 278개 통과, 외부 실조회 4개 생략. V20→V21, 재시작·중복 실패·취소·중단·소유권·버전 충돌과 기존 상품 기능을 포함한다.
- 실제 Chrome에 모의 응답만 주입하여 API 로그인 리다이렉트(CDP 차단 포함), 무요청·무응답·통신 오류·검증 불일치·명시적 HTTP 제한을 검사했다.
- 재시도·대기·취소·재개는 Java와 JavaScript 회귀 테스트로 검증한다. 브라우저에서는 대표 상품 최신화와 미저장 입력 보존 흐름을 확인한다. 실행 방법은 [테스트 안내](testing.md)를 따른다.
