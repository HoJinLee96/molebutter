# 목록 선택 상태와 실행 대상 보호

검증일: 2026-10-19. 코드·모의 API·로컬 화면 회귀다. 운영 DB·실행 중인 IDE 앱·실제 쿠팡 판매값·R2 객체는 변경하지 않았으며 운영 DB 이력을 조회하지 않았다. 새 엔드포인트·테이블·마이그레이션은 없다.

## 원인과 영향

사용자 화면에는 조회 4개·선택 6개가 표시되고 실제 체크는 1개였다. 쿠팡 목록의 `selected` Set은 등록상품 ID를 저장한다. 일괄 처리의 `onApplied`가 목록을 다시 조회하면 추천이 해소된 행은 DOM에서 사라지지만 이전 ID를 Set에서 제거하지 않았다. 선택 상품 갱신은 그 Set 전체를 `sellerProductIds`로 보냈으므로 화면 밖의 이전 5개까지 포함할 수 있었다.

공통 전체 선택 컨트롤은 DOM 체크박스의 전체/일부 표시만 맞추며 업무 선택 저장소를 정리하지 않았다. 같은 문제가 내부 상품 목록의 Map에도 있어 페이지·변동 필터·목록 재조회 뒤 삭제·자동관리·브랜드 작업이 화면 밖 ID 또는 이전 revision을 사용할 수 있었다. 서버의 권한·revision 검사는 유지되지만 대상 ID 자체가 의도와 다르면 이것만으로 차단할 수 없다.

별도 검토에서 일괄 수정 재진입이 ‘이전 큐에 receipt가 하나라도 있으면 저장된 큐 전체 복원’을 수행하는 경로도 확인했다. 새 선택 밖의 이전 미전송 행이 함께 복원될 수 있으므로 복구와 새 작업을 분리했다.

## 수정

1. 공통 `TableSelection.reconcile`로 현재 목록과 선택을 대조한다. 사라진 ID를 제거하고 Map의 행 객체·revision도 현재 자료로 바꾼다. 검색·필터·페이지·페이지 크기 변경은 선택을 초기화한다.
2. 선택 작업 실행 직전 `TableSelection.snapshot`으로 현재 행·업무 선택·해당 표의 활성 체크박스를 교차 확인한다. 빈 선택을 전체 수집/전체 최신화로 전환하지 않는다. 처리 대상 배열은 클릭 시 고정한다.
3. 쿠팡 일괄 처리의 성공·변경 없음 항목을 선택 해제한다. 추천 행 제거와 마지막 페이지 보정에서도 내부 선택·표시 개수·체크가 일치한다. 실패·미확인 항목의 receipt는 보존한다.
4. 내부 상품 목록은 행과 건수를 성공 응답 시 함께 교체하고 조회 중 선택 작업을 막는다. 삭제와 브랜드 지정은 확인 모달을 열 때 ID·revision을 고정한다. 단일 삭제의 기존 확인·중복 실행 잠금도 유지한다.
5. 일괄 저장 입력은 현재 선택과 일치하는 상품·옵션만 복원한다. 선택 밖 receipt는 대상을 안내하고 별도 ‘이전 전송 결과 확인’으로 분리한다. 이 화면은 receipt만 다루고 새 prepare나 이전 미전송 행의 실행을 금지한다. 기존 준비 ID·중복 방지 키·실행 ID, 계정·revision·관측·선정 근거 및 UNKNOWN/ACCEPTED 보호는 유지한다.
6. R2 이미지 선택기는 동일 상품 재조회에서도 현재 응답에 없는 선택 키를 제거하고 존재하는 파일 정보는 갱신한다. 더 보기와 같은 상품의 폴더 간 명시적 다중 선택은 유지한다. 적용 전 URL 검증도 유지한다.

## 점검 범위

| 분야 | 결과 |
|---|---|
| 쿠팡 선택 상품 갱신 | 현재 체크한 등록상품 ID만 전송, 빈 선택 거절 |
| 일괄 가격·재고 | 현재 페이지의 선택 옵션만 열기, 완료/동일값 선택 해제 |
| 이전 일괄 전송 복구 | 선택 밖 큐 자동 대체 차단, 별도 receipt 전용 확인 |
| 내부 상품 삭제·자동관리·브랜드 추론 | 현재 체크와 현재 revision을 실행 대상으로 고정 |
| 브랜드 지정·삭제 모달 | 표시한 검토 대상을 고정하고 저장 때 다른 선택을 끼워 넣지 않음 |
| R2 이미지 선택 | 재조회로 사라진 파일 제외, 조회 실패는 기존 결과 유지 |
| 중복 상품 통합 | 현재 체크된 중복 행과 현재 중복 목록을 사용하는 경로 확인 |
| 주문·재고·근태 상세 | 표의 숨은 다중 선택 저장소를 실행하는 구조가 아니며 기존 단일 대상·revision/토큰 계약 유지 |
| 매입처 설정·이미지 순서 | 설정의 명시적 선택 태그/유효 목록·현재 이미지 ID를 사용하는 별도 구조, 전체 선택 대상으로 변환하지 않음 |

점검은 해당 선택·실행 경로에 한정한다. 모든 기능의 무결성이나 운영 이력을 전수 검증했다는 의미는 아니다.

## 실행 결과

| 검사 | 결과 |
|---|---|
| Java 전체 `verify` | 797개 통과, 실패·오류·생략 0 |
| JavaScript 전체 | 264개 통과, 실패·생략 0 |
| 일괄 수정 모의 화면 | 1920·1440·390px 통과 |
| 상품·설정·삭제·재고 기존 화면 | 1440·390px 통과 |
| 수집·목록 기존 화면 | 1920·1440·390px 통과 |
| R2 선택 모의 화면 | 1440·390px 통과 |
| diff 공백 검사 | 통과 |

핵심 화면 검사는 6개 중 5개를 가격 변경한 뒤 추천 판정으로 그 5개를 제거하고, 남은 ID `16` 한 개를 체크해 선택 갱신 요청에 `['16']`만 들어가는지 확인한다. 이전 큐에 다른 ID의 UNKNOWN receipt와 미전송 입력을 넣은 상태에서 새 선택을 열어 자동 실행 0건, 별도 결과 확인에서 reconcile 1건·새 prepare/execute 0건도 대조한다. 복구용 화면 전환은 모달을 닫았다 즉시 다시 여는 방식을 쓰지 않아 늦은 close 이벤트가 새 조회를 무효화하지 않는다.

JavaScript 검사는 조회 실패·페이지 이동·직접 체크 해제·삭제/자동관리/브랜드 추론 요청 ID·검토 시점 브랜드 대상·현재 revision 갱신·복구 전용 큐의 새 준비 금지를 포함한다. 기존 충돌·설정 변경·응답 유실·중복 전송·입력 보존 검사도 통과했다.

Maven 출력은 IDE와 분리한 `target/selection-safety-check`다. 기본 `verify`는 `*IT`를 실행하지 않으며 이 변경에서 운영 DB나 별도 DB 마이그레이션은 수행하지 않았다. 화면 테스트는 실제 Thymeleaf fixture와 로컬 모의 API이며 실제 외부 계정 전송이 아니다.

```sh
JAVA_HOME=/opt/homebrew/opt/openjdk@21 \
  CLOUDFLARE_R2_ENABLED=false MOLEBUTTER_COUPANG_LIVE=false MOLEBUTTER_ORDER_LIVE=false \
  ./mvnw -o -Dmolebutter.build-directory=target/selection-safety-check verify
node --test src/test/js/*.test.cjs
node scripts/test-coupang-bulk-edit-ui.cjs
node scripts/test-coupang-products.cjs
node scripts/test-product-ui.cjs
node scripts/test-r2-image-picker.cjs
git diff --check
```

현재 환경은 번들 Node·Playwright와 로컬 Chrome headless를 사용했다. 일괄 화면 캡처는 `/tmp/coupang-bulk-edit-{1920,1440,390}.png`다.
