# 사이즈 R2 업로드 가로 750px 검증

실행일: 2026-10-21 (한국 시각). 실제 R2·쿠팡·운영 DB·실행 중 IDE 앱은 변경하지 않았다.

사이즈 PNG는 서버가 보관한 SIZE 종류를 기준으로 업로드용 복사본만 750px로 변환한다. 파일명이나 브라우저 분류를 신뢰하지 않는다. 비율을 유지해 세로를 반올림하며 고해상도 편집·확정 원본과 ZIP 다운로드 바이트는 보존한다. NOTICE·일반 상품 사진·선택 순서·분류 경로·기존 객체 중복 제외는 유지한다. 이미 R2에 있는 파일을 덮어쓰거나 삭제하지 않는다.

`ProductImageWorkspace.prepareExport`가 캡처한 소유권 확인 스냅샷에서 업로드용 렌더링을 실행한다. 모든 변환이 끝난 후 기존 예약·중복 확인·해시 계산·조건부 생성을 수행한다. 읽기 실패는 업로드를 차단하며 원본 통과로 숨기지 않는다. 새 API·테이블·마이그레이션·R2 호출 종류 변경은 없다.

검증 명령:

```sh
JAVA_HOME=/opt/homebrew/opt/openjdk@21 ./mvnw -o -Djava.awt.headless=true \
  -Dmolebutter.build-directory=target/size-upload-check -pl molebutter-app -am test \
  -Dtest=DownloadServiceTest,ProductImageWorkspaceTest,SizeGuideServiceTest,ProductImageUploadServiceTest,ProductImageUploadReservationsTest,ProductImageUploadHttpTest \
  -Dsurefire.failIfNoSpecifiedTests=false
```

**BUILD SUCCESS, 88개 통과, 실패·오류·생략 0개.** 최초 sandbox 실행에서 앱 테스트 JVM의 macOS 그래픽 초기화가 종료돼 headless 옵션으로 실행했다. IDE 프로세스나 운영 설정은 변경하지 않았다.

- 2880×1880 → 750×490, 780×509 → 750×489, 이미 750px인 입력의 바이트 보존, 작은 이미지의 정확한 750px 출력.
- 복수 사이즈 이미지·과거 includeSizeImage 경로·서버 보관 종류·파일 순서·분류·동일 이미지 중복 번호.
- 상품정보·일반 상품 사진 폭 보존, 고해상도 원본·ZIP 바이트 보존, 읽을 수 없는 SIZE 파일 차단.
- 모의 ObjectStorage에 전달한 실제 PNG의 가로 750·세로 490 및 변환 바이트의 SHA-256 일치.
- 기존 계정·사용자 소유권·관측 캡처·조건부 생성·중복 제외·UNKNOWN·응답 유실 재확인·예약 해제와 모의 HTTP 경로 회귀.
