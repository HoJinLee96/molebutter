# 신규 등록 호출 축소와 결과 연결 검증

검증일: 2026-10-21 한국 시각. 운영 DB·실행 중인 IDE 앱·실제 쿠팡 상품값·R2 객체는 변경하지 않았다. 새로운 엔드포인트·테이블·마이그레이션을 추가하지 않았다.

## 구현

- 상품 정보 도구 준비의 브랜드 검색 → 카테고리 추천 → 유효성 검사 → 규격 조회를 유지한다. 서버가 조회한 규격을 계정별 클라이언트의 제한된 메모리 보관소에 10분간 보관한다. `CategoryRules.checkedAt`과 `Entry.categoryRules`로 화면에 전달하며, 브라우저의 규격을 전송 검증에 사용하지 않는다.
- 신규 화면 진입·새로고침·작업본 재진입은 남아 있는 규격을 재사용한다. 규격 누락·만료·재시작은 입력을 보존하고 기존 재조회 버튼으로 갱신하도록 안내한다. 준비·실행·최초 전송 직전·자동 재시도에서 서버 보관 근거를 확인하며, 미리보기의 근거 시각이 달라졌으면 새 미리보기를 요구한다. 시각은 기존 준비 JSON의 CREATE 단계 baseline과 미리보기의 선택 필드 `categoryRulesCheckedAt`에 보관하고 화면에도 표시한다.
- 옵션 수와 관계없이 신규 전문 구성의 규격을 한 번 확보한다. 기존 상품 수정은 종전의 최신 조회를 유지한다. 출고지 주소 또는 주소록에서 정상 확인한 지역 배송 정책도 신규 준비·전송에서 재사용하며 10분 만료 시 주소록 재조회를 요구한다.
- 신규 준비·실행·자동 재시도·결과 확인에서 판매자상품코드 조회를 제거했다. 과거 `knownSellerProductIds`, 전문, 해시 등 감사 자료는 변경하지 않는다. 같은 코드의 여러 등록상품을 고유 등록상품 ID와 옵션 ID로 구분한다.
- 등록 성공 ID는 기존 실행 완료 트랜잭션에서 저장한 뒤 해당 ID에만 승인을 요청한다. ID 없는 UNKNOWN은 Wing 직접 확인 안내를 반환하고 외부 조회·승인·재등록을 수행하지 않는다. 승인 실패 시 등록 성공을 보존한다.
- 승인 후 상세 조회는 기존 관측 저장소에 반영하고 옵션 ID를 연결한다. 기존 작업본 GET에 선택적인 `observed=true`를 추가해 완료 화면을 저장된 관측값으로 갱신한다. 기존 일반 GET의 최신 조회 동작은 유지한다. 상세만으로 확정하지 못한 현재 가격·재고는 미확인 상태로 둔다.
- 카테고리 규격 재사용 경로에서도 처리 상태가 끝나면 전송 버튼 상태를 갱신한다. 미리보기·명시적 확인·기존 revision/계정/UNKNOWN 보호와 1초 간격·제한적 재시도를 유지한다.

## 호출 예산

브랜드 1페이지·카테고리 추천 성공·재시도 없음·근거 유효 기준: 브랜드 1, 추천 1, 유효성 1, 규격 1, 등록 POST 1, 승인 PUT 1, 상세 GET 1 = 7회. 저장된 출고지 주소를 불러오면 1회 추가되어 8회다. 브랜드 추가 페이지·명시적 규격/주소 재조회·일시 오류 재시도는 별도다. 이미지 확인·설정·DB 읽기는 쿠팡 호출이 아니다.

## 검증

- `scripts/test-integration.sh`: 새 임시 MySQL·Redis에서 Java 전체 1,173개 실행, 1,168개 통과·기존 조건부 생략 5개, 실패/오류 0. 운영 설정이나 DB를 사용한 결과가 아니다. `CoupangWorkingCopyFlowIT`는 저장된 상세의 관측 재사용, 현재 재고 미확인, 계정/revision/저장 수정 보존을 포함해 32개 통과했다.
- 전체 격리 회귀 이후 최종 출고지 재사용·복수 옵션·미리보기 시각 보완을 새 격리 DB에서 재검증했다. `CoupangWorkingCopyWriteTest` 62개, `CoupangClientTest` 29개, `CoupangShippingPlacesTest` 5개, `CoupangWorkingCopyFlowIT` 33개, 합계 129개 통과·실패/오류/생략 0이다. 미리보기 시각의 DB 저장·복원과 작업본 규격 응답을 포함한다. 실제 HTTP 실행기를 모의 전송에 연결한 테스트가 규격 GET → 등록 POST → 승인 PUT → 상세 GET의 정확한 순서를 확인한다.
- `node --test src/test/js/*.test.cjs`: 284개 통과. 규격의 계정 보관은 Java에서, 카테고리·시각·10분 경계 및 형식은 JavaScript에서도 검사한다.
- `scripts/test-coupang-creation-queries-ui.cjs`: 1440px/390px에서 준비 규격 재사용, 만료 시 자동 조회 없음, 입력 보존, 명시적 재조회 1회, 미리보기에서 쓰기 없음, 명시적 전송, 관측값으로 완료 화면 갱신·추가 조회 없음 확인.
- 기존 PC/모바일 회귀: `test-coupang-prefill-ui.cjs`, `test-coupang-brand-logo-ui.cjs`, `test-coupang-attribute-identity.cjs`, `test-coupang-create-reentry-ui.cjs`, `test-coupang-submissions.cjs`, `test-coupang-save-settlement.cjs` 통과. 외부 URL은 차단하고 가짜 R2/쿠팡/앱 API만 사용한다.
- 변경 범위 `git diff --check` 통과. 실제 판매 API의 수용이나 운영 배포까지 검증한 것으로 해석하지 않는다.
