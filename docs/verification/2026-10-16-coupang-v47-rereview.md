# V47 전환·커밋·중단 재검토

실행일은 2026-10-16(KST)다. 기준은 `16f89813` 위에 적용한 [V47 중복 미디어 보존 수정](2026-10-16-coupang-v47-media-fix.md)의 로컬 작업 상태다. 이번에는 V47 보완과 관련 저장·복구·전송 회귀를 검토했으며 PR 전체를 새로 검토했다는 의미는 아니다.

## 재현한 문제와 수정

**[P2] 정리 커밋의 응답 유실 시 감사 대조가 실행되지 않았다.** 기존 순서는 준비 입력 제거 커밋 → 감사·파일 대조였다. 실제 DB 커밋 후 JDBC 예외를 발생시키면 표식은 사라지지만 후속 대조가 호출되지 않아 재실행 검사가 검증되지 않은 상태를 통과시켰다. 격리 MySQL에서 `proofRan=false`인 채 새 연결의 잔여 표식 검사가 통과하는 것을 재현했다. 실제 원본 데이터 손실을 재현했다는 의미는 아니다.

이제 준비 입력을 미커밋 상태로 제거한 같은 연결에서 보존 업무·감사 원문·실행된 미리보기 지문과 이미지 파일 해시를 대조하고, 모두 통과해야 정리를 커밋한다. 커밋 전에 대조·파일 기록이 실패하거나 프로세스가 중단되면 제거를 롤백해 표식을 보존한다. 실제 커밋은 성공했지만 응답만 유실돼도 대조는 이미 완료된 상태다. 명령은 커밋 예외를 성공으로 바꾸지 않고 `UPGRADE_COMPLETE`는 성공 응답 이후에만 작성한다.

준비·정리의 중복 트랜잭션 처리는 하나의 비공개 함수로 통합했다. 롤백도 실패하면 autocommit을 다시 켜서 미완료 쓰기를 암묵적으로 커밋하지 않는다. 불변 V1~V48·역사적 지원 시그니처와 현재 미디어 매칭·작업본 저장·쿠팡 전송 코드는 변경하지 않았다. 현재 경로에 새로운 판매 계층이나 호환 주소를 추가하지 않았다.

복원·재실행 기준은 [V47 절차](../coupang-working-copy-migration.md)와 [V48 절차](../coupang-intent-migration.md), 실행 방법은 [검증 안내](../testing.md)를 따른다. 잔여 표식이 있으면 전체 백업을 복원하며 수동 삭제로 우회하지 않는다.
