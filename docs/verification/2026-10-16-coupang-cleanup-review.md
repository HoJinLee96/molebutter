# 쿠팡 정리 계획 이중 검토와 적용 — 2026-10-16

사용자가 제공한 `coupang-only-cleanup-plan.md`를 현재 코드와 대조했다. 문서의 제안·결정 요청을 그대로 실행 명령으로 취급하지 않았다. 1차로 호출 관계·현재 계약·보존 경계를 확인하고, 필요한 수정 후 2차로 회귀·패키징·데이터 보존을 검사했다. 별도 Git 커밋·push·실계정 쿠팡 쓰기·R2 삭제는 수행하지 않는다.

| F4 | 등록상품 탐색 키를 작업본 탭에서도 사용. 두 탐색 상태가 함께 있을 때 등록상품 탭·검색 입력 복원, 복원 후 키 제거를 PC·모바일에서 검사 |
| F5 | 전송 확인 표의 공통 가로 스크롤과 이미지 편집 제목 정렬을 정의. 삭제 화면에 한정돼 있던 표 스크롤 의존 제거. 현재 쓰는 보조 클래스 정리 |
| B1 | 예기치 않은 전송 예외는 실행 ID·예외 클래스만 WARN. 외부 본문·예외 메시지·스택을 새 로그에 넣지 않음 |
| B2 | FK 삭제 실패 전에 파일이 사라지는 것을 재현. DB 삭제가 성공한 뒤 파일 삭제, 파일 IO 실패 시 DB 변경 롤백. 잠금 후 원본 편집·감사 핀 등 참조를 다시 확인. 파일·참조 보호 3개 검사 통과 |

## 운영 계약과 문서

- 쿠팡 예외를 전역 매핑으로 통합하고 기존 `COUPANG_`, `COUPANG_ORDER_`, `COUPANG_WORKING_COPY_`, `COUPANG_EDITING_`, `COUPANG_SUBMISSION_` 코드를 보존했다. 현재 쓰기 요청의 운영 감사와 요청 사용자 실패 알림을 추가했다. 비동기 반영 결과는 기존 전송 이력으로 판정한다.
- 이전 요청 형식 검사를 알려진 계약 위치로 한정하고 본문 바이트·크기 한도·오류 코드·읽기 알림 제외·쓰기 알림 대상 검사를 추가했다. 주문 구체 경로의 보안 순서를 명시했다.
- D1~D3: 고아 첫 조회 안내를 현재 구현/작업본 안내에 통합하고 주문 주소를 수정했다. 2026-10-07 계정 읽기 건수·테스트 사실은 별도 역사 기록으로 분리해 보존했다.
- D4·D11: 과거 검증 표시와 승인된 타 마켓 설명 제거 사실을 기록했다. 당시 건수·해시·쿠팡 실행 사실은 유지했고 오타·미기록 상태만 명확히 했다.
- D5~D10: 삭제된 sales_channel 표기, 감사 이미지 참조·과거 전환·현재 V48·개인 경로·로컬 비추적 링크·판매 업무·미구현 메뉴 설명을 수정했다.
- 현재 listing_state는 과거 세대를 보호하고 기존 행 상태만 갱신한다. 재연결 기능이 없는 신규 작업본은 세대 1을 사용한다. INSERT 누락으로 단정해 새로운 상태 계층을 만들지 않았다.
- V45 초기화는 역사적 명령으로 표시했다. V47+ 감사 FK를 우회하지 않는다. 스키마 허용 목록·기존 회원이 있는 설치의 전환 게이트·향후 작업/취소/임대 검사 기준을 문서화했다.
- [운영 기준](../operations.md)에 재기동·롤백·설정 키 이름·프로필·백업 범위·역할·로그를 모았다. [현재 HTTP 표](../coupang-api/endpoints.md)는 컨트롤러 매핑 34개를 기록한다. 원문의 28개와는 공개 이미지 등 포함 범위가 다르다.
- `.gitignore` 중복과 런타임 data 노출 위험을 정리하고 빈 구 소스/문서 디렉터리를 제거했다. 쿠팡 자료 1791개는 원본 해시 그대로 별도 비공개 쿠팡 전용 아카이브로 검증 보관했다. 새 클론 복원 절차도 명시했다.

## 보존·미적용 판단

Q1은 기존 비추적 보관을 유지하고 복원 절차를 추가했다. Q2는 과거 세대 보호를 보존했다. Q3은 초기화 동작을 바꾸지 않고 역사적 사용 범위를 명시했다. Q4는 현재 native 읽기를 좁히되 V47 지원 함수를 보존했다. Q5는 미사용 multipart만 제거하고 실제 preview URL을 유지했다. Q6은 승인된 타 마켓 설명 제거를 유지하면서 역사 표시를 추가했다. Q7의 비밀 파일 이름, Q9의 다른 업무 메뉴 정의, Q10의 인증된 관리자용 계정 구분 해시는 유지했다. Q8은 HTTP 운영 감사·실패 알림을 보강했다.

D12 파일명만 바꾸는 작업, 일반 head fragment 전체 개편·전체 JS 포맷, 추가 인덱스·마이그레이션 연속 체인 검사, GitHub CI 구성은 이번 버그 수정에 필요한 변경으로 판단하지 않았다. R3/R4/R6의 호스트 도구·IDE·tunnel launch agent와 로그 경로는 수정하지 않았다. 기존 비밀 설정·브라우저 프로필·원문·복구 백업은 보존하며 WIP 전체를 정리 커밋으로 묶지 않았다.

초기 검사에서 유지보수 도구의 internal 의존과 제거된 업로드를 참조하던 multipart CSRF 검사 2건이 실패했다. 유지보수 해시는 원래 독립 구현으로 보존하고 CSRF 검사를 현행 API로 교체한 뒤 전체 검사가 통과했다. 마지막 요청 가드의 native 문서 위치 보강은 별도 HTTP 계약 검사와 인증·패키지 기동 검사로 다시 확인한다. 구문 분석 결과와 생성자 제거는 Java 호출·직렬화·데이터 전환 검사로 검증했으며 실제 계정 성공을 주장하지 않는다.
