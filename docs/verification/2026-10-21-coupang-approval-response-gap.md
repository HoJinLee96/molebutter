# 등록·승인 성공 응답 후 대기

검증일: 2026-10-21 한국 시각. 운영 DB·실행 중인 IDE 앱·실제 쿠팡 상품값·R2 객체는 변경하지 않았다. 새 테이블·마이그레이션·API 호출을 추가하지 않았다.

공통 간격은 **최소 2초**이며, 신규 등록 성공→승인 요청과 승인 성공→최초 결과 조회는 후속 요청에 따라 [최소 5초](2026-10-21-coupang-create-five-second-gap.md)를 적용한다. 아래 1초·2초 검증은 이전 버전의 기록이다.

## 최초 1초 버전의 원인과 변경

- 기존 공통 제한은 요청 시작부터 다음 요청 시작까지 최소 1초였다. 등록 POST가 1초 이상 걸리면 응답 수신 직후 승인 PUT이 나갈 수 있었고, 승인 PUT이 오래 걸리면 결과 GET도 바로 나갈 수 있었다.
- 쓰기 계약의 등록 POST 또는 승인 PUT이 HTTP 200·본문 SUCCESS로 끝나면, 응답 본문 수신 시점의 monotonic 시각부터 최소 1초 동안 다음 요청을 대기시킨다. 중첩 `code=200,data.code=SUCCESS`도 같은 기준이다.
- 흐름은 등록 성공 응답 → 1초 이상 → 승인 요청 → 승인 성공 응답 → 1초 이상 → 자동 상품 상세 조회다. 기존 승인 실행기의 자동 조회를 지연시키며 추가 조회나 반복 등록을 만들지 않는다.
- 대기에는 기존 취소 가능한 공통 제한을 사용한다. 이미 설정된 더 긴 대기시간을 줄이지 않는다. 성공한 등록 ID와 기존 실행 기록·재시도 예산·UNKNOWN 보호를 유지한다. 조회 결과가 승인 대기이면 승인 완료로 표시하지 않는다.

## 검증

- 같은 모의 전문에 등록·승인 응답을 각각 1.2초 지연시킨 실제 클라이언트/업무 게이트웨이 회귀를 실행했다. 수정 전 등록 응답→승인 시작 간격은 44,440,958ns(약 44ms)여서 최소 1초 검사가 실패했다. 수정 후 두 응답→후속 요청 간격이 모두 1,000,000,000ns 이상으로 통과했다.
- 규격 GET → 등록 POST → 승인 PUT → 상세 GET의 호출 종류·횟수와 반환 상품 ID·옵션 ID 연결을 함께 검사한다. 상품코드/재고 조회나 두 번째 등록은 발생하지 않는다.
- 중첩 성공 응답과 1.1초 지연에서도 각 응답 뒤 1초를 검사한다. 승인 후 대기 중 취소하면 상세 GET을 전송하지 않는지 확인한다. 승인 성공 뒤 자동 조회가 아직 승인 대기이면 ACCEPTED와 상품 ID를 유지하는지 검사한다.
- `scripts/test-integration.sh -Dtest=CoupangWorkingCopyFlowIT,CoupangWorkingCopyWriteTest,CoupangRetryTest,CoupangClientTest -Dsurefire.failIfNoSpecifiedTests=false`: 새 임시 MySQL·Redis 및 모의 API에서 137개 통과·실패/오류/생략 0. 클라이언트 29, 쓰기 게이트웨이 63, 공통 재시도 12, 작업본/실행 격리 DB 33개다. 전체 모듈 컴파일도 통과했다.
- `scripts/test-coupang-submissions.cjs`: 1440px/390px에서 미리보기·명시적 전송·응답 유실·멱등키·UNKNOWN 결과 확인 회귀 통과. 실제 쿠팡이나 운영 앱에 접속하지 않았다.
- 변경 범위 `git diff --check` 통과. 실계정에서 1초 뒤 승인 완료가 보장됨을 검증한 것은 아니다. 로컬 변경만 완료했으며 실행 중인 IDE 앱은 재시작하거나 빌드 산출물을 교체하지 않았다.

## 후속 변경: 성공 응답 후 최소 2초

- 같은 날 사용자가 등록 성공 → 최소 2초 → 승인 요청 → 승인 성공 → 최소 2초 → 자동 결과 조회를 요청해 성공 응답 뒤 대기를 각각 2초로 변경했다. 일반 요청 시작 간격과 실패 응답의 재시도 정책은 유지한다.
- `CoupangWorkingCopyWriteTest` 63개와 `CoupangRetryTest` 12개, 합계 75개 통과·실패/오류/생략 0. 느린 응답 및 중첩 SUCCESS에서 두 간격을 각각 2,000,000,000ns 이상으로 검사한다. 취소·자동 조회·ID 보존도 포함한다.
- 전체 모듈 컴파일과 변경 범위 `git diff --check` 통과. 운영 DB·실행 중인 앱·실제 쿠팡 상품값·R2 객체는 변경하지 않았다.
