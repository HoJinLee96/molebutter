# 이미지 정리·예외·작업본 재검토 — 2026-10-16

이전 [정리 계획 검토](2026-10-16-coupang-cleanup-review.md) 이후 소스를 다시 검사하고 필요한 수정을 적용했다. 쿠팡 공식 SOURCE·원문은 참고만 했으며 실제 쿠팡 쓰기·공용 R2 삭제는 수행하지 않는다.

## 수정한 문제

1. **[P1] 이미지 정리의 커밋 실패.** FK 검사와 SQL DELETE 뒤에도 DB 커밋은 실패할 수 있었다. 기존 구현에서는 파일이 이미 삭제돼 롤백된 메타데이터가 없는 파일을 가리켰다. 커밋 실패 테스트에서 `NoSuchFileException`으로 재현했다. DB 삭제 커밋 이후 파일을 삭제하고, 삭제 표식으로 재시도한다. 롤백 후 재진입은 DB 행을 잠가 확인하며 파일을 보존한다. 새 테이블·마이그레이션은 추가하지 않는다.
2. **[P2] 잘못된 JSON의 서버 오류 분류.** 요청 가드의 선행 JSON 파싱 예외가 메시지 변환기의 400 처리에 연결되지 않았다. 계약 검사로 재현한 뒤 `HttpMessageNotReadableException`으로 연결했다. 실제 HTTP에서도 400·실패 감사 기록을 확인하며 잘못된 입력을 서버 장애 알림으로 만들지 않는다.
3. **[P2] 저장 요청의 세션 누락.** null 세션 ID가 `ConcurrentHashMap.get`에 들어가 서버 오류를 만들 수 있었다. 입력 검사를 추가했다. 세션 누락은 400으로 응답하고 작업본을 만들지 않는다. 존재하지 않는 세션은 기존 `COUPANG_WORKING_COPY_NOT_FOUND`·404·요청 사용자 실패 알림을 유지한다.

이미지 정리는 작업본·전송 전문·감사 이력·감사 핀·편집본 원본 참조를 잠금 아래 재확인한다. FK 거절·DB 커밋 실패는 파일을 보존한다. 파일 삭제 실패는 `.delete-pending` 표식으로 다음 실행에서 재시도한다. 프로세스 중단 후 DB 행이 존재하면 표식만 제거한다. 한 후보의 실패가 다음 후보 처리를 막지 않으며 WARN에는 자산 ID·예외 클래스만 남긴다. 전체 고아 파일 검색·삭제는 하지 않는다. 자세한 절차는 [운영 기준](../operations.md)을 따른다.

## 잔여 코드·문서 정리

- 현재 경로에서 호출하지 않는 WebP 픽셀 비교용 검사 오버로드·테스트·fixture와 media의 직접 디코더 의존성을 제거했다. 현재 이미지 입력의 JPG·PNG 정책은 동일하다. 상품업무 imaging의 독립 WebP 의존성은 보존했다.
- 사용하지 않는 이미지 규칙의 `retained` 인자와 전달 오버로드를 제거했다. 기존 CDN 캐시를 신규 이미지로 재사용하지 못하도록 하는 실제 `existingOnly` 보호는 유지한다.
- 단일 쿠팡 writer를 다시 감싸던 계정 공급 함수·Supplier와 도달하지 않는 null writer 분기를 제거했다. 워커는 같은 writer의 현재 계정을 직접 확인한다. 전송 결과 커밋 실패에는 실행 ID·예외 클래스만 기록한다.
- 실행 JAR 검증 프로세스에서 쿠팡 워커·자격 증명과 R2를 명시적으로 비활성화했다. 셸 환경의 설정에 의존해 외부 호출을 막지 않는다.
- 운영 문서에 정리 순서·삭제 표식의 백업 범위·실패 로그를 추가하고 테스트 안내의 중복 색인을 줄였다. 과거 검증 기록에는 현재 비교 계층이 제거됐다는 안내를 보강하며 과거 실행 결과는 바꾸지 않았다.

현재 쿠팡 화면·API·저장 계약에서 판매용 내부 상품·연결 후보·비교 계층은 확인되지 않았다. 상품업무의 매입처 비교, 옵션 UUID·외부 ID 매핑, 계정·revision·연결 세대 보호와 역사적 전송 판독기는 별도 필요 기능으로 보존한다. 과거 Flyway·감사 FK·복구 자료는 정리 대상이 아니다.

## 회귀 확인

- 색상만 수정한 작업본 재진입에서 외부 사이즈 변경을 보존한다. 명시적으로 수정한 가격은 `120000 → 사용자 130000 → 외부 150000 → 요청 130000`을 유지하며 가격 전용 PUT을 사용한다.
- 일반 상품 수정은 전송 직전 GET의 원문에 명시한 수정 항목만 적용한다. 미수정 배송·상품·옵션 값과 알 수 없는 필드·인증·서류 경로를 보존한다.
- 완료 직후 저장, 새 revision의 미전송 입력, 중복 미디어 ID, 세션 만료·재진입·신규 옵션 UUID 복구, UNKNOWN 재쓰기 차단·결과 확인을 기존 회귀 검사로 다시 확인한다.
- HTTP 쓰기 접수와 비동기 외부 반영의 최종 결과를 구분한다. 감사는 요청 사용자·operation ID·HTTP 결과를 기록하며 본문·서명·비밀 값을 기록하지 않는다. 실패 알림은 요청 사용자만 받는다. 비동기 최종 결과는 전송 실행 이력이 기준이다.
