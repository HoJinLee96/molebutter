# 모든 연속 쿠팡 호출의 응답 후 2초 대기

## 변경 범위

2026-10-21 사용자 요청으로 등록·승인 성공에 한정했던 응답 후 대기를 앱의 모든 쿠팡 호출에 적용한다. 이는 앱 호출 정책이며 공식 API의 처리 완료 시간 보장이 아니다. 이전 등록·승인 전용 변경은 [이전 검증](2026-10-21-coupang-approval-response-gap.md)에 남긴다.

`CoupangProductClient.exchange`의 실제 전송 종료 시점부터 단조 시계로 2초의 공통 제한을 설정한다. 정상·거절·잘못된 응답, 네트워크 오류·타임아웃 모두 적용한다. 본문 파싱 전 적용하므로 파싱 실패도 제한을 지운 것으로 취급하지 않는다. 다음 요청은 공통 실행기에서 대기하며 작업 세션 사이에도 유지한다. 같은 계정의 조회·쓰기 경로는 기존 재진입 잠금을 공유한다.

등록 → 승인 → 자동 상세 조회, 가격·재고 수정 → 결과 조회뿐 아니라 목록·옵션·카테고리·브랜드·물류·주문·클레임의 연속 호출과 자동 재시도에 동일하게 적용한다. 앱의 Coupang HTTP 전송 호출 지점은 이 실행기 한 곳임을 코드 검색으로 확인했다. 읽기 POST도 예외가 아니다.

첫 호출은 즉시 가능하며 직전 전송 종료 후 이미 2초가 지났으면 추가로 기다리지 않는다. 더 긴 `Retry-After`, 30초 초과 대기의 즉시 오류, 취소 검사, 최대 2회 시도, 재시도 직전 보호 검사는 유지한다. 모호한 쓰기의 재전송 금지와 UNKNOWN·ACCEPTED 보호를 변경하지 않는다. 실제 조회 상태가 승인 대기이면 성공한 승인 요청을 다시 쓰지 않고 기존 상태를 표시한다.

## 회귀 검사

- 느린 응답을 포함한 GET → 읽기 POST → 가격 PUT → 재고 GET → 수량 PUT → 재고 GET → DELETE → GET의 각 응답 후 간격이 최소 2초인지 검사한다. 호출별로 서로 다른 작업 세션을 사용한다.
- HTTP 401, HTTP 200의 영구 거절·잘못된 본문 이후 다음 작업도 2초를 기다리는지 검사한다.
- 조회 네트워크 오류의 1회 재시도, 쓰기 타임아웃 뒤 별도 조회가 2초를 지키는지 검사한다. 타임아웃 CREATE 자체는 반복하지 않는다.
- 쓰기 재시도 직전의 보호 GET 응답부터 재시도 PUT까지도 2초인지 검사한다.
- 기존 등록·승인·자동 결과 조회, 대기 중 취소, 긴 Retry-After, 새 서명, 재시도 예산·영구 오류·민감정보 없는 진단 로그 검사를 유지한다.

`node scripts/test-coupang-submissions.cjs`의 PC 1440px·모바일 390px 모의 화면 검사도 통과했다. 미리보기·명시적 전송 확인·응답 유실 시 입력 보존·동일 실행키 재사용·UNKNOWN 결과 확인을 검사한다. 화면 검사는 서버의 실제 호출 간격 검사를 대신하지 않으며 간격은 Java 모의 전송의 응답 종료·다음 시작 시각으로 검증했다. 변경 파일의 `git diff --check`도 통과했다.

운영 DB·실행 중인 IDE 앱·실제 쿠팡 판매값·R2 객체는 변경하지 않았다. 실제 쿠팡의 거절 해소를 실계정에서 검증한 결과는 아니다. 실행 중인 앱은 재기동하지 않았으며 변경 코드를 반영한 다음 실행부터 적용한다.
