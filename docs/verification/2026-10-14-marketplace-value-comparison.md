# 네 마켓 최신 조회값과 앱 저장값 비교

2026-10-14. 쿠팡·스마트스토어·롯데ON·11번가 공용 편집기. ESM 제외.

## 구현

`MarketplaceEditing.Target.comparison`은 현재 편집 입력과 별도로 서버가 만든 비교 결과다. 좌측은 실제 조회로 확인된 값, 우측은 마지막 앱 저장 의도다. 기존 전송 준비/실행 문서는 변경하지 않는다. 읽기 실패나 삭제 상태의 보관 문서를 최신 조회값으로 표시하거나 채택하지 않는다.

- **마켓 조회값을 앱에 저장**: 선택한 필드만 해당 마켓의 개별 저장 의도로 채택한다. 해당 필드의 보관 변경을 제거한다. 공통 기준, 다른 마켓, 미선택 변경은 보존한다.
- **앱 저장값으로 수정 준비**: 저장 의도를 최신 관찰값에 대한 UPDATE 변경으로 지정한다. 실제 전송은 입력 검증·전송 확인·실행을 거친다. 수정 불가 항목은 사유와 함께 비활성화한다.
- 다중 선택은 처음에는 미선택이다. 미저장 편집은 별도 ‘현재 편집 · 전송 준비 변경’ 영역에서 표시한다. 내부 선택 응답을 적용할 때 미선택 미저장 입력을 다시 합친다.
- 판매 시작·종료 설정은 서로 다른 경로다. 브랜드 이름·ID만 원자적으로 묶는다. 네이버·11번가 옵션도 공통 옵션 UUID와 필드로 다룬다. 기존 전체 옵션 배열 입력은 경계에서 세분화하고, 실제 마켓 전문은 기존 마켓별 병합 규칙을 따른다.

## 데이터와 동시성

V43은 `marketplace_target_saved`와 `marketplace_comparison_resolution`을 추가한다. 마켓·계정·연결 세대별 저장 문서, 확인된 저장 필드, 항목별 선택 근거와 중복 요청 원장을 보관한다. 기존 초안·옵션 UUID·연결·전송 기록을 다시 쓰지 않는다.

첫 비교 시 유효한 보관 변경의 의도, 기존 네이티브 저장 입력, 동일 연결·세대의 수락/완료된 실행 준비 문서 순으로 복원한다. 출처를 확인할 수 없으면 ‘앱 저장값 없음’이다. 이후 일반 임시 저장은 명시적으로 변경한 필드만 저장 의도에 합친다. 다른 탭을 조회했다는 이유로 전체 저장 문서를 교체하지 않는다.

`POST /api/marketplaces/editor/resolve`는 세션 또는 단독 조회 토큰, revision, 마켓, 연결 세대, 서버 비교 토큰, UUID 중복 방지 ID와 `{key, action: MARKET|APP}`만 받는다. A/B 실제 값은 브라우저에서 받지 않는다. 서버가 해당 마켓을 다시 읽고, 선택한 관찰값과 옵션 연결을 확인한 다음 짧은 DB 트랜잭션에서 revision·세대를 재확인한다. 변경을 발견하면 `applied=false`와 새로운 비교를 돌려주며 입력을 보존한다. 중복 요청의 원장은 잠금 조회하여 MySQL 반복 읽기에서도 같은 요청이 두 번 저장되지 않게 한다.

단독 상품의 첫 명시적 내부 저장은 MARKET_ONLY를 사용한다. 공통 상품을 자동 생성하지 않는다. 첫 조회로 얻은 네이티브 입력을 모든 필드의 앱 저장 의도로 꾸미지 않는다. 기존 공통 연결로 옮길 때 저장 문서의 옵션 UUID도 직접 대응표로 옮긴다.

진행 중·결과 미확인 실행이 있어도 내부 의도 저장은 별도로 가능하다. 해당 실행을 성공 처리하거나 준비 문서를 변경하지 않는다. 새 외부 실행은 기존 실행 상태·수정 권한·승인 조건 검사를 계속 통과해야 한다. 가격·재고 등 무관한 차이까지 자동으로 재전송하지 않는다.

서버가 생성한 편집 이미지와 HTML 자산 참조도 앱 저장 의도에 남아 있는 동안 초안 자산 참조로 보호한다. 전송 준비 변경을 취소하는 것만으로 저장된 편집 이미지를 삭제하지 않는다. 재등록의 이전 세대 문서와 이력도 보존한다.

## 마켓별 제한

- 쿠팡은 공통 문서를 바꾸지 않고 해당 마켓 저장 문서와 선택 변경을 관리한다. CREATE가 외부 ID를 받은 뒤에는 실제 실행 근거가 확인되는 경우에만 저장 문서의 연결을 승계한다. 재등록 세대나 다른 연결을 강제로 통과시키지 않는다.
- 스마트스토어의 현재 옵션 상품 수정 제한을 유지한다. 선택한 옵션 재고 수정만 지원하는 구조는 상품명 등 재적용을 제공하지 않는다. 허용된 재고 변경은 기존 option-stock 경로로 준비한다.
- 롯데ON은 단품 UUID 기반 선택과 기존 승인·수정 조건을 유지한다. 조회되지 않는 정책값을 저장값으로 대신해 관찰값이라고 표시하지 않는다.
- 11번가는 누락된 필드와 읽지 못한 대표·추가 이미지, 확인되지 않은 옵션 메타정보를 관찰값으로 만들지 않는다. 가격·재고·설명 전용 수정 및 전체 PUT의 보존 검사, 주소 생략/이미지 생략 규칙을 유지한다.

공식 계약은 `marketplace-api-docs/README.md`의 읽기 규칙에 따라 쿠팡 수정, 네이버 원상품 수정/옵션 재고, 롯데ON 승인 상품 수정, 11번가 1619 및 관련 FAQ SOURCE를 기준으로 기존 어댑터와 대조했다. 문서 SOURCE·원문은 수정하지 않았다. 계정별 실제 쓰기 성공을 의미하지 않는다.
