# WCWA705R2 비교 화면 실측과 복원 오류 수정

2026-10-14 21:26~21:49 KST. ESM 제외. 로그인된 Chrome의 실제 상품 편집 화면과 읽기 전용 DB 조회로 확인했다. 마켓 등록·수정·삭제·이미지 업로드·공유 정책 변경은 실행하지 않았다.

## 재현과 원인

- 공통 상품 `897779631605467192`의 쿠팡 탭에서 실제 조회는 성공했지만, 등록 전에 보관한 변경을 복원하면서 `보관된 변경의 상품 연결이 달라졌습니다`로 실패했다. 폼과 검증·전송 버튼도 잠겼다.
- 성공한 CREATE 준비 문서의 `mapping`은 null이 아니라 **외부 상품·옵션 ID가 없는 공통 옵션 UUID 틀**이었다. 복원 코드는 mapping 자체가 null인 경우만 신규 등록 근거로 인정했다. 보관 revision은 8, 등록 revision은 7이어서 `applied_revision` 우회도 적용되지 않았다.
- 실제 보관 변경과 등록 의도는 일치했다. 다른 부분은 관련 없는 롯데ON·11번가 설정뿐이었다. 등록 성공·현재 상품 ID·계정·연결 세대가 맞아도 위 조건 때문에 전체 등록 근거 판정이 false였다. 수정 후 같은 실제 데이터의 전체 판정이 true인 것을 확인했다.
- FAILED 대상에도 비교 문서를 만들면서 모든 필드가 `조회 미확인 / 앱 저장값 없음`으로 표시됐다. 새 등록 의도도 복원되지 않아 유효한 앱 저장값이 없는 것으로 보였다.
- 스마트스토어 방문 뒤 쿠팡으로 돌아오면 스마트스토어 공통 적용 설정이 남았다. 전용 컨트롤의 숨김 조건에 현재 탭이 빠져 있었다.
- 쿠팡 조회에 직접 대응하지 않는 공통 제조국·소재·A/S 안내가 투영 과정의 빈 문자열로 비교되어, 실제 빈값처럼 채택할 수 있었다. 상품고시의 해당 값과 공통 필드를 자동으로 동일시하지 않는다.

## 수정

- `registrationBasis`는 기존 null mapping과 ID 미발급 옵션 틀을 구분한다. 동일 계정·연결 세대·공통 옵션 UUID 구성, 외부 ID 미발급 상태를 검사한다. 현재 상품 ID를 받은 수락/성공 CREATE 실행 근거와 같은 저장 의도가 있어야만 복원한다. 다른 상품·계정·세대·옵션 연결은 계속 거부한다.
- 성공한 등록의 저장 의도는 앱 저장 문서로 보존하고 오래된 CREATE 변경만 정리한다. 실제 마켓값과 다른 저장 의도는 비교에서 선택할 수 있다.
- FAILED/DELETED/UNLOADED에는 신뢰할 최신값 비교를 만들지 않는다. 실패한 구버전 응답도 프론트가 미확인 목록으로 펼치지 않는다. 보관 입력과 재조회 경로는 유지한다.
- 앱 저장값 없는 항목은 접힌 목록에서 필요한 경우만 채택한다. 양쪽 모두 모르는 항목은 비교행을 만들지 않는다. 구비서류는 코드 경로 대신 항목명을 표시한다.
- 스마트스토어 전용 적용 설정은 스마트스토어 탭에서만 표시한다.
- 쿠팡 조회에서 확인할 수 없는 공통 필드는 `조회 미확인`으로 표시하고 두 선택을 차단한다. 가죽·국내 등의 기존 앱 저장값은 유지한다.
- IDE가 실행하는 `target/classes`와 실행 JAR를 함께 빌드했다. 실행 방식만 확인했으며 비밀 설정 파일은 열지 않았다.
