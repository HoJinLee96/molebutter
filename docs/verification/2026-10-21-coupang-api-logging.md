# 쿠팡 전체 호출 시작·응답·대기 로그

## 변경

2026-10-21 사용자 요청에 따라 `CoupangProductClient.exchange`의 모든 전송 시도에 START와 RESPONSE/FAILURE를 남긴다. 업무 서비스마다 로그를 추가하거나 새 외부 호출을 만들지 않는다. 기존 응답 후 최소 2초 간격·제한적 재시도·취소·계정 잠금·UNKNOWN/ACCEPTED 보호는 유지한다. 새 API·DB 테이블·마이그레이션은 없다.

한국 시각과 UTC 오프셋, 추적 ID·시도 번호·실행/단계 ID, 고정 API 종류·메서드, HTTP 상태·고정 결과·재시도 결정을 기록한다. 응답 본문 수신 완료 또는 실패 반환 시점을 기준으로 단조 시계의 경과 밀리초를 기록한다. `sincePreviousResponseMs`는 실제 직전 HTTP 응답 이후의 간격이고, `sincePreviousFinishMs`는 직전 전송 실패도 포함한 간격이다. 공통 호출기가 기다린 `paceWaitMs`와 업무 처리·자연 유휴 시간을 합친 간격은 다를 수 있다. 이전 응답이 없거나 응답 없는 실패인 경우 시각을 임의 생성하지 않고 해당 값은 `-`로 기록한다.

첫 성공·재시도 후 성공은 INFO, 업무 거절·취소·재시도 예정 일시 오류는 WARN, 최종 통신/서버 장애·잘못된 응답·예상하지 못한 클라이언트 예외는 ERROR다. 요청 경로·쿼리·전문, 응답 전문·자유 문구, 계정·자격 증명·서명·주문/개인정보, 예외 메시지·스택은 기록하지 않는다. 전송 없이 캐시를 재사용하면 호출 로그도 생기지 않는다.

응답 봉투의 성공과 이후 전체 업무 검증 결과는 구분한다. 주문·클레임의 `code:200`, 반품지의 `code:200,data.content/pagination`, 출고지의 최상위 `content/pagination`과 일반/중첩 SUCCESS 응답을 구분한다. 알 수 없는 결과를 성공으로 처리하지 않는다. 이 판독은 진단용이며 기존 업무 파서의 검증·반환값은 변경하지 않는다. 문서 근거는 현재 보관 SOURCE의 브랜드 검색·발주서 목록·출고지/반품지 목록과 기존 파서다. 공식 SOURCE·원문은 수정하지 않았다.

## 검증

`CoupangApiLoggingTest`에서 다음을 검사한다.

- 첫 성공부터 START/RESPONSE가 INFO 한 쌍으로 남고 추적 ID가 일치하는지.
- 느린 응답과 서로 다른 작업 세션 사이의 실제 간격이 2초 이상이며 로그에도 반영되는지.
- 첫 호출의 이전 응답 값, 네트워크 실패의 없는 응답 시각, 실패 후 재시도의 완료 간격을 구분하는지.
- 재시도는 같은 요청 ID·다른 시도 번호를 가지며 WARN → INFO 복구, WARN → ERROR 소진을 구분하는지.
- 401·403·5xx·업무 거절·잘못된 JSON·예상하지 못한 예외·취소의 레벨과 고정 결과가 적합한지.
- 정상 주문·출고지·반품지·카테고리 응답 봉투를 잘못된 응답으로 기록하지 않는지.
- 키·서명·요청/응답·계정·예외 메시지·스택이 로그에 섞이지 않는지.

## 실행 결과

2026-10-21 18:01 KST, JDK 21·오프라인 Maven으로 `bash scripts/test-integration.sh`를 실행했다. 임시 MySQL·Redis와 모의 API만 사용하며 빌드는 `target/verification`으로 분리했다. 126개 검사 묶음, 1,190개 중 1,185개 통과·5개 조건부 생략, 실패·오류 0개로 BUILD SUCCESS다. 생략은 인증 통합 조건 4개와 실제 쿠팡 주문 조회 조건 1개다.

전용 로그 검사 6개, 기존 `CoupangRetryTest` 16개·`CoupangClientTest` 29개·`CoupangWorkingCopyWriteTest` 63개가 모두 통과했다. 느린 모의 CREATE → APPROVAL → 상세 GET의 로그에서 응답 간격 `sincePreviousResponseMs=2004`와 공통 간격 검사 대기 `paceWaitMs=2000`/`1993`을 구분해 확인했다. 이것은 로컬 모의 HTTP 검증이며 실제 쿠팡 호출 결과가 아니다. 변경 경로의 `git diff --check`도 통과했다.

운영 DB·실행 중인 IDE 앱·실제 쿠팡 상품값·R2 객체는 변경하지 않았다. 현재 동작 중 앱의 로그 계측을 검증했다고 주장하지 않으며 변경 코드가 반영된 앱 실행부터 전체 호출 로그가 생긴다.
