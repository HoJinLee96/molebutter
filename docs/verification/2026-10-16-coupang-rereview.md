# 쿠팡 작업본·전송 재검토 — 2026-10-16

이전 V48 변경을 다시 검토해 저장·복구·미수정 원문 보존 문제 4개를 회귀 검사로 재현하고 수정했다. 판매용 내부 상품·연결 후보·기준값·비교 실행 계층은 현재 화면·API에서 제거된 상태를 유지한다. 필요한 공개 계약·서버 식별자 보호·감사 판독은 보존했다.

## 재현과 수정

| 문제 | 재현된 동작 | 수정 |
|---|---|---|
| P1 완료 직후 임시 저장 | 가격 전송이 성공한 뒤 목록 갱신 전에 기존 세션으로 상품명을 저장하면 완료된 가격 수정도 다시 저장됨 | 세션이 확인한 미완료 의도와 현재 남은 의도를 잠금 안에서 대조. 확인된 기존 값만 제외하고 해당 기준 문서를 갱신. 새 가격·상품명은 보존 |
| P1 중복 미디어 재진입 | 같은 URL·설명이 여러 행이면 이전 ID를 여러 번 배정해 작업본 조회가 식별자 검사에서 실패 | 이전 ID를 한 번만 배정. 외부 목록의 앞 삽입·순서 변경 때 새 ID와 재사용 ID의 충돌 방지. 최신 설명 세부 유형도 유지 |
| P2 서류의 미수정 원문 변경 | B의 벤더 경로를 수정하면 A의 미수정 벤더 경로가 사라짐. 같은 행의 벤더 경로 수정도 기존 CDN 경로 우선 처리 때문에 반영되지 않음 | 최신 원문의 지정한 행·필드만 직접 패치. 두 경로와 알 수 없는 필드는 독립적으로 보존 |
| P2 인증의 누락 필드 변경 | 한 인증 코드를 수정하면 다른 인증에 원래 없던 코드 필드를 null로 추가함 | 미수정 행은 원문 그대로 유지. 고시·인증·서류의 추가·삭제·필드 수정을 같은 원문 패치로 처리 |

작업본 통합 검사는 `aCompletedPriceCannotReturnThroughAnUnrefreshedSessionSave`, `repeatedImageUrlsAndDescriptionTextKeepDistinctIdsOnReentry`, `aSessionWithoutPendingIntentIsRenewedWithoutChangingSavedInputs`로 추가했다. 전송 검사는 서류 두 경로 독립 수정·미수정 행 동일성·인증 누락 필드·고시 삭제와 외부 추가 행 보존을 추가했다. 수정 전에는 전송 검사 2건 실패와 통합 검사 1건 실패·1건 오류를 확인했다. 수정 후 같은 검사가 통과했다.

이전 세션 JSON에 미완료 의도 정보가 없으면 저장 입력을 유지한 채 만료 복구로 새 세션을 연다. DB 열이나 테이블을 추가하지 않는다. 과거 Session 생성자와 직렬화 형태, 전문·해시·중복 방지 키와 역사적 판독은 유지한다. 새 전문은 계속 schemaVersion 4다.

## 코드와 문서 정리

- 별도 공개 `saveWorkflow` 호출과 전문을 두 번 파싱하는 승인 준비를 제거했다. 전송 준비에서 저장·승인 단계 목록을 한 번 완성한다. 가격·재고·배송만 변경하면 승인 단계를 추가하지 않는다.
- 사용하지 않는 실행 오버로드·기본 계정 반환 구현·바인딩 생성자·구매 속성 변경 매퍼를 제거했다. 실제 전송 전문 기록 콜백은 필수 계약으로 유지한다.
- 서로 다른 두 목록 병합기를 하나의 원문 행 패치로 교체했다. 완료 의도 대조도 같은 `sameChange` 규칙을 사용한다.
- 쿠팡 구현 안내에서 오래된 날짜별 중복 설명·옛 재등록 흐름을 덜어내고 현재 책임·API·전송·복구 기준으로 정리했다. 모듈·DB 책임표의 초안·비교·configuration 표기도 현재 작업본 구조로 고쳤다.
- V47 절차는 역사적 전환으로 표시하고 현재 V48 절차를 연결했다. 이전 날짜의 검증 기록과 복구용 소스 백업을 남겼으며 공식 SOURCE·원문·전용 자산을 변경하지 않았다.

## 실제 로컬 앱

이번에는 마이그레이션·판매 초기화를 실행하지 않았다. 적용된 V48을 유지했다. 현재 판매 작업·활성 임대가 없는 것을 확인하고 기존 JAR를 보존한 뒤 검증된 JAR로 8081 앱을 재기동했다. 새 형식 정보가 없는 기존 편집 세션은 입력 보존·세션 갱신으로 재개한다.

수정 전 소스·해시·이전 JAR·검증 로그·재기동 전 DB 지문은 `backups/coupang-rereview-before-20261016/`에 보존한다. 최종 JAR SHA-256은 `0bfd28100bee5f59e1c9a3d910835d5ab3883d838a844b50611f6e9d9b758e8b`다. 실제 로컬 DB의 73개 전체 테이블에서 재기동 전후 행 수와 값 지문이 동일했고 V48 실패 이력은 없었다. 로그인·CSRF·정적 JS·작업본 API 인증·없는 공개 이미지 404·제거된 편집기 자원 404도 확인했다.

실제 쿠팡 쓰기·공용 R2 삭제·Redis 전체 초기화는 실행하지 않았다. GET과 PUT 사이 외부 변경의 원자적 차단은 보장하지 않는다. 현재 계약은 [상품과 작업본](../coupang-api/working-copies.md), [구현 안내](../coupang-api/coupang-wing.md), 재현 명령은 [테스트 안내](../testing.md)를 따른다.
