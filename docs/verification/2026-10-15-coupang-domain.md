# 쿠팡 업무 통합과 V46 데이터 보존 검증

검증일: 2026-10-15 KST. 이전 V45 초기화 작업과 구분되는 **데이터 보존 전환**이다. 이번 작업에서 판매 데이터를 다시 초기화하지 않았다.

## 반영 결과

- 판매 관련 세 Maven 모듈을 `molebutter-coupang` 하나로 통합했다. `coupang.api`가 계약, `coupang.internal`이 업무·저장, `coupang.internal.client`가 쿠팡 HTTP를 담당한다.
- Marketplace 이름, 공급자 선택과 마켓 인자·바인딩 맵·단일 대상 리스트 호환을 제거했다. 편집·미리보기·전송은 `target` 하나를 처리한다. 확장용 기본 구현과 불필요한 관측 래퍼도 제거했다.
- `/coupang`, `/coupang/drafts/...`, `/coupang/products/...`, `/coupang/orders`, `/api/coupang/...`, `/coupang/images/{token}`으로 전환했다. 이전 앱 주소의 별칭은 없다.
- 내부 기준 / 쿠팡 적용값 비교, 옵션 UUID·외부 ID, 계정·revision·연결 세대, 임시 저장·재진입·이미지 상속·변경 충돌·중복 전송·UNKNOWN 차단을 유지했다.
- 신규 전송은 schemaVersion 2를 저장한다. 과거 v1 증거는 쿠팡 전용 판독기로 읽고 요청 원문·요청 해시·중복 방지 키는 다시 쓰지 않는다. 타 마켓 값·복수 대상·채널 ID는 자동 폐기하지 않고 거절한다.
- 브라우저 저장 키는 값 확인 후 새 이름으로 옮기며 충돌 시 양쪽 입력을 보존한다. 매입·인증·보유 재고 저장 상태는 유지한다.

V46 검사는 현재 주문·클레임, 0수량과 큰 외부 ID, 초안·편집 binding·이미지·공개 토큰·전송 증거를 보존한다. 타 마켓 값, QUEUED/RUNNING 작업과 유효한 주문/전송 계정 임대를 전환 전에 거절한다. FK·인덱스·CHECK 이름과 부모 참조, 원본 prepared JSON의 동일성과 반복 migrate를 검사했다. 실패한 Flyway repair는 격리 테스트 DB에서만 수행했다.

## 실제 로컬 DB 적용

앱·워커 중지 → 전체 DB 백업 → 격리 MySQL 복원·전체 지문 대조 → V46 → 전후 지문 및 파일 대조 순서로 실행했다.

- 백업: `backups/coupang-domain-20261015-1647`
- 전체 SQL 백업: 419,098,999바이트. 격리 복원의 모든 테이블 지문이 원본과 일치했다.
- 업무 테이블 69개를 전후 대조했다. 쿠팡 테이블 32개와 보존 영역 37개의 모든 행·값을 보존했다. Flyway 적용 이력은 별도로 정상 전진했다.
- 적용 전 판매 테이블은 계정 잠금 1행 외 비어 있었다. 전환 후에도 동일했다. 이번 명령은 데이터를 삭제하지 않았다.
- 판매 이미지 DB 행과 이전 이미지 디렉터리는 없었으며, 새 `molebutter-app/data/coupang-assets` 경로를 준비했다. 파일이 있는 경우의 백업·이동·바이트 보존은 별도 합성 검증에서 확인했다.
- `UPGRADE_COMPLETE`, `verified-before.txt`, `canonical-before.txt`, `asset-locations.txt`를 백업에 남겼다. 백업은 비공개로 보관한다.

기존 실행 설정으로 새 앱을 8081 포트에 재기동했다. Flyway는 현재 버전 46과 추가 마이그레이션 없음으로 확인됐고, `/signin`·`/api/auth/csrf`는 HTTP 200을 반환했다. 비밀 파일은 직접 열거나 수정하지 않았다.

## 보존과 제외 범위

회원·권한·근태·내부 상품·매입·보유 재고·재고 이동·가격조회 영역의 소스는 이번 전환 직전 백업과 동일하다. V1~V45와 역사적 SalesSchema도 바이트가 동일하다. 쿠팡 SOURCE·원문·전용 검수 자료 1,791개는 이전 해시와 모두 일치한다.

문자열 예외는 쿠팡 공식 API·SOURCE·원문, 과거 Flyway·감사 증거·복구 백업, 기존 비밀 설정 경로와 이행 판독기다. 역사적 마켓 테이블 목록을 현재 유지보수용 CoupangSchema와 분리했다.

실제 쿠팡 쓰기·공용 R2 삭제·Redis 전체 초기화는 실행하지 않았다. 실계정 조건 생략은 실제 계정 검증 성공을 뜻하지 않는다. 다른 업무의 정상 워커 동작과 전환 자체의 지문 검증은 구분한다.

실행 로그는 비공개 로컬 `output/coupang-domain/`에 보존했다. 절차와 복구는 [V46 전환 안내](../coupang-domain-migration.md), 반복 검증은 [테스트 안내](../testing.md)를 따른다.
