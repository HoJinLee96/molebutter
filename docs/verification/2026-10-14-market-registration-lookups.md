# 롯데ON·11번가 상품 등록 준비 조회 검증

검증일: 2026-10-14. ESM은 변경 대상에서 제외했다. 쿠팡·네이버의 기존 선택 기능은 공통 창 회귀만 확인했다. 실제 마켓 상품 등록·수정, 이미지 업로드, 주소·정책 생성, 운영 DB 변경과 서버 재시작은 수행하지 않았다.

## 근거

`marketplace-api-docs/README.md` → 각 OVERVIEW/INDEX → SOURCE·관련 공지 → KNOWN-ISSUES를 확인했다. 롯데ON 203/204/205/206, 89, 150, 166, 87/90과 브랜드 공지 102879/104708을 사용했다. 11번가 1001, 1014/1015, 6735, 1003/1619 및 브랜드 198344974·107007559, 주소 정책 204817455, 발송마감 166614155, 배송 결제 148765077 공지를 대조했다. 사용자 제공 SOURCE는 수정하지 않았다.

롯데ON은 실제 선택한 거래처의 주소·배송비 정책 등록이 필요하다. 11번가는 일반 택배 상품 등록 전 셀러오피스에서 발송마감 템플릿을 등록해야 한다. 조회 성공과 등록 준비 완료는 별개다.

11번가 원산지 공식 파일은 HTTP 200·정상 XLSX·헤더 `원산지상세코드, 원산지상세명`으로 확인했다. 1003 SOURCE의 인증유형 링크 `https://cdn.011st.com/upload/selleroffice/download/product/cert/Product_Cert_20250826_update.xlsx`도 HTTP 200이었지만 실제 첫 시트는 AS-IS/TO-BE/LEAF 카테고리 표 15,291행이었다. 이를 인증 코드로 변환하지 않았다. 상품고시·인증 코드표와 관리 브랜드 CSV 최신본 확보는 남은 외부 자료 의존성이다.

## 실행한 자동 검증

- 관련 Java 단위 83개: 오류 0. 브랜드 CSV 인코딩·따옴표·페이지·갱신·중복 거부, 공통 주소 서버 정규화와 롯데ON 투영·개별값 보존, 카테고리 상위 필터, 기존 상품 전송 모의 회귀 포함.
- 격리 MySQL·Redis의 `MarketplaceEditingFlowIT` 37개: 오류 0. 추가 읽기 API의 HTTP 계약과 기존 연결·저장·재진입·모의 전송 회귀 포함.
- 전체 JavaScript 단위 310개: 오류 0. 공통 브랜드·주소와 개별값 보존, 늦은 응답·조회 실패·페이지 보존 포함.
- Chrome 모의 화면: 1440px·390px에서 롯데ON, 11번가, 공통 주소, 공통 카테고리 네 흐름 통과. 외부 요청 차단. 브랜드·카테고리·주소·원산지·택배사·템플릿·속성·고시·인증 선택과 임시 저장·재진입을 검사했다. Enter 조회와 입력창 Enter의 쓰기 방지도 확인했다.

브라우저 검증은 현재 통합 HTML과 실제 화면 제어 코드를 사용하지만 API·초안 DB 응답은 모의다. 실계정 검증은 위 읽기 건수에 한정하며 실제 등록 성공을 보증하지 않는다. 실행 JAR를 갱신했고 서버 적용은 재시작 후 이루어진다.
