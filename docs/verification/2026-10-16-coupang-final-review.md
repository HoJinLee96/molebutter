# 업로드·재시도·요청 형식 재검토 — 2026-10-16

[직전 수정 3건](2026-10-16-coupang-recovery-review.md)을 다시 검사했다. 불명확한 업로드 커밋에서 이미지 보존, 삭제 실패 표식의 재시도 순서, 지원하지 않는 Content-Type의 415 처리에서 회귀는 재현되지 않았다. 기존 작업본·전송의 보호 계약도 유지한다.

## 추가 수정

**[P2] 앱이 받는 구조화된 JSON의 입력 검사 누락.** Spring JSON 변환기는 `application/*+json`을 받지만 쿠팡 요청 가드는 `application/json`만 검사했다. vendor JSON에서 이전 판매 형식을 거절하지 않고 11MiB 제한도 건너뛰는 것을 계약 검사로 재현했다. 같은 가드를 적용하도록 보완하고 중복 Content-Type 조회를 제거했다. 정상 입력의 원본 바이트와 불투명한 수정값을 보존하며 text/plain·XML의 415 처리는 유지한다. 쿠팡 공식 API 요청 형식을 변경한 것이 아니다.

확정 업로드 롤백 후 파일 삭제가 실패하는 경로를 추가로 검사했다. DB 행은 롤백되고 파일 삭제 표식이 남으며, 새 정리 객체가 파일과 표식을 제거한다. 이미지 저장·정리의 실행 코드와 공통 415 처리는 이번에 변경하지 않았다. 새 업무 계층·DTO·마이그레이션·호환 주소는 추가하지 않는다.

## 재검토 범위

- 업로드 커밋의 확정 롤백·결과 불명확 양쪽 결과, 감사 참조 이미지 보존과 롤백 파일 정리 실패 후 복구.
- 현재·감사·편집 원본 참조, 후보 조회 뒤 추가된 핀, 커밋 전후 별도 JVM 강제 종료·재시작 복구, 100개 이상 실패 표식의 재시도.
- 일반·구조화된 JSON의 과거 형식 거절·크기 제한·바이트 보존과 실제 HTTP 감사. JSON·세션 오류의 400/404와 지원하지 않는 Content-Type의 415·장애 알림 방지.
- 작업본 저장·복구·완료 경합·중복 미디어 ID, 수정 항목만 최신 쿠팡 원문에 적용, 미수정 값·알 수 없는 필드 보존, 중복 전송·UNKNOWN 보호.

판매용 내부 상품·연결 후보·비교 계층의 잔재나 재도입은 확인되지 않았다. 옵션 UUID·외부 ID 매핑, 계정·revision·연결 세대와 역사적 증거 판독기는 필요한 보호로 유지한다. 회원·권한·근태·상품업무·매입·보유 재고·공용 R2·과거 자료는 정리하지 않는다.

## 로컬 반영

활성 판매 작업·임대가 없음을 확인하고 이전 JAR의 해시 사본을 보관한 뒤 검증본으로 재기동했다. V48과 전체 73개 테이블의 행·값 지문은 전후 동일하다. 로그인·CSRF·편집 JS 200, 작업본 API 인증 401, 없는 공개 이미지·제거 JS 404와 정상 기동을 확인했다.

최종 JAR SHA-256은 `894b8e11562c57d0e464f69207a3c64aeb52f06343ad31e19ced3a0f83fc6e68`다. 실행 중 JAR를 빌드로 덮지 않고 별도 검증 경로의 JAR로 교체했다.

수정 전 소스 735개를 해시·파일 권한까지 대조해 `backups/coupang-final-review-before-20261016/`에 보관했다. 실패 재현·성공 검증 로그와 검사 집계는 같은 디렉터리에 보관한다. 실제 쿠팡 쓰기·공용 R2 삭제·기존 DB 초기화는 수행하지 않는다. 실행 기준은 [테스트 안내](../testing.md)와 [운영 기준](../operations.md)을 따른다.
