# 다른 상품의 전송 복구 기록과 새 일괄 수정 선택 분리

검증일: 2026-10-22 한국 시각. 운영 DB·실행 중인 IDE 앱·실제 쿠팡 상품값·R2 객체를 변경하지 않았다.

## 원인과 수정

- 기존 `coupang-bulk-edit.js`는 `sessionStorage`의 가격/재고별 복구 기록에서 선택 밖의 receipt를 발견하면 새로 선택한 행을 전부 비우고 큐를 생성하지 않았다. A상품 기록이 남으면 다른 B상품도 빈 모달·저장 불가가 되는 원인이다. 쿠팡 API가 이번 B상품을 거절한 상태는 아니다.
- 현재 선택은 그대로 열고 다른 대상의 기록은 안내와 명시적인 이전 결과 확인 버튼에 보존한다. 현재 큐에 과거 대상을 추가하지 않는다. 복구 전환 버튼은 조회/전송 중 비활성화하며 실행 함수에서도 검사한다.
- 저장은 등록상품 ID·옵션 ID를 함께 키로 사용해 현재 행만 교체한다. 현재 선택 밖의 receipt와 준비 ID·멱등키·실행 ID, 미전송 입력은 보존한다. B상품 완료 뒤 A 복구도 B의 결과를 덮어쓰지 않는다. 세션 자료가 잘못됐으면 원문을 보존하고 새 전송을 중단한다.
- 서버 전송 경로는 바꾸지 않았다. 같은 상품의 UNKNOWN/ACCEPTED 보호·revision·매핑·근거·권한·계정 임대와 HTTP 간격은 그대로다. 공개 API·테이블·마이그레이션을 추가하지 않았다. 브라우저 정적 리소스 버전을 갱신했다.

## 실패 로그 확인 범위

기존 로그에서 13:46:09의 가격 실행 `900968234273033016`이 `FAILED / MAPPING_CHANGED`로 끝난 것을 읽었다. 해당 실행은 상품 상세·현재 옵션 재고 GET 성공 후 가격 PUT 전에 중단됐다. 로그에 상품코드·옵션 ID가 없어 이것이 사용자가 말한 A상품인지 확정하지 않았다. 실패 기록을 임의로 성공 처리하거나 삭제하지 않았다.
