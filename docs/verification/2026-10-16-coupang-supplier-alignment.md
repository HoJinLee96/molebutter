# 쿠팡 선정 매입처 열 정렬·보유 재고 검증

- 펼침 내부 표에 기존 쿠팡 표의 12열 `colgroup`을 그대로 재사용했다. 이미지·코드·가격·재고·조회 상태를 위 행의 해당 열에 맞추고 내부 셀은 6px/18px 패딩을 유지한다. 재고 열에는 매입처 수량과 실제 보유 수량을 두 줄로 표시한다.
- 기존 공통 매입처 렌더러에 열별 표시를 추가했으며 상품 화면의 기존 요약은 유지한다. 요청한 두 안내 문구를 제거하고 미선정·미발견·조회 실패는 남긴다.
- 보유 값은 기존 재고 요약 API의 `onHand`이며 미입고는 합산하지 않는다. 재고 항목이 없는 상품은 보유 0개, 조회 실패는 실패로 표시한다. 기존 중복 제거·100개 단위 조회·지연 응답 무시와 `inventory-updated` 갱신을 재사용한다. 새 공개 API·DB 마이그레이션은 없다.

검증 결과:

- JavaScript 전체 205개 통과.
- `LayoutViewTest`, `CoupangUnifiedViewTest` 6개 및 패키징 통과.
- `test-coupang-suppliers-ui.cjs`: Chrome 1920/1440/390px에서 이미지·코드·가격·재고·상태 열의 좌표 차이 1.5px 이내, 이전 매입처 수량·0개, 보유 양수·0개·조회 실패·갱신, 미입고 제외, 체크·다중 펼침·더 보기·늦은 응답·실패 재시도·카드 검색 회귀 통과.
- `test-coupang-quick-edit-ui.cjs`, `test-product-ui.cjs`: 기존 같은 페이지 상품 모달, 가격·재고 수정·미저장 입력·UNKNOWN 보호, 상품·설정 화면 회귀 통과.
- 모의 캡처를 직접 확인했다. `molebutter-app/target/ui-check/supplier-alignment/`에 1920/1440/390px 캡처를 보관한다.

실행 중인 IDE 앱·운영 DB는 변경하지 않았다. 외부 트래픽은 모의 화면에서 차단했으며 실제 쿠팡 요청·재고 변경은 실행하지 않았다. 이번 변경은 화면과 기존 조회 API 재사용이므로 운영 DB 검증·마이그레이션을 실행하지 않았다.
