# 쿠팡 작업본 복구·수정 의도·잔여 계층 정리 — 2026-10-15

승인된 세 문제를 수정하고 V48을 실제 로컬 DB에 적용했다. 판매용 내부 상품·연결·기준값·비교 화면/API를 다시 도입하지 않았다. 현재 업무에는 쿠팡 상품·작업본·전송과 필요한 보호만 남긴다. 실제 쿠팡 쓰기와 공용 R2 삭제는 실행하지 않았다.

## 수정한 동작

- 신규 작성은 세션 만료·앱 재시작으로 서버 세션이 없어져도 작성 문서 전체와 옵션 UUID를 새 세션에 보존한다. PC·모바일에서 첫 요청 실패 뒤 재시도의 문서가 동일함을 검사했다. 첫 저장 전 작업본을 만들지 않으며 저장 후 새 작성 화면의 캐시를 비운다.
- 등록상품은 최신 조회에 명시한 행·필드 수정만 적용한다. 속성의 이름·노출 구분, 고시의 분류·항목명, 인증 유형, 서류명을 `rowKey`로 사용하며 `SET`/`REMOVE`를 구분한다. 이미지·상세설명은 옵션별 목록 단위다. 색상만 수정한 뒤 외부 사이즈가 L·XL로 바뀌어도 유지한다.
- 즉시 응답·자동 조회·새로고침·수동 결과 확인의 완료 처리를 통일했다. 확인된 단계와 값이 일치하는 수정만 제거하고 새 미저장 입력·다른 revision에서 저장한 다른 값을 보존한다. 가격 단계 성공·상품 단계 실패에서도 다음 상품명 수정에 완료된 가격을 포함하지 않는다. 등록 완료 후 UPDATE로 전환하고 입력 잠금을 해제한다.
- 캐시는 마지막 저장 문서와 미저장 입력의 차이를 보관한다. 완료 전 캐시가 남아도 최신 서버 의도에 미저장 차이만 복구한다. 계정·revision·옵션 구조 변경 시 입력을 보관하고 재준비한다. 모호한 과거 목록 전체 수정은 추정하지 않으며 내려받기·보관 후 재준비하도록 한다.
- 전송 직전 GET 원문에 수정 의도만 적용한다. 가격 120000 → 사용자 130000 → 외부 150000 → 요청 130000 정책과 미수정·알 수 없는 원문 필드 보존을 유지한다. 구매 속성은 최신 개별 editable 권한을 확인한다.
- 새 전송 전문은 schemaVersion 4다. 기존 1~3 전문·해시·중복 방지 키는 조회·결과 확인에 사용하고 새 쓰기는 새 미리보기를 요구한다. 과거 3필드 Change의 직렬화 형태를 유지했다.

현재 실행에서 쓰지 않는 옛 변경 매퍼·복구 함수·가져오기 취소 변수·세션 보조 메서드, 중복 edit-data·검증·세션 갱신 API, 무시되던 requested 요청 인자와 전송 준비 오버로드를 제거했다. 재등록 이력 작성 API를 제거하고 이력 조회·이미지 보호는 감사 테이블을 읽도록 바꿨다. 이전 V45/V46/V47 유지보수 명령은 각 대상 버전으로 고정했다. 변경된 JS의 템플릿 버전을 갱신했다.

Coupang 전송 검사는 모의 API다. 실제 계정 권한이나 실제 외부 쓰기의 성공을 뜻하지 않는다. 공식 SOURCE 수집일과 위 실행일을 구분한다. GET과 PUT 사이 외부 변경의 원자적 차단을 보장하지 않는다.

## 실제 로컬 적용과 보존

앱·워커를 중지하고 전체 DB·판매 파일의 격리 복원을 확인한 뒤 사전 검사·V48·전후 대조·재기동 순으로 적용했다. 새 백업은 `backups/coupang-intent-20261015-v48-verified/`이며 전체 dump는 413128779바이트다. `UPGRADE_COMPLETE`, 전후 행 지문, 실행된 미리보기 지문, 적용 소스·JAR 지문을 보존했다. 이전 V47 JAR와 이번 수정 전 소스는 `backups/coupang-intent-before-20261015/`에 있다.

첫 전환 시 기존 V48 실패 이력(20:31:18)이 검증을 막았다. 해당 시점의 전환 SQL 미적용을 확인했고 V47 적용 직후와 판매 테이블명·행 지문이 동일했다. 전체 백업의 격리 복원과 현재 모든 행 지문, 세 원본 테이블 존재·세 감사 대상 부재, 단일 실패 이력이며 다른 체크섬 오류가 없음을 확인했다. 실패 이력도 첫 백업에 보존한 뒤 해당 실패 기록 한 건만 정리했다. 일괄 Flyway repair나 과거 체크섬 변경은 하지 않았다. 이후 새 전체 백업을 다시 복원 검증해 V48을 적용했다. 첫 백업과 조치 근거도 `backups/coupang-intent-20261015-v48/`에 보존한다.

- 보존 영역 37개 테이블·90509행의 행 수와 값 지문이 전후 동일했다. 상품업무·매입·보유 재고·회원 등을 초기화하지 않았다.
- 실제 전환 직전 작업본·주문·이미지·전송은 0행이었다. 주문 계정 잠금 1행을 보존했다. 실제 로컬 DB에는 판매 이미지 파일이 없었으며, 자료가 있는 전환·이미지 바이트 검증은 위 합성 DB에서 별도로 수행했다.
- 현재 쿠팡 테이블 24개, 감사 테이블 11개다. 이력 3개를 이름 변경해 감사 영역으로 옮겼다. 전체 FK 81개에서 고아 행 0개를 확인했고 재기동 후에도 보존 지문과 FK를 다시 확인했다. 실제 전환 명령 재실행도 데이터·파일을 변경하지 않았다.
- 상품업무 등 보호 소스와 V1~V47·역사적 SalesSchema 363개, 쿠팡 SOURCE·원문·전용 자산 1791개의 SHA-256 동일성을 확인했다. V47 소스는 `ac01909803bce44d76b269a9a6507047b89cbaf61b9e49a39c39347d1f36265b`, 적용된 V48 소스는 `248bc238c12269f01b633ebbb683c98ba207cd6b179d2dfb9418d1cca25b8c19`다.

최종 `molebutter-app/target/molebutter-0.0.1-SNAPSHOT.jar`로 8081에서 재기동했다. 로그인·CSRF·새 JS 버전·작업본 API 인증·없는 공개 이미지의 인증 없는 404·제거된 편집기 자원 404를 확인했다. 최종 JAR SHA-256은 `c18ab6b4c33f22c43b0d6c445adccbcded7aa19336d6ece197a8ed87d6712eb3`다. IDE 문제 표시와 실제 Maven 빌드 결과는 구분한다.

현재 계약은 [작업본](../coupang-api/working-copies.md), 적용·복구는 [V48 절차](../coupang-intent-migration.md), 재현 명령은 [테스트 안내](../testing.md)를 따른다. 백업에는 실제 DB 자료가 있으므로 공개 산출물에 포함하지 않는다.
