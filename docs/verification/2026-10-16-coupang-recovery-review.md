# 커밋·재시작 복구 재검토 — 2026-10-16

[이전 검토의 3건](2026-10-16-coupang-cleanup-rereview.md)을 다시 검사했다. 삭제 커밋 실패·재진입과 참조 보호, JSON 문법 오류·세션 누락 처리는 유지됐다. 별도 JVM을 삭제 커밋 직전·직후에 종료하는 검사를 추가했다. 실제 쿠팡 쓰기·공용 R2 삭제·기존 DB 초기화는 수행하지 않는다.

## 추가로 재현·수정한 문제

- **[P1] 업로드의 불명확한 커밋에서 파일 유실.** `afterCompletion`이 COMMITTED 이외 상태에서 파일을 지워, DB 커밋 후 응답을 잃은 UNKNOWN 상태에서도 이미 저장한 파일이 사라졌다. 격리 MySQL의 실제 커밋 후 예외로 재현했으며 감사 FK와 메타데이터는 남아 있었다. 확정 롤백에서만 즉시 삭제하고 결과가 불명확하면 파일·삭제 표식으로 DB 확인을 기다린다. DB에 행이 남으면 파일을 보존하며, 행이 없을 때만 정리한다. 확정 롤백의 파일 삭제 실패도 같은 표식으로 재시도한다.
- **[P2] 실패 표식 100개 뒤의 파일이 계속 대기.** 고정된 디렉터리 순서의 첫 100개가 계속 실패하면 이후 정상 파일이 다음 실행에서도 선택되지 않았다. 101개 표식으로 재현했다. 오래된 표식을 먼저 처리하고 실패한 표식의 시각을 갱신한다. 새 정리 객체에서도 남은 정상 파일을 처리하는 것을 검사한다.
- **[P2] 잘못된 Content-Type의 서버 오류·장애 알림.** 쿠팡 JSON 요청을 text/plain·XML로 보내면 지원하지 않는 미디어 예외가 공통 500 처리로 흘렀다. 격리 HTTP에서 재현한 뒤 공통 415 처리로 연결했다. 입력 오류를 서버 장애 알림으로 기록하지 않고 감사에는 실제 HTTP 결과를 남긴다. 예외 메시지·요청 원문을 응답에 복사하지 않는다.

삭제 표식 생성·형식 검사를 공용 메서드로 모았다. 새로운 업무 계층·DTO·테이블·마이그레이션·호환 주소는 추가하지 않았다. 운영 문서에는 업로드 결과 불명확과 삭제 재시도 순서를 반영했다. 과거 검증 결과·공식 SOURCE·원문은 수정하지 않는다.

## 다시 확인한 계약

- 작업본·전송 전문·감사 이력·감사 핀·편집본 원본 참조를 보호한다. 후보 조회 뒤 다른 트랜잭션에서 추가된 감사 핀도 자산 잠금 뒤에 확인한다.
- 삭제 SQL 커밋 전후의 별도 JVM 강제 종료에서 파일을 보존하고, 새 정리 객체가 DB의 실제 존재 여부에 따라 복구한다. 호스트 전원 차단 검사는 아니다.
- 업로드의 확정 롤백과 커밋 응답 유실 양쪽 결과를 검사한다. 로컬 DB의 UNKNOWN은 쿠팡 전송 UNKNOWN과 별개다.
- 빈 본문·공백·null·배열·문자열·여러 JSON 값·잘못된 문법은 실제 HTTP에서 400으로 처리한다. 세션 null·빈 값·잘못된 숫자 형식은 400이며 작업본을 만들지 않는다. 존재하지 않는 정상 형식의 세션은 기존 404 코드와 요청 사용자 실패 알림을 유지한다.
- 저장·전송 완료 겹침, 세션 복구, 중복 미디어 ID, 수정 항목만 전송, 미수정 최신 쿠팡 값·알 수 없는 원문 필드 보존, 성공 단계 재실행 금지와 UNKNOWN 재쓰기 차단을 기존 회귀 검사로 확인한다.

현재 판매용 내부 상품·연결 후보·비교 계층의 재도입은 확인되지 않았다. 옵션 UUID·외부 ID 매핑, revision·계정·연결 세대 보호와 역사적 판독기는 전송 안전에 필요한 코드로 유지한다. 상품업무의 상품·매입·보유 재고는 별도 보존 범위다.
