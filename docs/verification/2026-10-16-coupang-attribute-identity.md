# PR #35 구매·검색 속성 구분 재검토

실행일은 2026-10-16(KST), 기준 커밋은 `0d22ff21`이다. 별도 리뷰의 지적을 현재 화면·작업본·서버 전송과 대조했다. 이 기록은 해당 속성 흐름의 수정·회귀 결과이며 PR 전체의 새 리뷰와 구분한다. 이전 결과는 [V47 커밋·중단 재검토](2026-10-16-coupang-v47-rereview.md)다.

## 재현과 변경

**[P2] 같은 이름의 검색속성을 구매 입력칸에 연결하는 결함을 재현했다.** `색상/NONE`이 `색상/EXPOSED`보다 앞에 있는 합성 상품을 실제 로컬 Chrome에 표시했을 때 구매칸의 값이 `검색 색상`이었다. 새 모델 회귀 검사도 규격 채우기·선택·권한·검증에서 실패했다. 저장 모델과 서버는 이미 이름·노출 구분의 복합 키를 사용하므로, 잘못 선택한 검색행이 그대로 수정 의도가 되는 문제다.

같은 원인의 규격 채우기·필수/형식 검증·선택 구매속성 표시·택1 선택도 함께 수정했다. 택1 전환은 구매행만 바꾸고 이름이 같은 검색행을 보존한다. 반복되는 행 비교는 `sameAttribute` 함수로 통일했다.

서버의 화면용 수정 권한도 이름만 전달하고 있었다. `attributePermissions`에 원문의 `exposed`를 전달해 구매행의 명시적인 true만 수정 권한으로 읽는다. 검색행의 true나 노출 구분 없는 과거 권한으로 기존 구매행의 입력을 열지 않는다. 새 세션에서는 최신 조회로 권한을 갱신한다. 권한·조회 원문은 저장 문서와 수정 의도에 포함하지 않는다.

판매용 내부 상품·연결·비교 계층을 다시 도입하지 않았다. 작업본 저장·전송 계약과 수정 의도 schemaVersion 4, V1~V48과 역사적 지원 코드는 유지했다. 데이터 전환·초기화는 필요하지 않다. [작업본 계약](../coupang-api/working-copies.md)과 [검증 안내](../testing.md)를 갱신했다.
