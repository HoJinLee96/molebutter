# 쿠팡 상품·작업본 통합 검증 — 2026-10-15

판매용 내부 상품·연결·기준값·비교 계층을 제거하고 쿠팡 등록상품과 작업본으로 통합했다. 상품업무·매입·보유 재고는 보존했다. 아래 검증은 모의 API, 격리 DB와 실제 로컬 DB 전환을 구분한다. 실제 쿠팡 쓰기와 공용 R2 삭제는 실행하지 않았다.

## 적용된 동작

- `/coupang`은 쿠팡 등록상품이 기본이고 임시 저장이 보조 탭이다. 신규·기존 상품 주소는 유지하며 재진입은 `/coupang/working-copies/{id}/edit`이다. 이전 drafts·연결·비교 API와 화면은 제거했다.
- 쿠팡 입력 폼 하나와 작업본 계약을 사용한다. 첫 임시 저장 때 생성하며, 등록상품은 계정·등록상품 ID로 작업본을 재사용한다. 임시 저장은 외부 전송을 실행하지 않는다.
- 전송 직전 최신 GET 원문에 사용자 수정 항목만 반영한다. 사용자 가격 130000은 외부 가격이 150000으로 바뀌어도 유지하며, 미수정 상품명·배송·옵션·알 수 없는 원문 필드는 최신 값을 유지한다. 가격·재고·정상가는 옵션 전용 PUT이다.
- 계정·revision·상품·옵션 ID·권한·수정 가능 상태, 실행 임대·중복 방지·부분 성공·UNKNOWN 보호를 유지한다. 실패·세션 만료·재진입 때 입력을 복구하며 쿠팡 반영은 미리보기와 명시적 확인을 거친다.

모의 API는 신규 등록·승인, 상품 PUT, 옵션 가격·재고, 이미지·상세설명·배송, 외부 값 변경, 알 수 없는 원문 필드, 옵션 ID 보완·변경, 계정 누락, 전송 실패·부분 성공·UNKNOWN 결과 확인을 검사했다. 저장 전 작업본 미생성, canonical 작업본 재사용, 로컬 revision 충돌·만료·조회 실패 입력 보존도 검사했다. 입력창 Enter는 쓰기를 실행하지 않고 버튼 Enter·Space는 실행하며, 줄바꿈·한글 조합·실패 후 입력을 보존한다.

데이터가 있는 V46→V47 검사는 수정 의도 우선 복원, 미연결 초안의 신규 등록 전환·계정 귀속 보고, authoritative 쿠팡 원문 우선, 채널 null 판독, 옵션·이미지 UUID·공개 토큰·연결 세대·감사 원문·전송 증거 동일성, 활성 임대 등 중단 조건과 반복 적용을 확인했다. GET과 PUT 사이의 외부 변경을 원자적으로 막는 기능은 보장하지 않는다.

## 실제 로컬 DB 전환

앱·워커 중지 → 전체 DB·판매 파일 백업의 격리 복원 → 사전 검사·V47 → 전후 대조 순서로 실행했다. 백업은 `backups/coupang-working-copy-20261015-v47/`에 있고 `UPGRADE_COMPLETE`를 기록했다. 덤프는 413124415바이트이며 복구용 이전 JAR은 `backups/coupang-working-copy-before-20261015/app-before.jar`에 보존했다. 백업에는 실제 DB 자료가 있으므로 공개 산출물에 포함하지 않는다.

- 보존 대상 37개 테이블, 90508행의 행 수와 값 지문이 동일했다. 상품 579개, 보유 재고 항목 54개, 재고 이동 55개, 매입 19개, 회원 2개가 포함된다.
- 전환 직전 판매 상품·주문·이미지·전송 이력은 비어 있었고 주문 계정 잠금 1행은 그대로 보존했다. 계정 미지정 초안은 0개였다. 기존 입력이 있는 변환은 위 합성 DB 검사 결과로 구분한다.
- 현재 쿠팡 테이블 27개, `legacy_coupang_*` 감사 테이블 8개다. 실제 DB 전체 FK 81개에서 고아 행 0개를 확인했다. 감사 자료의 이미지 참조는 자동 정리와 초기화에서 보호한다. 이전 실행 전문·해시·중복 방지 키는 변경하지 않는다. 실제 유지보수 명령 재실행도 이미 적용됨을 확인하고 데이터·파일 변경 없이 종료했다.
- V1~V46·역사적 SalesSchema와 상품업무 등 보호 소스 363개, 쿠팡 SOURCE·원문·자산 1791개의 SHA-256 동일성을 확인했다. 적용된 V47 소스의 SHA-256은 `ac01909803bce44d76b269a9a6507047b89cbaf61b9e49a39c39347d1f36265b`다.

최종 JAR `molebutter-app/target/molebutter-0.0.1-SNAPSHOT.jar`로 8081 포트에서 재기동했다. 로그인·CSRF·작업본 JS/CSS의 HTTP 응답, 작업본 API 인증, 존재하지 않는 공개 이미지의 인증 없는 404, 제거된 공통 편집기 자원의 404를 확인했다. 최종 JAR SHA-256은 `8c93eecc80417d2253dc1444c599c8bbd4ce7d672b6b5fde3dabab43e0d8e2f0`이다.
