# 쿠팡 전용 전환 검증 — 2026-10-15

## 적용 결과

판매 연동을 쿠팡 전용으로 변경했다. 다른 판매 마켓의 네 Maven 모듈·의존성·컨트롤러·DTO·설정 참조·화면·JS·CSS·전용 테스트·자료·도구를 제거했다. 네이버 공개 검색과 매입처 조회 코드는 보존한다. 쿠팡 공식 자료 1,791개와 기존 Flyway 파일 44개는 전환 전 SHA-256/HEAD 내용 대조에서 변경·누락이 없었다.

초안은 단일 `configuration`, 편집·전송은 단일 `target`, 주문 수집은 단일 `result`를 사용한다. 주문 조회·수집의 마켓 선택 인자를 제거했고 상세는 `/api/marketplace-orders/{orderId}/detail`이다. 이전 `selectedMarkets`·`markets`·`targets` JSON은 명시적으로 거절한다.

쿠팡 옵션 UUID·외부 ID 연결, 내부 기준값과 현재 쿠팡 값의 비교·선택 반영, 이미지 상속·상세설명·CDN 픽셀 지문, 계정·revision·연결 세대 보호, 임시 저장·재진입·전송 확인·중복 방지·UNKNOWN 복구를 유지한다. WebP 디코딩은 쿠팡 CDN 이미지 비교에 필요하므로 유지한다.

## 실제 로컬 DB·파일 전환

앱이 정지된 상태에서 전체 DB를 백업하고 별도 MySQL에 복원하여 모든 테이블의 행 지문을 대조했다. 판매 이미지 위치를 확인한 뒤 전용 디렉터리를 백업으로 이동하고 명시적 32개 판매 테이블을 FK 자식부터 트랜잭션으로 초기화했다. 쿠팡 데이터도 초기화 대상이다.

- 실제 백업: `backups/sales-reset-20261015-coupang-only/` (약 409 MiB).
- 전체 DB 덤프: `database.sql` 422,485,192 bytes. 백업 디렉터리 권한 700, 덤프 권한 600.
- 기존 이미지 경로: `molebutter-app/data/marketplace-assets`. 백업의 `marketplace-assets`에 보관했다.
- 복원 확인: `verified-before.txt`. 초기화 완료: `RESET_COMPLETE`.
- V45를 앱·워커 없이 유지보수 진입점으로 적용했다. 적용 전 판매 데이터가 남아 있으면 V45가 중단하며 자동 삭제하지 않는다.
- V45 직후 감사: 판매 테이블 32개가 모두 비어 있고, Flyway 이력을 제외한 보존 테이블 37개의 모든 행 값이 백업 전과 동일했다. `MIGRATION_VERIFIED`에 기록했다.
- 첫 재기동 후 다시 정지하여 대조했을 때도 보존 테이블 지문은 동일했다. 판매 상태 조회에서는 상품·초안·주문·클레임·연결·편집·전송·이미지·이력 등 31개 테이블이 0행이고, 주문 스케줄러가 만든 `marketplace_order_account_lock`만 1행이었다. 이 행은 주문 데이터가 없는 계정 동시 실행 잠금 메타데이터다. 엄격한 `--audit`는 이 행도 거절하므로 마이그레이션 직후·재기동 전 실행한다. 재기동 후 업무 데이터 확인에는 `--status`를 사용한다.

회원·권한·근태·내부 상품·매입처·매입 및 보유 재고·이동 이력·가격조회 데이터가 보존됐다. 공유 R2 객체, 매입 브라우저 프로필과 Redis 전체를 삭제하지 않았다. 브라우저는 각 탭의 판매 전용 sessionStorage와 localStorage만 한 번 정리한다. 인증·매입·재고 저장 키를 보존하는 회귀 검사를 포함했다.

최종 JAR은 14:53 KST에 기존 설정으로 8081에서 재기동했다. 실제 쿠팡 상품 재조회·가져오기·주문 재수집은 실행하지 않았다. 실제 쿠팡 등록·수정·이미지 쓰기도 수행하지 않았다. 비밀 파일을 직접 열거나 수정하지 않았다.
