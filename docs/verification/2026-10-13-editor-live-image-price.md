# WCWA705R2 실제 이미지·가격·브랜드 검증

검증일: 2026-10-13. 실제 마켓의 상품 등록·수정·이미지 업로드는 실행하지 않았다. 기존 운영 서버를 재시작하지 않았다.

## 실제 브라우저와 저장 데이터

- 로그인된 Chrome의 공통 상품 `897779631605467192`에서 기존 대표 이미지의 편집을 열었다. 원본 750×962px, 기존 범위 x=41, y=186, 너비·높이=669가 복원됐다.
- 범위를 바꾸지 않고 확인한 후 **공통 기준 저장**을 눌렀다. ‘임시 저장 완료’와 revision 4→5를 확인했다. 이미지 UUID `a3118c75-cda6-4c06-bf5f-70473c323336`은 유지하고 편집 자산만 `dfa9654c-c923-4f67-aa9a-e63b510e414d`로 교체됐다. 기존 다른 입력·전송 기록은 유지했다.
- 새로고침 후 쿠팡 탭에서 대표 이미지 상속을 확인하고 **입력 검증**을 눌렀다. 실제 화면에 쿠팡 검증 완료, 대표 669×669px/401,280바이트 적합, 상세설명 750×962px/88,040바이트 적합이 표시됐다.
- 새 편집본 공개 URL의 비인증 GET은 HTTP 200/image/png였다. 응답 SHA-256은 서버 보관 파일과 같았다. R2 원본은 변경하지 않았다.
- 스마트스토어 탭을 처음 클릭해 최신 상품을 조회했다. 사용자가 외부에서 수정한 판매가 128,000원, 즉시할인 41,000원이 그대로 표시됐다. 이 탭에서 저장·전송은 누르지 않았다.

## 확인한 문제와 수정

1. 공통 탭의 저장 버튼은 여러 마켓 선택 시 단일 전송 대상을 정하지 못해 비활성화됐다. 공통 탭에서는 저장 대상 선택 창을 열고 해당 마켓 탭으로 이동하여 확인하도록 연결했다. 이 선택만으로 전송 준비·이미지 업로드·상품 저장을 실행하지 않는다. 쿠팡·스마트스토어 탭은 각각 ‘쿠팡에 저장’, ‘스마트스토어에 저장’으로 표시한다. 외부 쓰기는 기존 한 마켓 확인·실행 절차를 유지한다.
2. 공통 네이버 가격 계산은 브라우저에서 정상가를 반영했지만 Java 투영은 이전 최소 판매가 계산으로 덮어썼다. 기존 실제 실행 전문에도 판매가 87,000원, 할인 41,000원, 추가금 0원이 기록돼 있었다. 서버도 브라우저와 동일하게 정상가 최댓값/현재 네이버 판매가 중 큰 값과 수동 할인으로 추가금을 계산하도록 수정했다. 같은 운영 초안을 메모리에서 계산하면 판매가 128,000원, 할인 41,000원, 추가금 0원이 된다. 실제 마켓에 다시 전송하지 않았다.
3. 저장 브랜드는 메모리 검색 이력 만료·재시작 시 전송 준비에서 거절됐다. 캐시가 없으면 쿠팡에서 저장된 ID·이름을 정확히 다시 확인하도록 수정했다. 새 프로세스의 빈 캐시에서 실제 브랜드 검색으로 `KR-41013`/`닥스` 확인에 성공했다. 이 재조회는 쿠팡 전송 세션 잠금 밖에서 수행하여 중첩 잠금 BUSY를 피하고 기존 요청 간격을 유지한다. 확인 실패 시 임의 브랜드를 허용하지 않는다.
4. 다른 탭으로 이동할 때 이전 마켓의 검증 완료 표시가 남았다. 탭 전환 시 표시·응답 세대를 무효화하도록 수정했다.
