# 쿠팡 저장 후 판매 승인 요청 — 2026-10-14

## 적용 결과

공통·단독 등록·수정의 통합 화면에서 쿠팡 승인 선택 체크박스를 제거했다. 쿠팡 탭의 `쿠팡에 저장`과 기존 전송 확인 절차를 사용하면 서버가 저장 후 판매 승인을 순차적으로 요청한다. 임시 저장은 내부 초안만 보관한다.

1. 신규 상품은 CREATE POST, 승인 필요 상품 변경은 PRODUCT PUT을 `requested=false`로 보낸다.
2. 저장 성공 후 서버가 보관한 등록상품 ID로 빈 본문의 APPROVAL PUT을 보낸다.
3. 상품·옵션 연결과 실제 승인 상태를 조회하여 전체 실행의 완료 여부를 판정한다. 승인 요청 접수만으로 승인완료를 표시하지 않는다.

승인이 필요 없는 가격·재고·배송 전용 변경에는 승인 요청을 추가하지 않는다. 변경이 없는 준비 결과에 불필요한 쓰기를 만들지 않는다. 새로 준비하는 실행에만 적용하며 이미 보관한 실행·준비 스냅샷의 요청 의미는 유지한다.

## 서버 기록과 복구

- CREATE/PRODUCT와 APPROVAL을 서로 다른 영속 단계로 보관한다. 저장 응답 성공 후 승인 단계가 남아 있으면 전체 실행과 적용 revision을 완료 처리하지 않는다.
- 생성 응답의 상품 ID를 연결에 보관하고 그 ID로 승인한다. 승인 응답에 다른 상품 ID가 오면 결과 미확인이다.
- 실행 직전 최신 조회로 다시 구성한 실제 저장 요청을 승인 단계의 검증 기준으로 전달한다. 이전 미리보기 값으로 덮어쓰거나 검증하지 않는다.
- 승인만 명시적으로 실패하면 실패 단계 재시도는 승인 PUT만 보낸다. 생성 POST나 이미 성공한 수정은 반복하지 않는다.
- 승인 응답 유실은 UNKNOWN으로 보관하고 결과 확인 시 GET만 수행한다. 확인되지 않은 승인을 자동 재전송하지 않는다.
- 쿠팡이 상품 등록·수정 처리 중이라는 400 응답을 반환하면 최소 10분 후 승인 단계만 재시도하도록 안내한다. 기존 호출 간격·계정 잠금·명시적 429 정책을 유지한다.
- 원격 응답의 연락처·인증값·원문은 공개 결과에 포함하지 않는다. 기존 서버 전용 요청 스냅샷 보호를 유지한다.

## 계약 근거

프로젝트 최신 문서의 쿠팡 OVERVIEW·INDEX·승인 요청/생성/수정 SOURCE, 승인 상태 FAQ·KNOWN-ISSUES를 확인했다. [공식 승인 API](https://developers.coupang.com/ko/api/products/request-for-product-approval)도 2026-10-14에 다시 확인했다.

- 전체 경로: `PUT /v2/providers/seller_api/apis/api/v1/marketplace/seller-products/{sellerProductId}/approvals`.
- 공식 규격은 생성·수정에 `requested=true`를 보내면 자동 승인 요청한다고도 명시한다. 이번 변경은 사용자가 요청한 별도 두 단계 실행을 적용한다.
- 승인 가능 상태에 관해서 본문/FAQ의 임시저장 설명과 오류 표의 승인완료·승인반려·부분승인완료 안내가 상충한다. 상태 제한을 임의로 확정하지 않고 실제 업무 거절을 실패로 보관한다. 처리 중 400은 공식 최소 10분 재시도 안내를 따른다.

- 실행 JAR 빌드 및 수정된 HTML·JS·서버 클래스의 패키지 일치 확인, `git diff --check` 통과. 비밀 파일은 패키지에 포함되지 않는다.

이번 검증에서 실제 쿠팡·다른 마켓 상품 등록·수정·승인 요청이나 운영 DB 변경은 실행하지 않았다. 서버는 재시작하지 않았다. 실제 두 요청의 계정별 처리 결과와 승인 소요 시간은 재시작 후 사용자 저장 실행에서 확인해야 한다.
