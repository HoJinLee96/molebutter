# 쇼핑윈도 대표 재고 조회와 개별 조회

## 조회 정책

신규 최신화의 `selection_snapshot.stockPolicy=STORE_REPRESENTATIVE`부터 적용한다. 검색의 `chnlSeq`와 캐시 채널 번호, 매장·쇼핑윈도 구분을 보존하고 실제 상세 응답의 `channel.id`·매장·WINDOW 유형과 대조한다. 근거가 부족하면 종전처럼 개별 조회한다. 숫자 채널 ID와 기존 `channelUid`는 별개다.

상품별 이번 조회에서 가격순으로 구매 가능한 양수 재고를 확보하면 같은 검증된 채널·매장의 나머지는 `SKIPPED_SAME_STORE`로 저장한다. 현재 선정 글은 먼저 확인하고, 더 저렴한 대안은 별도 확인한다. 품절·미확인·실패로는 생략하지 않는다. 실행별 동일 상품 상세 캐시는 재사용하되 다른 상품의 대표 글 확보 여부는 공유하지 않는다.

생략한 글은 옵션·재고 확인 시각이 없으며 다른 글의 수량·모델명을 복사하지 않는다. 사진·가격·배송비·URL은 개별 글의 검색 결과를 유지한다. 생략만으로 실패/재고 미확인 건수나 부분 확인 상태를 늘리지 않는다. 비선호 추천의 가격차 1,000원, 일반 판매자 제외, 추가 요청 40건 기준을 유지한다.

## 개별 조회

- `POST /api/products/{product}/suppliers/{supplier}/stock-lookups`: `{revision, supplierRevision}`로 접수. 동일 판매글의 진행 중 요청은 기존 작업을 반환한다.
- `GET .../stock-lookups/{job}`: 상태, 버전, 메시지, 공통 차단 여부 조회.
- `DELETE .../stock-lookups/{job}`: `{revision}`으로 취소. 이미 전송된 요청은 결과 반영만 막는다.
- `POST .../stock-lookups/{job}/resume`: `{revision}`으로 접속 제한 해제. 취소된 작업은 다시 실행하지 않는다.

관리자·상품 담당자에게 허용한다. 모든 변경 API는 CSRF와 최신 계정 상태를 검사한다. 요청에 URL이나 응답을 받지 않고 저장된 판매글을 조회한다. 아직 직접 확인하지 않은 글은 선정할 수 없다. 정상 응답으로 실제 매장을 확인했으나 수량을 제공하지 않는 경우에는 기존 선정 조건을 적용한다. 조회 성공 자체가 선정을 바꾸지는 않는다.

## 워커·저장

`V18__supplier_stock_lookups.sql`의 MySQL 대기열과 기존 `product_settings` 워커 임대를 함께 사용한다. 현재 상품 처리 완료 후 개별 조회를 FIFO로 우선 처리하고 자동 최신화를 계속한다. 개별 조회는 검색을 실행하거나 검색 완료 후 30초 대기를 갱신하지 않는다.

트랜잭션은 READ COMMITTED로 실행하고 기존 공통 잠금 이후 대기열을 읽는다. MySQL 기본 반복 읽기의 과거 스냅샷 때문에 동시 접수에서 기존 작업을 놓치지 않도록 한다. 활성 판매글 고유 제약도 적용한다. HTTP 통신은 트랜잭션 밖에서 수행하고, 완료 시 소유권·대상 버전·선정 기준·선호/매장 변경·권한을 다시 확인한다. 임대 만료 후 재처리는 가능하지만 늦게 도착한 이전 워커 결과와 중복 이력 저장은 차단한다.

일시중단·로그인 대기·접속 제한에서는 대기열을 실행하지 않는다. 개별 조회에서 생긴 제한은 공통 차단으로 남으며 취소나 새 작업으로 우회할 수 없다. 상품 상세 또는 최신화 작업 화면에서 명시적으로 해제한다. 삭제되거나 기준이 달라진 작업은 재실행하지 않고 차단만 해제한다.

개별 결과는 판매글 관측과 상품 현재 요약에 반영하되 검색 가격·가격 시각은 유지한다. 기존 작업 결과와 조회 이력은 수정하지 않고 개별 조회 이력과 감사 기록을 추가한다. 자동 캐시에서는 해당 상세 항목을 무효화한다. 개별 완료 알림은 쌓지 않는다.

## 전환과 검증

서버 적용 전 기존 진행·중단 작업은 완료 또는 취소한다. 이전 `stockPolicy`가 없는 작업은 자동 실행/수동 재개를 거부한다. 과거 선정·선호·가격·조회 이력은 유지한다.

- 실제 목동점 두 응답을 정제한 자료: `src/test/resources/product/supplier-group`.
- `SupplierGroupStockTest`: 2→1 요청, 실제 25/13개 수량, 선정 글과 저렴한 대안, 실패/품절/누락·채널 충돌, 상품 간 분리, 추천 상한.
- `ProductFlowIT`의 `stockQueue*`: 임시 MySQL 동시 접수·점유 회복·취소·기준 변경·전역 차단·권한·CSRF·JSON/이력 보존.
- `MigrationUpgradeIT`: 빈 DB 및 기존 DB의 V18 전환.
- 큐 상태·취소·재개·중복 처리는 Java 회귀 테스트로 검증하고, 대표 상품 최신화 UI는 [테스트 안내](testing.md)를 따른다.

테스트는 실제 네이버에 반복 접속 제한을 발생시키지 않는다.
