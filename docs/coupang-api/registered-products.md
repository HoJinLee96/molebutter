# 쿠팡 등록상품 저장소

화면은 `/coupang/products`다. 이전 `/coupang` 목록 주소는 제공하지 않는다. API는 `/api/coupang/products` 아래에 있으며 상품업무·매입·보유 재고와 별개다.

## 검색과 표시

기본 정렬은 쿠팡 응답의 `createdAt`(등록일) 최신순이다. 목록 API의 `sort=CREATED_DESC|CREATED_ASC`로 최신순·오래된순을 선택한다. 등록일 미확인(null·빈 값)은 두 방향 모두 맨 뒤에 표시하며, 같은 등록일은 내부 상품 ID 내림차순·옵션 식별자 오름차순으로 고정한다. 페이지당 보기 옆 정렬 선택은 즉시 첫 페이지를 조회하고 체크 선택·펼침을 해제한다. 검색·카드·초기화는 정렬을 유지하며 수정 화면에서 돌아올 때도 복원한다. DB 조회만 사용하고 수집·갱신 시각은 정렬에 사용하지 않는다.

DB에서 옵션당 한 행을 조회한다. ID는 등록상품 ID·노출상품 ID·옵션 ID·업체상품옵션 ID의 정확한 일치, 브랜드는 선택, 등록상품명·판매자상품코드는 부분 일치다. 재고와 출고소요일의 `LE`/`GE`/`EQ`는 각각 이하/이상/일치다. 같은 옵션에 모든 조건을 적용한다. 판매상태는 `ON_SALE`/`STOPPED`/`UNVERIFIED`다. 미수집값은 0으로 간주하지 않는다.

선택은 현재 페이지의 등록상품에 한정한다. 갱신으로 사라진 상품은 내부 선택에서도 제거하고 검색·페이지·페이지 크기 변경은 선택을 초기화한다. 선택 갱신과 일괄 가격·재고 변경은 실행 직전에 현재 행과 실제 체크박스를 대조한다. 선택 갱신의 빈 대상은 전체 가져오기로 바꾸지 않는다. 일괄 처리의 성공·변경 없음 항목은 선택 해제하며 실패·미확인 전송의 복구 자료는 보존한다.

일괄 재진입은 현재 선택과 같은 상품·옵션의 저장 입력만 복원한다. 선택 밖 미완료 전송은 대상 코드·옵션 ID를 표시한 ‘이전 전송 결과 확인’으로 분리한다. 복구 화면은 해당 전송만 표시하며 신규 `/prepare` 없이 기존 준비 ID·중복 방지 키·실행 ID로 복구한다. 과거 미전송 행은 함께 실행하지 않는다. 계정·revision·관측·선정 근거와 `UNKNOWN`·`ACCEPTED` 보호는 유지한다.

표는 선택, 이미지, 판매자상품코드, 노출상품 ID, 옵션 ID, 등록상품명, 구매속성, 현재가격, 재고, 판매상태, 출고소요일, 수정 순서다. 체크 선택은 기존처럼 등록상품 단위이며 판매자상품코드는 볼드 펼침 버튼이다. 썸네일은 같은 옵션의 유효한 HTTPS 대표이미지, 첫 유효 이미지 순으로 선택하며 없거나 로드에 실패하면 사진 없음을 표시한다. 다른 옵션 이미지로 대체하지 않는다. `productCount`는 상품 수, `totalElements`는 옵션 행 수다. 상세 미수집 상품도 옵션 미확인 행으로 나타난다. 브랜드 선택지는 DB에서 읽는다. 일반 목록·상세·검색·페이지 이동은 쿠팡을 호출하지 않는다.

페이지 신규 진입의 기본 카드는 판매중이며 판매상태 ON_SALE·재고 GE 1로 조회한다. 수정 화면에서 돌아오는 경우에는 저장된 카드·검색 조건을 우선 복원한다. 상단 상태 카드는 옵션 행 기준이다. `group=ALL|RECOMMENDED|SELLING|SOLD_OUT|STOPPED`는 기존 검색 조건과 같은 옵션에 적용한다. 상품은 삭제되지 않은 모든 행, 판매중은 판매 중이고 재고 1 이상, 품절은 판매 중이고 재고 0, 판매중지는 재고와 무관하게 판매 중지인 행이다. 삭제 카드는 `deleted=true&group=ALL`을 쓴다. 옵션이 없는 상품은 미확인 행 하나다. `counts.all/recommended/selling/soldOut/stopped/deleted`는 현재 계정 전체 DB의 건수이며 검색·페이지의 영향을 받지 않는다.

카드 선택은 판매상태·재고 조건을 카드 기본값으로 채우고 다른 검색 조건은 유지하며 첫 페이지로 조회한다. 판매중은 ON_SALE·재고 GE 1, 품절은 ON_SALE·재고 EQ 0, 판매중지는 STOPPED·재고 없음, 상품/삭제는 판매상태·재고 없음이다. 수동 검색에서도 이 조합과 정확히 일치하면 상태 카드를 선택하며 브랜드·상품명 등 추가 조건은 판정에 영향을 주지 않는다. 재고 GE 10이나 판매중지+재고 같은 다른 조합은 상품 카드를 사용하고 숨은 이전 카드 조건을 적용하지 않는다. 카드가 자동으로 채운 재고를 수정하지 않은 채 판매상태를 바꾸면 새 상태 기본값으로 교체하고 사용자 재고 입력은 보존한다. 삭제 범위의 수동 검색은 삭제 카드를 유지한다. 초기화는 카드 기본 조건만 남기고 페이지 크기는 유지한다. 검색·카드·초기화는 체크와 펼침을 해제하며 입력 수정만으로 조회하지 않는다. 수정 화면으로 이동하기 전에 카드·검색·페이지 크기·페이지·스크롤·조회에 적용한 자동 조건의 출처를 세션에 보관하고 목록 복귀 시 복원한다. 목록에서는 확인 시각 보조 문구를 생략하고 상세의 저장·반영 상태와 이력에서 확인한다.

## 추천 카드

카드는 상품 → 추천 → 판매중 → 품절 → 판매중지 → 삭제 순서다. 신규 진입은 판매중을 유지한다. 추천은 삭제되지 않은 판매 중 옵션만 대상으로 하며 재고 0도 포함한다. 가격 인하(현재 가격 > 최종 제안 가격), 역마진(현재 가격 기준 이익 < 0), 재고 보충(쿠팡 재고 0이고 정상 확인 구매 가능 매입처 옵션 재고 > 0) 중 하나 이상이면 옵션당 한 번 집계한다. 손익분기 0과 양의 이익이지만 목표 마진에 미달하는 경우만으로는 역마진 추천하지 않는다.

선정 근거는 앞뒤 공백 제거·대문자 변환 후 전체 코드가 정확히 일치하는 활성 내부 상품이 하나일 때만 사용한다. 삭제·병합·중복 코드와 선정 판매글 미발견, 매장 충돌, 조회 기준 변경, 지원하지 않는 채널은 제외한다. 동일 선정 판매글의 마지막 정상 확인 가격은 허용하고 이전 사입가 여부·확인 시각은 변경값의 툴팁과 접근성 설명에 보존한다. 가격 계산은 공통 배송비·수수료율·마진율과 서버 계산기의 천 원 버림·만 원 경계 차감을 사용한다. 매입처 표시 배송비나 보유 재고를 합산하지 않는다. 역마진 부호는 반올림 전 정확한 이익 분자로 판정한다.

재고 보충은 동일 선정 판매글의 최신 정상 확인값을 사용하고, 없으면 마지막 정상 확인값을 사용한다. 조회 대기·진행 중·실패 상태만으로 이전 정상 재고를 제외하지 않는다. 구매 가능·양의 수량인 옵션만 후보로 삼고 구매 불가·수량 미확인·0은 제외한다. 이전값 여부와 확인 시각을 표시한다. 다중 옵션 중 하나라도 해당하면 포함하되 전체 옵션 수를 보존하며 합산하거나 쿠팡 옵션과 자동 대응하지 않는다. 가격과 재고 근거를 독립 판정하므로 가격 미확인이어도 재고 보충은 가능하다.

목록 응답 `recommendation`에는 `reasons`(PRICE_HIGH/NEGATIVE_MARGIN/RESTOCK/MARK_SOLD_OUT/OWNED_STOCK_MISMATCH), `internalProductId`, `suggestedPrice`, 현재 가격 기준 `profit`/`marginPercent`, 정상 확인 구매 가능 `stocks`, 전체 `stockOptionCount`, `previousPrice`/`priceCheckedAt`, `suggestedLoss`가 포함된다. 모든 카드의 구매속성 다음 추천 사유 열에 표시하며 해당 사유가 있는 가격·재고 칸만 ‘현재값 → 변경값 [수정]’ 한 줄로 보여준다. 가격 인하·역마진은 가격 수정, 재고 보충은 재고 수정만 표시하고 관계없는 항목은 현재값만 남긴다. ‘제안’·‘이전 가격’ 문구는 생략하고 변경값을 강조하며 28px 수정 버튼으로 기존 모달을 연다. 동일값은 중복 화살표를 생략하고 역마진의 직접 조정과 설정 검토 안내는 유지한다. 다중 옵션은 ‘0개 → 옵션 선택 [수정]’으로 표시하고 모달에서 구매 상태·수량을 보고 선택한다. 빠른 수정 응답의 기존 `stocks`는 유효 수량 후보를 유지하며 `stockOptions`는 수량 미확인(null) 옵션까지 구분한다. 미확인 옵션 선택은 변경 수량을 비워 두고 0으로 변환하지 않는다. 제안 가격에서도 손실이면 설정 검토와 직접 조정을 안내하며 가격을 임의로 올리지 않는다.

추천 클릭은 판매상태 ON_SALE·재고 조건 없음으로 채우고 다른 검색·페이지 크기·정렬을 유지한다. 추천 안의 검색·초기화는 RECOMMENDED와 선택한 유형을 유지한다. 추천 카드 아래의 전체·가격 인하·역마진·재고 보충·품절 전환·보유 재고 맞춤 중 하나를 선택한다. 유형 변경은 기존 검색·크기·정렬을 유지해 첫 페이지를 조회하고 체크·펼침을 해제한다. 다른 카드에서는 유형을 숨기고 필터를 보내지 않으며 추천으로 돌아오거나 편집기에서 복귀하면 마지막 유형을 복원한다. 다른 카드 클릭 시 해당 카드의 기존 동작을 사용한다. 선정 변경·빠른 수정 반영 완료·목록 재조회마다 다시 판정하며 사라진 마지막 페이지는 마지막 유효 페이지로 이동한다. 근거 조회 실패 시 오류와 직전 성공 목록·유형 선택·집계를 유지한다.

목록 API는 `reason=ALL|PRICE_HIGH|NEGATIVE_MARGIN|RESTOCK|MARK_SOLD_OUT|OWNED_STOCK_MISMATCH`을 받으며 기본은 ALL이다. ALL 외 유형은 `group=RECOMMENDED`에서만 허용한다. `counts.recommendationReasons.priceHigh/negativeMargin/restock/markSoldOut/ownedStockMismatch`은 검색·선택 유형과 무관한 현재 계정 전체 건수다. 유형별로 복수 사유의 같은 옵션이 포함될 수 있으며 전체 `counts.recommended`는 옵션을 한 번만 센다. 추천 판정 후 검색·유형 필터·정렬·페이징 순서로 처리하며 선택 유형에서도 모든 실제 추천 사유를 표시한다. 해결된 유형에서 행을 제거하고 다른 사유가 남으면 해당 유형과 전체 집계에는 유지한다.

서버는 읽기 전용 REPEATABLE_READ 트랜잭션에서 계정 전체의 가벼운 옵션 투영, 공통 설정과 코드별 매입 근거를 일괄 읽는다. 공개 `CoupangRecommendationSources` 포트와 앱 어댑터에서 매입 공개 `byCodes` 조회를 연결한다. 쿠팡 모듈에 매입 의존성은 없으며 검색·정렬 후 추천을 필터링하고 페이징한 현재 행만 상세를 읽는다. 카드 집계는 검색과 무관하다. 추천 조회는 DB만 사용하며 새 테이블·마이그레이션·영구 연결·주기 작업·자동 수정·일괄 전송을 만들지 않는다. 버튼 진입 후에는 기존 최신 문맥 확인과 단일 항목 저장·전송 보호를 사용한다.

## 선정 매입처 펼침

판매자상품코드를 누르면 해당 옵션 행 바로 아래에 읽기 전용 요약을 펼친다. 같은 버튼으로 닫으며 여러 옵션을 독립적으로 펼칠 수 있다. 정확한 전체 코드가 일치하는 활성 매입 상품을 모두 구분해 이미지·브랜드·코드·선정 매입처 가격·배송비·재고·조회 상태를 보여준다. 미선정·미일치·이전값·실패·선정 판매글 미발견을 구분하며 `/products`의 공통 요약 렌더러를 사용한다. 펼침의 상품코드·재고 상세는 현재 쿠팡 페이지의 공통 상품 모달을 연다. 펼침 자체는 DB 읽기만 수행하고 선정 변경 등의 작업은 공통 모달의 기존 권한과 명시적 버튼을 따른다.

`GET /api/products/by-code?code=...&page=0&size=20`은 상품 조회 공개 포트에서 DB만 읽는다. 앞뒤 공백 제거·대문자 변환 뒤 전체 코드를 비교하며 DB의 악센트 무시 정렬로 다른 코드가 합쳐지지 않도록 바이너리 비교한다. 브랜드로 제한하지 않고 삭제·병합 상품을 제외한다. ID 역순으로 20개씩 더 보기를 제공하며 다시 펼치면 새로 조회한다. 로딩·실패·재시도는 펼침 안에서 처리하고 닫거나 목록을 바꾼 뒤의 응답은 무시한다. 체크 변경만으로는 펼침과 조회 결과를 지우지 않는다.

펼치기·보유 재고 요약 조회는 영구 상품 연결이나 새 저장 구조를 만들지 않고 외부 매입처·쿠팡 API를 호출하지 않는다. 가격·수량 빠른 수정은 아래 별도 경로를 따른다.

## 수집과 원문

전체 가져오기는 무조건 목록 → 삭제 상태 목록 → 상세·옵션 판매값 → 누락 상품 개별 확인 순서다. 선택 갱신은 지정한 상품만 확인한다. 수집만으로 작업본을 만들지 않는다. 기본·상세·옵션 응답과 관측 순서, 시각, 오류를 보관한다. 상세 등록 가격·수량은 현재 판매값과 분리한다. 실패하면 마지막 성공값을 보존한다. 오래된 응답은 최신값을 덮어쓰지 않는다.

작업은 DB에 체크포인트를 저장하고 취소·재개·실패 재시도를 제공한다. 앱 중단 시 임대가 만료된 작업은 INTERRUPTED가 되며 사용자가 재개한다. 완료한 상세 항목은 재개에서 반복하지 않는다. 호출 제한·인증 오류는 작업을 일시 중단한다. 자동 정기 수집은 없다.

전체 가져오기·선택 갱신 현황은 상품 카드 아래에 표시한다. 기존 `collections/latest`·`collections/{id}`의 DB 상태를 읽어 목록·삭제 목록·상세/가격/재고·누락 상품 확인 단계, 발견·처리·성공·실패 건수와 갱신 시각을 보여준다. `completed`는 성공 상품 수이고 처리 수는 `completed+failed`다. 옵션 수나 외부 API 호출 수가 아닌 등록상품 단위 집계다. 전체 목록 확인 중에는 총건수가 확정되지 않았으므로 진행률은 미정으로 표시한다. 이후 진행률은 현재 발견 건수 중 처리 비율이며 누락 상품 확인 시 대상이 늘어날 수 있음을 안내한다.

활성 작업은 1.5초 간격으로 상태만 조회하고 새로고침·재진입 시 최근 작업을 복원한다. 완료·일부 실패·취소·중단 후에도 마지막 결과를 표시한다. 현황 조회 실패 시 기존 단계·건수는 유지하고 패널 내 오류·현황 다시 조회를 제공한다. 활성 작업의 조회 실패는 5초 뒤 DB 상태를 다시 확인하며 수집 시작 POST를 자동 반복하지 않는다. 취소·재개·새 작업 뒤 늦게 온 이전 상태 응답과 페이지 이탈 후 응답은 반영하지 않는다. 기존 명시적 수집·취소·재개와 중복 실행 잠금은 유지한다. 이 화면 표시로 쿠팡 호출·DB 쓰기·마이그레이션을 추가하지 않는다.

종료·취소·중단 상태의 현황에는 닫기 버튼을 제공한다. 닫기는 서버 작업과 이력을 변경하지 않으며 같은 탭의 `sessionStorage`에 작업 ID·상태·갱신 시각을 기억해 새로고침·재진입에서도 같은 결과를 숨긴다. 다른 작업이나 상태·갱신 시각이 바뀐 결과는 표시한다. 새 수집·재개를 누르거나 진행 중 상태를 확인하면 숨김을 해제한다. 대기·진행 중 작업은 닫을 수 없으며 기존 취소 동작을 사용한다.

화면에는 고정 진행 문단 대신 처리 중인 버튼과 취소·재개·재시도 버튼을 표시한다. 완료·일부 실패·실패·취소·일시중지·중단 결과는 요청자의 기존 알림함에만 남긴다. 공개 `CoupangCollectionNotifications` 포트를 앱의 알림 어댑터로 연결하며 `COUPANG_COLLECTION_RESULT` 유형은 자동 토스트에서 제외한다. 알림에는 대상·완료·실패 수와 작업/실패 항목의 오류 코드를 포함한다. 작업의 결과 확정과 알림 저장은 같은 트랜잭션이다. 결과 상태·확정 시각을 포함한 이벤트 키로 중복을 방지하며 조회는 알림을 생성하지 않는다. 알림 저장 실패 시 결과도 롤백하고 임대 만료 뒤 중단 상태로 복구한다. 이 UI 변경에는 DB 마이그레이션을 추가하지 않는다.

현재값 변경과 원문 버전·이력은 같은 트랜잭션이다. 같은 응답은 변경 이력을 중복 생성하지 않고 조회 기록만 추가한다. 배열의 식별 가능한 행과 순서, 누락·null·알 수 없는 필드를 보존한다. 저장한 수정, 선택, 전송 요청·결과도 기록한다. 앱에서 관측하지 못한 외부 중간 변화와 미저장 키 입력은 이력이 아니다. 이력은 자동 삭제하지 않는다. 이력이 참조하는 로컬 이미지도 정리에서 보호한다.

## 수정 의도와 충돌

최초 수정의 기준값은 작업본의 행·필드 식별자로 별도 보관한다. 수집은 작업본을 덮어쓰지 않는다. 미수정 항목은 쿠팡값으로 갱신한다. 기준값과 최신 쿠팡값이 다르고 내 수정값도 다르면 충돌을 표시한다. 쿠팡값 사용은 해당 의도만 취소한다. 내 수정값 반영은 선택한 관측값을 확인값으로 보관하고 기존 미리보기·명시적 전송으로 이어진다. 선택 뒤 최신값이 바뀌면 다시 선택한다. 확인할 수 없는 값은 전송을 차단한다. 기존 작업본의 기준값이 없는 경우 추정하지 않는다. 기준값 없음으로 표시하고 사용자가 쿠팡값 사용 또는 내 수정값 반영을 명시적으로 선택해야 한다. 후자를 선택하면 확인한 현재값을 새 기준값으로 기록하고 재확인 이력을 남긴다.

UNKNOWN·ACCEPTED 실행은 결과 확인을 우선한다. 요청 접수와 조회 반영을 구분하고 성공한 단계의 의도만 제거한다. 새 미저장 입력을 보존한다. 수정 의도 schemaVersion 4와 역사적 실행 전문은 유지한다.

## 판매상태와 삭제

판매중지·재개는 옵션 전용 작업이며 판매중지 상품은 일반 목록에 남는다. 상품 전체 작업은 대상 옵션을 미리보기에 표시한다. 삭제는 필요한 판매중지 단계 뒤에 실행하고 일부 실패·미확인 단계가 있으면 진행하지 않는다. 저장된 수정이 있으면 먼저 반영하거나 취소해야 삭제를 준비할 수 있다.

명시적인 쿠팡 삭제 상태 또는 대상 ID가 일치하는 앱 삭제 성공 응답만 자동으로 삭제 목록으로 이동한다. 전체 목록 수집이 정상 완료됐고 개별 조회에서 명시적인 상품 데이터 부재를 확인한 경우는 삭제 확인 필요 후보로 둔다. 사용자가 직접 확정하거나 삭제 아님을 선택한다. 일반 HTTP 400·404·500, 인증·권한·호출 제한·네트워크 오류, 등록·수정 처리 중 응답은 삭제 근거가 아니다. 중단 수집·선택 갱신은 다른 상품의 삭제를 추정하지 않는다.

삭제 목록에서도 원문·옵션·작업본·이력·이미지 참조를 보존한다. 실제 존재가 다시 확인되면 일반 목록으로 복귀하며 근거를 기록한다. 로컬 삭제 확정은 쿠팡에 DELETE를 보내지 않는다.

## 전환

[V49 전환](../coupang-products-migration.md)을 먼저 적용하고 가격 계산 설정은 [V50 전환](../coupang-pricing-migration.md)을 따른다. 현재 매입 근거·추천 조회는 영구 연결 없이 공개 포트로 조립한다. 추천 표시·유형 필터에는 추가 마이그레이션이 없다. 로켓그로스 전송 확대는 포함하지 않으며 실제 API 호출 성공과 계정 권한은 모의 검증과 구분한다.

## 선정 매입처 상세와 옵션 빠른 수정

선정 매입처 펼침의 내부 상품코드는 같은 쿠팡 페이지에서 기존 상품 모달을 연다. 상품·쿠팡 화면은 `fragments/product-detail`과 `ProductDetailModal.mount`를 공유한다. 쿠팡 호스트의 선정 변경 후 갱신은 관련 펼침 행에만 적용하며 카드·체크·페이지를 유지한다. 이미지·상품코드·가격·재고·조회 상태는 위 쿠팡 옵션 행과 같은 열 너비를 사용한다. 재고 칸에는 매입처 수량과 실제 보유(`onHand`) 수량을 구분해 0개도 표시한다. 보유 재고는 기존 `/api/inventory/summaries`를 중복 ID 제거·100개 단위로 조회하며 미입고는 합산하지 않는다. 조회 실패는 0개로 바꾸지 않고 실패를 표시한다. `선정 매입처 · 사입 기준가`, `조회 중 - 이전 가격 및 재고` 안내는 제거하고 조회 상태와 필요한 실패·미발견 표시를 상태 열에 둔다.

가격수정·재고수정은 해당 `vendorItemId` 한 항목만 대상으로 한다. 진입은 기존 작업본 편집 조회를 사용한다. 빠른 수정의 저장 버튼은 옆에 표시한 변경 전후 값에 대한 저장·전송 확인이며, 내부적으로 기존 준비·실행 API를 순서대로 사용한다. 준비 후 값·관측 버전·대상 단계가 표시와 다르거나 충돌·검증 문제가 있으면 전송하지 않고 입력을 보존한 채 재확인을 요구한다. 같은 값은 저장·전송을 생략한다. 서버는 기존 작업본의 다른 의도를 보존하고 `prepareSelected`로 가격 또는 수량 하나를 준비한다. 이전 schemaVersion 4 전문은 수정하지 않으며 새 미리보기의 선택 의도에만 선택적 `quickEditBasis`를 보관한다. 성공한 해당 의도만 제거한다. 전체 편집기의 전송 경로는 전체 의도 일치 검증을 유지한다.

선정 매입처는 앱의 DB 조회 어댑터에서 읽고 영구 연결을 만들지 않는다. 출처 fingerprint와 가격 설정 revision은 미리보기 준비·실행 접수·실제 dispatch 직전에 확인한다. 값이 달라지면 입력을 보존하고 다시 확인한다. 쿠팡값 충돌 선택과 UNKNOWN·ACCEPTED 보호는 기존 실행을 재사용한다. 가격 변경은 10원 단위, 판매 가능 수량은 기존 0~99999 정수 범위를 유지하며 판매상태·실제 보유 재고는 자동 변경하지 않는다.

이전 정상 사입가도 계산에 사용할 수 있고 미확인 사입가는 직접 입력하거나 판매가격을 직접 입력한다. 매입처 재고는 최신 정상 확인값 또는 같은 선정 판매글의 마지막 정상 확인값을 제안한다. 이전 재고 후보는 확인 시각과 이전 조회 여부를 구분한다. 여러 옵션은 직접 선택하며 합산·자동 대응하지 않는다.

공통설정의 쿠팡 가격 계산 탭은 배송비(VAT 포함)·판매수수료율·희망 마진율을 관리한다. 수수료와 마진은 API에서 퍼센트 단위다. 판매가 역산은 `(사입가+배송비)/(1-1.1*(수수료율+마진율))`이며 원 단위 반올림 후 천 원 미만을 버리고 만 원 단위면 1,000원을 추가 차감한다. 사입가를 바꾸면 조정된 제안 가격을 판매가격에 자동 입력하며 이후 판매가격을 직접 수정할 수 있다. 사입가 아래에는 적용 설정을, 판매가격 아래에는 실제 이익·마진율을 표시하고 VAT 상세는 접을 수 있다. 매입처 표시 배송비는 계산 배송비에 자동 합산하지 않는다. [V50 전환](../coupang-pricing-migration.md)을 따른다.

빠른 수정의 실행 요청 전에 계정·상품·옵션·수정 종류로 구분한 sessionStorage에 준비 ID·중복 방지 키를 보관한다. 실행 응답 유실 시 새 준비를 만들지 않고 결과 확인 버튼으로 같은 준비 ID·키의 실행을 복구한다. 실행 ID를 받은 뒤에는 재진입 시 조회로 기존 결과를 복구한다. 요청 접수·결과 미확인·조회 반영 완료를 구분하고 성공한 해당 수정만 제거한다. 복구 정보를 보관하지 못하면 전송하지 않는다.

## 옵션 ID 외부 링크

쿠팡 옵션 ID(vendorItemId)는 공통 표시 헬퍼로 새 탭 링크를 제공한다. 노출상품 ID(productId)가 있으면 `https://www.coupang.com/vp/products/{productId}?vendorItemId={vendorItemId}`를 사용하며 noopener/noreferrer를 적용한다. 목록·상세·편집기·가격/재고 모달·주문/클레임의 표시 ID에 적용한다. 선택 상자의 옵션 선택 동작은 유지한다. 주문처럼 노출상품 ID가 없는 화면은 `GET /api/coupang/products/options/{vendorItemId}/open`에서 기존 ADMIN 권한·현재 계정으로 DB만 조회해 302 이동한다. 삭제/비활성 옵션의 보존 기록도 조회하되 노출상품 ID가 없거나 서로 다른 ID가 발견되면 안내 오류를 반환한다. 등록상품 ID나 옵션 ID를 노출상품 ID로 대체하지 않으며 쿠팡 API 호출·수집·저장 작업은 하지 않는다.

구매속성과 현재가격 사이의 **추천 사유** 열에 가격 인하·역마진·재고 보충을 표시한다. 모든 카드에서 서버가 판정한 해당 행의 사유를 보여주며 사유가 없으면 `—`로 표시한다. 추천 전용 비교값·수정 버튼과 유형 필터는 추천 카드에서 유지한다. 매입처 펼침 행은 같은 13열 구조를 공유한다.

## 매입 가능 상태와 보유 재고 추천

가격 인하·역마진은 선정 매입처의 정상 확인 옵션에 구매 가능하고 양의 재고인 옵션이 있을 때만 판정한다. 최신 정상값이 없으면 같은 선정 판매글의 마지막 정상값을 일괄 판독하고 이전 매입 상태와 확인 시각을 표시한다. 재고 0은 AVAILABLE 표시여도 매입 불가다. 모든 옵션이 재고 0 또는 구매 불가로 확인되어야 매입 불가이며, 일부 미확인이나 옵션 구성 누락은 품절로 추정하지 않는다. 미선정·미발견·식별 충돌도 구매 불가로 처리하지 않는다. RESTOCK도 동일 선정 판매글의 이전 정상 확인값을 사용하며 구매 가능·양의 재고 조건은 유지한다.

매입 불가이고 보유 0·쿠팡 판매 중 수량 양수이면 MARK_SOLD_OUT(품절 전환)으로 수량 0을 제안한다. 보유 양수이면 OWNED_STOCK_MISMATCH(보유 재고 맞춤)로 단일 보유 옵션·단일 쿠팡 옵션의 불일치 수량을 제안한다. 다중 보유/쿠팡 옵션은 옵션 확인 필요로 안내하며 총재고를 각각 배정하지 않는다. 미입고는 포함하지 않고 정상 조회의 재고 기록 없음은 0, 조회 실패는 오류로 처리한다.

`stockProposal`은 `source`(SUPPLIER/ZERO/OWNED), `quantity`, `selectionRequired`를 전달한다. `previousAvailability`/`availabilityCheckedAt`으로 근거를 표시한다. 공개 매입 `selectedStocks`와 재고 `ownedStocks`를 통해 일괄 읽고 쿠팡 모듈은 매입·재고 모듈에 의존하지 않는다. 계정 내 같은 코드의 활성 쿠팡 옵션 수는 공개 `CoupangOptionCounts` 포트를 사용한다. 빠른 수정 근거 fingerprint에 선정 상태·보유 옵션 수량·쿠팡 옵션 수를 포함하여 준비·실행 시 변경을 재확인한다. 모달에는 보유 옵션별 수량을 제공하고 미저장·저장된 해당 수정값을 제안값보다 우선한다. 품절 전환은 판매중지가 아니라 기존 STOCK 단일 항목 전송이다.

## 반응형 목록

1440px 이상은 13열 표, 그 미만은 같은 옵션 DOM과 조회 상태를 사용하는 카드로 표시한다. 강제 최소 너비를 제거하고 짧은 열은 좌우 6px, 나머지는 8px·상하 6px로 압축한다. ID·코드와 긴 값은 줄바꿈하며 표나 페이지를 가로로 넘기지 않는다. 추천 값과 수정 버튼은 필요하면 두 줄로 배치하고 매입처 행도 같은 열 구조를 공유한다. 카드는 이미지·코드·상품명, ID·구매속성, 추천 사유, 가격·재고, 상태·작업과 내부 매입처 펼침을 제공한다. 새 테이블·마이그레이션·외부 조회·자동 전송은 없다.

## 조회 비용과 일관성

조회는 계정 전체 추천을 요청 시점의 DB·계산 설정으로 판정한다. 검색·유형 필터 후 정렬·페이징과 전체 건수 기준은 유지한다. 페이지 행은 목록 전용 프로젝션으로 한 번에 읽으며 상세·쿠팡 원문을 행마다 다시 읽지 않는다. 코드별 중복 판정은 정확한 정규화 코드의 일괄 집계를 사용하고, 선정 매입처 표시에는 최신화 전문 대신 존재 여부만 읽는다.

이전 정상 재고는 기존 `(product_id,id)` 인덱스로 상품별 과거 20건씩 이어 읽는다. 최대 100상품 단위로 묶고 같은 선정 판매글의 일치·상태·옵션 근거만 가져온다. 기존 정상값 판정·동일 판매글 식별·중복 관측 보류·전체 옵션 수·확인 시각은 유지한다. 시간 기반 추천 캐시·영구 요약·새 테이블이나 인덱스는 추가하지 않는다. 검증은 [조회 최적화 기록](../verification/2026-10-17-coupang-query-performance.md)을 확인한다.

## 현재 페이지 선택과 일괄 수정

전체 선택은 현재 페이지 옵션 행의 기존 상품 단위 체크를 적용하며, 다른 페이지의 선택은 일괄 수정 대상에 포함하지 않는다. ‘조회 · 선택’ 요약 오른쪽의 가격 변경하기/재고 변경하기 버튼은 현재 페이지에서 선택한 상품의 보이는 옵션들만 모달로 연다. 정확히 일치하는 내부 상품이 하나여야 추천 문맥을 열 수 있으며 불명확한 행은 전송에서 제외한다.

모달은 상품별 bulk-edit/context의 DB 전용 문맥으로 현재값·저장된 수정값·추천값을 조회하고 옵션별 변경값을 편집한다. 같은 상품 옵션은 한 요청·한 편집 관측·세션을 공유하고 공통 문서는 응답에 한 번만 제공한다. 서로 다른 상품의 초기 DB 문맥은 최대 4개 요청으로 병렬 처리하며 닫힘·중단 이후 응답은 무시한다. 초기 표시와 저장 준비에는 쿠팡 API를 호출하지 않는다. 열기만으로 수정 의도를 저장하거나 전송하지 않는다.

저장은 포함한 각 옵션의 해당 항목 한 개를 bulk-edit/options/{vendor}/prepare → 기존 submissions/execute 순서로 직렬 처리한다. 준비는 서버가 저장한 DB 관측과 기존 단일 항목 검증을 사용한다. 같은 값은 저장·전송하지 않는다. 실제 실행 직전에 상품·대상 옵션의 최신 쿠팡값을 읽고 판매자상품코드·선택 항목 기준값·계정·매핑·선정 근거·설정·revision을 검증한다. 달라진 값은 전송하지 않고 입력을 보존해 재확인한다. 전송 후 반영 조회도 유지한다.

같은 상품의 다음 옵션은 이 일괄 작업이 확인한 성공 revision·appliedRevision과 일치하고 그 옵션의 현재값·식별자·선정 근거·설정이 그대로인 경우에만 이어 처리한다. 외부 수정으로 바뀐 revision·관측값·준비 범위·충돌에서는 기존처럼 멈춘다. 새로 연 미저장 상품은 서버 세션의 옵션 매핑을 재사용하여 불필요하게 옵션 ID를 다시 만들지 않는다.

실행 전 준비 ID·중복 방지 키를 세션에 보관하며 응답 유실·재진입은 같은 실행을 복구한다. ACCEPTED/UNKNOWN/실패는 후속 항목을 중단하고 결과 확인 또는 기존 실패 입력 수정 경로로 이어진다. 중단은 현재 처리 후 멈추며, 저장 도중에는 모달을 닫지 않는다. 성공한 항목만 완료하고 목록을 다시 읽으며 체크·검색·펼침 상태를 유지한다. DB 구조와 마이그레이션은 추가하지 않는다. 일괄 저장도 공통 FormActions를 적용하여 입력창 Enter로 실행하지 않는다.

다른 선택에 남은 전송 복구 기록은 현재 선택의 행을 비우거나 전체 모달을 잠그지 않는다. 현재 선택한 등록상품·옵션만 편집·전송하며, 이전 대상은 안내와 ‘이전 전송 결과 확인’ 버튼으로 따로 제공한다. 세션 저장은 현재 대상만 교체하고 다른 대상의 준비 ID·중복 방지 키·실행 ID·미저장 입력을 보존한다. 이전 기록을 확인하는 모드는 전송 기록이 있는 행만 복구하며 과거의 미전송 입력을 실행하지 않는다. 같은 등록상품의 UNKNOWN/ACCEPTED·계정·revision·식별자·근거 보호와 계정별 실행 임대는 서버에서 계속 검사한다. 손상된 복구 자료는 덮어쓰지 않고 전송을 막는다. ## 정상 검색의 선정 판매글 미발견과 재고 제안

선정 판매글을 정상 검색에서 찾지 못했을 때도 매입 가능성이 확인되지 않은 판매 위험으로 품절 전환을 제안한다. 실제 재고 0 확인과는 구분하며 `availability=SELECTED_MISSING`, `availabilityReason=SELECTED_LISTING_MISSING`와 근거 시각을 반환한다. 쿠팡 판매 중·수량 양수·실제 보유 0이면 수량 0, 보유가 양수이면 기존 보유 재고 맞춤 규칙을 적용한다. 이미 0이면 품절 전환하지 않으며 다중 보유/연결 옵션의 총재고를 자동 배정하지 않는다. 미선정·중복 코드·선정 식별 충돌·조회 기준 변경·보유 조회 실패를 미발견/0개로 바꾸지 않는다.

`ProcurementProductQueries.SelectedStock.search`는 현재 상품코드·검색어·lookup revision과 정확한 선정 판매글 식별자로 읽은 마지막 정상 검색의 미발견 여부·시각·이전 근거 여부와 마지막 미발견 시각을 제공한다. 검색 실패·차단·취소·불완전 결과는 새 미발견을 만들거나 직전 정상 근거를 지우지 않는다. 최신 검색에서 발견돼도 미발견 이전 재고를 자동으로 살리지 않는다. 같은 판매글의 정상 구매 가능 양수 재고가 미발견보다 더 최신인 경우에만 그 미발견에 따른 제안을 해제한다. 시각을 비교할 수 없으면 과거 양수 값으로 해제하지 않는다. 개별 정상 재고 확인에 실제 확인 시각이 있으면 그 시각을 사용한다.

검색 근거는 기존 작업·검색 캐시에서 100상품 단위, 상품별 run keyset 20행 단위로 판독한다. 완료 플래그·선정 판매글의 원시 검색 키 포함 여부만 투영하고 전체 검색 이미지/상품 payload를 가져오지 않는다. 보유 및 정상 재고 판독은 기존 배치를 유지한다. 신규 외부 조회·영구 연결·DB 마이그레이션은 없다.

추천·빠른 수정 응답은 `availabilityReason`과 기존 `availabilityCheckedAt`·`previousAvailability`를 제공한다. 빠른 수정 Source의 `stockProposal`은 목록과 같은 서버 함수로 계산한 출처·수량·옵션 선택 필요 여부다. 개별/일괄 모달은 이를 기본값으로 사용하며 미저장 직접 입력과 저장된 수정값을 우선한다. `stockProposal=null`은 수량 미확정이므로 과거 매입처 수량을 자동 입력하지 않는다. 재고 옵션 상세에는 이전 수치를 남기되 구매 가능한 최신 수량으로 오인하지 않게 구분한다.

목록의 모든 카드에서 추천 사유에 미발견을 표시하고, 추천의 품절 전환 필터·전체 건수에 포함한다. 매입처 펼침은 `이전 확인 재고 1개`와 `정상 검색에서 미발견`을 구분한다. 미발견 중에는 가격 인하·역마진·재고 보충을 제안하지 않는다. 새 유형을 추가하거나 자동 전송하지 않으며 기존 수량 변경 API로 사용자가 명시적으로 저장·전송한다.

검색 근거도 기존 빠른 수정 fingerprint에 포함한다. 준비·실행·HTTP 재시도 직전에 근거가 바뀌면 입력을 보존하고 재확인한다. 기존 revision·관측 버전·계정·UNKNOWN·ACCEPTED 보호를 유지한다. 검증은 [2026-10-20 미발견 추천](../verification/2026-10-20-coupang-missing-listing.md)을 따른다.

## 기간 조건 + 최근 N개 가져오기 (V52)

`최근 등록 가져오기`는 한국 날짜 기준 최근 7일·100개로 시작한다. 오늘·7일·30일·직접 지정(양끝 포함 최대 90일)과 등록상품 1~500개를 지정한다. 기존 저장 상품도 갱신 대상이다. 목록 후보 건수와 실제 수집 대상 수는 다를 수 있다.

`POST /api/coupang/products/collections`에 `{ "mode":"RECENT", "sellerProductIds":[], "createdDateFrom":"2026-10-14", "createdDateTo":"2026-10-20", "maxProducts":100 }`를 전달한다. 최근 조건과 선택 ID를 혼합하지 않는다. 기존 `{sellerProductIds:[]}` 전체 수집과 ID 목록 선택 갱신은 그대로 사용한다.

종료일부터 하루씩 `createdAt=yyyy-MM-dd&maxPerPage=100`으로 조회하고 해당 날짜의 모든 페이지를 확인한다. 작업 요청 시각보다 나중인 상품과 명시적 삭제 상태를 제외한 뒤 등록 시각 내림차순, 동률이면 숫자 등록상품 ID 내림차순으로 선정한다. N개를 확보한 날짜를 마치면 이전 날짜는 조회하지 않는다. 기간 내 부족하거나 0개여도 정상 완료한다. 날짜 누락·잘못된 날짜·요청 날짜 불일치·중복 ID의 등록일 충돌·반복 페이지 토큰은 `RECENT_*` 고정 오류 코드로 중단한다.

내부 `RecentProductCandidates` 조회는 기존 SUMMARY 관측을 발행하지 않는다. 후보는 `coupang_collection_candidate`에만 보관한다. 페이지 후보와 토큰·날짜·페이지 수를 같은 트랜잭션으로 저장하고, 선정 확정 트랜잭션에서만 최대 N개를 기존 SUMMARY/상세/옵션 판매값 수집으로 전달한다. 후보의 최초 조회 관측 순서를 유지해 더 최신 관측을 보호한다. 후보에는 원문·등록일·관측 순서·관측 시각을 보관하며 공개 응답에 원문은 노출하지 않는다.

수집 응답의 선택 필드 `recent`는 `createdDateFrom`, `createdDateTo`, `maxProducts`, `cutoffAt`(한국 지역 일시), `currentDate`, `apiPages`, `candidates`, `selected`, `selectionComplete`를 포함한다. 선정 전 진행률은 미정이며 확정 후 `completed+failed`/`discovered`다. RECENT의 `listComplete`는 항상 false이고 계정 전체 목록 완료를 뜻하지 않는다. 전체 삭제 목록·누락 상품 판정을 실행하지 않으며, 선정 대상의 명시적 삭제 상세 응답만 기존 규칙으로 처리한다.

취소·임대 만료·호출 제한 뒤 재개는 기존 작업의 고정 기준 시각·후보·체크포인트를 사용한다. 대상 확정 후 상세 조회 실패를 다른 후보로 채우지 않으며 재시도는 실패한 대상만 다시 처리한다. 공유 호출 간격·HTTP 재시도·권한·계정 잠금·결과 알림을 재사용한다. 조회·수집은 쿠팡 상품 판매값을 변경하지 않는다. V52 운영 적용은 [전환 절차](../coupang-recent-products-migration.md)를 따른다.
