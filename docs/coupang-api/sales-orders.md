# 쿠팡 주문 수집과 조회

현재 구현 안내. 최신 프로젝트 `coupang-api-docs`의 SOURCE를 기준으로 한다. 문서 규격과 실제 계정 검증은 아래에서 구분한다.

## 화면과 범위

관리자의 **판매 주문**(`/coupang/orders`)에서 기간을 선택하고 수집한다. 기본 최근 7일, 한 작업 최대 31일이며 앱의 제한이다. 쿠팡 판매자배송의 결제 이후 주문과 취소·반품·교환·반품철회를 대상으로 한다. 로켓그로스·미결제 주문·자동 수집·발주확인·송장등록·클레임 처리·보유 재고 연결은 포함하지 않는다.

상품별 한 행의 통합 목록은 저장된 관측값이다. 상세를 열 때 쿠팡을 다시 조회하며 수령자·연락처·주소는 DB와 브라우저 저장소에 보관하지 않는다. 조회 실패 때 저장된 요약을 삭제하거나 수량을 0으로 변경하지 않는다.

## 수집 원칙

- 정상 발주서의 여섯 상태를 각각 조회하고 반환 커서 그대로 페이지를 이동한다. 교환·철회는 별도 API다. 정상 목록만으로 모든 클레임이 포함된다고 판단하지 않는다.
- 계정·주문번호를 부모 키로 사용한다. 쿠팡 분리배송 때 배송번호가 바뀔 수 있으므로 완전한 주문번호 단건 응답으로 현재 상품 스냅샷을 교체한다. 실패·구조 오류·부분 응답이면 교체하지 않는다.
- 클레임은 독립 ID로 유지하고 배송번호·옵션 ID가 유일하게 맞을 때 상품에 연결한다. 불명확한 연결은 주문 단위 클레임으로 남긴다.
- 저장된 미완료 주문·클레임도 재조회한다. 목록에서 사라졌다는 이유로 완료나 철회 처리하지 않는다.
- 수집 작업과 구간·커서를 저장한다. 성공한 구간은 유지하고 실패 구간을 재개한다. 재시작한 작업은 중단 상태로 복구하며 자동 완료하지 않는다.
- 전체 수집원의 완료 여부를 따로 기록한다. 미검증 계약이나 실패한 구간이 있으면 부분 완료다. 완료는 선택 기간의 조회 범위를 뜻하며 계정의 모든 과거 주문 발견을 보장하지 않는다.
- 상품·주문은 같은 계정 호출 제한을 사용한다. 요청당 연결 10초·전체 20초·본문 5MiB 제한과 HTTP 429 재시도 정책을 재사용한다. 외부 HTTP 대기 동안 DB 트랜잭션을 유지하지 않는다.

## 문서의 미확인 계약

쿠팡 `returnRequests`에는 일 단위 모드의 `searchType`, CANCEL에서 `orderId` 생략, 응답 `nextToken` 위치에 표·본문·예시 충돌이 있다. 실제 읽기 검증 전 해당 계약을 검증 완료로 표시하지 않는다. 운영 요청에서 실패를 근거로 다른 파라미터 방식으로 자동 전환하지 않는다.

발주서 검색의 `createdAtFrom/To`가 주문일·결제일 중 어느 필드에 해당하는지는 SOURCE에 명시되지 않았다. 수집 기간과 통합 목록의 주문일·결제일 검색을 구분한다. 교환·반품의 기간은 접수일이다.

## 실행 및 검증 기록

앱은 기존 쿠팡 서버 설정을 런타임에 읽는다. 비밀 파일을 직접 열거나 값을 테스트에 복사하지 않는다. 미설정 계정은 설정 필요 상태로 안내한다. 현재 V48 스키마는 주문·수집 이력·계정 잠금과 식별자를 보존한다. 추가 수집은 명시적으로 실행한다. 주문 상세는 `/api/coupang/orders/{orderId}/detail`이며 마켓 선택 인자를 받지 않는다.

배송 개인정보가 포함되지 않는 정규화 요약만 저장한다. V34·V35는 과거 적용 이력이며 변경하지 않는다. 기존 재고·알림 스케줄러와 주문 수집 스케줄러를 분리했다.


`coupang.orders.worker-enabled=false`로 수집 워커의 자동 실행을 중지할 수 있다. 수집 시작·취소·재개 API와 외부 쓰기를 구분하며 요청 접수는 운영 감사에 남긴다. 실제 수집 실패·부분 결과는 작업 이력에서 확인한다.

최신 자동 검증은 [테스트 안내](../testing.md), 실제 계정 읽기의 과거 결과는 [2026-10-07 기록](../verification/2026-10-07-coupang-orders.md)을 따른다. 이번 정리에서 실제 계정 읽기나 쓰기를 실행하지 않았다.
