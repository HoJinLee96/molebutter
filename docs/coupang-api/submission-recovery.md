# 쿠팡 전송 복구

현재 작업본·전송 계약은 [상품과 작업본](working-copies.md)을 따른다. 임시 저장과 미리보기는 실제 쿠팡 쓰기를 실행하지 않는다. 전송 확인 후 실행별 중복 방지 키로 요청을 접수하며 재요청에서도 같은 실행을 돌려준다.

실패·부분 성공에서는 성공한 단계를 재실행하지 않는다. UNKNOWN·ACCEPTED가 있으면 재쓰기와 새 미리보기를 막고 결과 확인을 우선한다. 결과 확인은 실제 전송 직전에 보관한 request 전문을 기준으로 조회하며, 조회 실패만으로 이전 쓰기를 실패 처리하지 않는다.

입력 수정은 과거 결과를 남기고 미실행 단계를 종료한 후 새 미리보기를 준비한다. 기존 전문·해시·키는 수정하지 않는다. schemaVersion 1~3 형식은 역사적 판독기로 조회·결과 확인하며 새 쓰기는 schemaVersion 4에서만 수행한다. 계정·revision·상품·옵션 식별자·권한 또는 수정 가능 상태 변경은 입력을 유지한 채 재준비한다.

검증은 [테스트 안내](../testing.md)의 모의 API와 격리 DB를 사용한다. 실제 쿠팡 쓰기를 실행하지 않는다.

완료 처리는 즉시 응답·목록 자동 조회·새로고침·결과 확인에서 동일하게 실행한다. 성공한 단계와 값이 일치하는 수정 의도만 제거하고 이후에 입력하거나 저장한 다른 값은 유지한다. 가격 단계가 성공하고 상품 단계가 실패한 경우에도 확인된 가격 수정을 새 상품 수정에 포함하지 않는다.

서버 저장에서도 세션이 확인했던 의도와 현재 남은 의도를 대조한다. 완료 직후 목록 갱신 전에 임시 저장해도 이전 가격 등이 다시 남지 않는다. 수정한 값이 달라졌다면 새 의도로 보존한다. 이 대조 정보가 없는 이전 세션은 재진입으로 갱신하고 저장 입력은 유지한다.

임시 저장 응답과 완료 조회가 겹쳐도 한 작업이 다른 작업의 입력 잠금을 해제하지 않는다. 저장으로 revision이 바뀌면 목록을 다시 확인해, 이전 revision 때문에 완료 처리를 보류한 경우에도 새 작업본으로 마무리한다.
