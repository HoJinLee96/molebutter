# 쿠팡 상품과 작업본

판매업무는 쿠팡 등록상품과 로컬 작업본을 관리한다. 상품업무의 상품·매입·보유 재고와는 독립적이다. 판매용 내부 상품·연결 후보·내부 기준값을 제공하지 않는다. 등록상품 관측값과 작업본의 수정값은 [등록상품 저장소](registered-products.md)에서 구분하고 충돌 시 사용할 값을 선택한다.

`/coupang/products`는 쿠팡 상품 목록이며 별도 임시저장 탭은 없다. 신규 등록 화면의 임시 저장 옆에 임시저장 불러오기 버튼을 제공한다. 모달은 서버의 `mode=CREATE` 필터로 신규 등록 작업본만 상품명 검색·최근 수정순·20개 단위로 조회하고 선택한 작업본 편집 주소로 이동한다. 취소·조회 실패는 현재 입력을 유지하며 불러오기 이동은 기존 미저장 입력 보관과 이탈 확인을 따른다. 기존 상품의 수정 작업본은 목록의 수정 버튼으로 다시 연다. 목록·상세·검색은 DB에서 읽는다. 쿠팡 조회는 수동 수집·편집 진입·전송 전 확인에서 실행한다. 신규 등록은 `/coupang/products/new`, 기존 상품은 `/coupang/products/{sellerProductId}/edit`, 저장 후 재진입은 `/coupang/working-copies/{id}/edit`이다. 이전 drafts 주소는 404이며 호환 경로를 제공하지 않는다.

## 저장과 전송

신규 등록은 [호출 축소 검증](../verification/2026-10-21-coupang-creation-queries.md)을 따른다. 서버에서 확인한 카테고리 규격을 계정·카테고리별로 10분간 재사용하고 `Entry.categoryRules.checkedAt`을 제공한다. 만료·재시작·카테고리 변경에는 입력을 보존하고 명시적인 규격 재조회를 요구한다. 신규 등록 결과 확인에서는 판매 시작·종료 일시, 검색어 배열의 순서, 상품 이미지의 vendorPath·cdnPath와 상세 IMAGE·HTML img src 주소 변환을 값 불일치에서 제외한다. 검색어 구성·개수, 상품 이미지 장수·역할·imageOrder, 상세 행 구조·타입과 문구 및 나머지 요청 필드는 계속 확인한다. 이 규칙은 CREATE 결과 확인에만 적용하며 기존 상품의 기간 수정·충돌 검사는 그대로다. 요청·관측 원문과 과거 결과 이력은 변경하지 않는다. [결과 비교 검증](../verification/2026-10-21-coupang-create-reflection.md)을 따른다. 신규 상품의 판매자상품코드 사전/후보 조회는 수행하지 않는다. 등록 응답 ID가 없으면 UNKNOWN으로 멈추고 Wing 직접 확인을 안내한다. 승인 후 상세 관측으로 완료 화면을 갱신할 때는 기존 작업본 GET의 선택 필드 `observed=true`를 사용하며 추가 상세/현재 재고 API를 호출하지 않는다. 일반 편집 진입과 기존 상품 수정은 최신 조회를 유지한다.

판매기간은 API의 `saleStartedAt`·`saleEndedAt`을 한국 시각의 시작·종료 일시로 항상 표시한다. 2099년 종료일을 기간 제한 없음으로 추정하지 않는다. 초 단위와 원문 날짜는 조회·재렌더링·재진입에서 보존하고, 잘못된 날짜는 원문을 텍스트로 표시해 수정을 안내한다. 신규 빈 입력도 자동으로 채우지 않는다. `장기 판매기간 설정` 버튼을 직접 누를 때만 현재 한국 시각부터 `2099-12-31T23:59:00`까지 설정한다. 버튼은 공통 FormActions에 명시적으로 연결하며 입력창 Enter로 이 동작을 실행하지 않는다.

고시유형 선택란은 규격 조회 중·실패에도 현재 유형을 표시하고 비활성화하며, 고시 영역에서 오류와 재조회 버튼을 제공한다. 정상 조회 후에도 기존 유형이 최신 후보에 없으면 보존하고 안내하며 첫 후보로 자동 교체하지 않는다. 옵션별 유형이 다르면 혼합 선택 상태와 각 옵션의 고시 내용을 표시한다. 혼합 상태의 내용 편집은 해당 옵션에만 적용하고, 고시유형을 명시적으로 선택하면 모든 옵션에 적용한다. 지연된 이전 규격 응답은 새 카테고리 입력을 변경하지 않는다.

고시 유형을 바꾸면 임시 저장·전송 문서에는 현재 선택한 유형의 고시 행만 포함한다. 이전 유형의 편집 중 값은 현재 폼에서 유지하지만 선택값을 이전 첫 행의 유형으로 되돌리지 않는다. 새로고침·불러오기는 저장된 선택 유형과 해당 고시 내용을 복원하며 전체 상세페이지 참조 여부도 해당 행의 내용으로 판단한다.

임시 저장은 앱 DB와 이미지 참조만 저장한다. 신규 편집기를 여는 것만으로 작업본을 만들지 않으며 첫 저장에서 ID를 부여한다. 등록상품은 계정과 등록상품 ID의 고유키로 기존 작업본을 재사용한다. 저장 요청은 `sessionId`, `expectedRevision`, `document`, `changes`다. 문서는 기본 정보, 옵션별 등록 설정·속성·이미지·상세설명·고시·인증, 배송·반품, 설정, 구비 서류를 보관한다.

조회 원문, 계정, 외부 상품·옵션 ID와 권한은 서버가 관리한다. 수정 의도는 허용된 필드와 옵션 UUID로 표현한다. 조회·렌더링·규격 채우기는 수정 항목을 만들지 않는다. 이미지·상세설명은 옵션별 목록 전체를 하나의 변경으로 취급한다. 같은 URL·설명을 여러 번 사용하거나 외부에서 순서를 바꿔도 개별 ID가 중복되지 않도록 복구한다. 속성·고시·인증·서류는 `rowKey`와 `operation`으로 수정한 행·필드를 명시한다. 키는 각각 이름·노출 구분, 분류·항목명, 인증 유형, 서류명이다. 필드 수정과 새 행 추가는 `SET`, 행 삭제는 `REMOVE`다. 속성은 같은 이름이라도 구매·검색 구분으로 별도 식별하며 수정 권한도 해당 원문 행에서 확인한다. 고시·인증·서류는 최신 원문에서 지정한 행·필드만 패치하고 미수정 행의 누락 필드·null·알 수 없는 항목과 두 서류 경로를 그대로 보존한다.

전체 상품 편집기의 쿠팡 반영은 임시 저장 → 미리보기 → 명시적 전송 확인으로 진행한다. 옵션 빠른 수정은 저장 버튼 옆에 변경 전후 값을 표시하며 저장 클릭으로 해당 한 항목의 저장·전송을 확인한다. 서버 준비·검증을 통과하고 준비 내용이 표시와 일치할 때만 기존 실행 API로 이어진다. 충돌·관측값 변경은 재확인을 요구하고 자동 전송하지 않는다. 일반 상품 정보는 실제 전송 직전 GET 원문을 복사하고 수정 항목만 적용한 PUT이다. 최신 원문의 알 수 없는 필드와 수정하지 않은 값은 보존한다. 가격·판매재고·정상가는 옵션 전용 PUT을 사용한다. 신규 등록은 POST 후 명시된 판매 승인 단계를 수행한다.

구매 입력칸·택1 선택·규격 채우기·입력 검증도 속성의 이름과 노출 구분을 함께 사용한다. 같은 이름의 `NONE` 검색속성이 먼저 있어도 `EXPOSED` 구매속성의 값·필수 조건을 표시한다. 조회 응답의 `attributePermissions`는 `name`, `exposed`, `editable`로 원문 행을 구분하며, 기존 구매속성은 해당 행의 명시적인 `editable=true`만 수정 권한으로 인정한다. 노출 구분이 없는 이전 권한은 기존 구매속성의 수정 권한을 부여하지 않으며 재진입에서 최신 조회로 갱신한다. 이 정보는 서버 조회에만 속하고 저장 문서·수정 의도에 복사하지 않는다.

예를 들어 조회 가격 120000, 사용자 입력 130000, 외부 변경 150000이면 최종 가격 요청은 130000이다. 외부 값도 변경되었으면 충돌 선택에서 내 수정값 반영을 선택한 뒤 전송한다. 선택 이후 다시 외부 값이 바뀌면 재확인을 요구한다. GET과 PUT 사이 외부 변경까지 원자적으로 방지하지는 못한다.

## 복구와 보호

상품 등록·승인·가격·수량을 포함한 API 호출의 제한적 재시도는 [공통 재시도](retries.md)를 따른다. 연속 호출의 기본 간격은 직전 응답 수신 후 최소 2초이며, 신규 등록 POST → 승인 PUT 및 승인 성공 후 자동 결과 GET에는 최소 5초를 적용한다. 명확한 일시 거절만 최대 1회 재시도하며, 전송 직전 근거를 다시 확인한다. 등록 성공은 유지하고 승인 단계만 재시도한다. 최종 실패는 기존 전송 기록에 남긴다.

신규 등록의 승인 PUT 성공 후 자동 GET은 최초 실행과 승인 단계 재시도 모두에서 수행한다. 상품 처리 중 응답 또는 실제 승인 대기 상태이면 5초 간격으로 GET만 계속한다. 단계는 RUNNING을 유지하고 화면은 승인·결과 자동 확인 중으로 표시하며 수동 결과 확인을 요구하지 않는다. 자동 확인은 10분·최대 120회이며 HTTP 실행기 내부의 제한적 재시도(2초)는 별도다. 승인 완료·반려·연결 이상이면 즉시 그 결과로 종료한다. 한도 소진은 `APPROVAL_CHECK_TIMEOUT`, 권한 변경은 `APPROVAL_CHECK_ACCESS_DENIED`, 처리 중 이외 조회 오류는 `APPROVAL_LOOKUP_FAILED`로 접수와 ID를 보존한다. 기존 ACCEPTED 신규 승인 단계의 결과 확인을 실행해도 같은 자동 확인을 사용한다. 조회 실패를 승인 실패로 바꾸거나 승인 PUT·등록 POST를 자동으로 다시 보내지 않는다. 앱 종료·중단은 기존 UNKNOWN 복구 보호를 유지하며 무조건 재전송하지 않는다. [자동 결과 조회 확인](../verification/2026-10-21-coupang-approval-auto-lookup.md)

쿠팡의 확정 거절은 HTTP 200 본문의 `code=ERROR`도 포함한다. 새 결과에는 `message`·`details`와 `errorItems`의 옵션 순서·속성명·오류 설명에서 추출한 상세 사유를 함께 보존한다. 응답 상품명·속성값·알 수 없는 필드는 복사하지 않고 요청 문자열 값, URL·이메일·연락처·긴 식별자는 가린다. 개인정보·인증정보 표식이 포함된 설명은 해당 조각 전체를 생략한다. 상세 설명은 최대 360자, 고정 안내를 포함한 화면 메시지는 기존 DB 제한인 500자 이내다. 원문 응답을 저장하거나 반환하지 않는다. 인증·권한·호출 제한·서버 오류와 UNKNOWN·ACCEPTED에는 이 거절 설명을 붙이지 않는다. 이전 실행에서 버린 원래 사유는 복구하지 못한다.

저장 입력은 새 편집 세션·앱 재시작 후 작업본에서 복구한다. 브라우저의 미저장 입력은 계정과 작업본별 sessionStorage에 보관한다. 신규 작성의 세션 만료·앱 재시작에서는 문서 전체와 옵션 UUID를 보존한다. 등록상품 수정은 같은 계정·revision의 새 세션에서 최신 조회값에 명시한 수정만 재적용한다. 캐시는 마지막 저장 문서와 미저장 입력의 차이를 보관해 이미 완료한 수정이 다시 섞이지 않게 한다. 저장·조회·전송 실패는 현재 입력을 지우지 않는다. 최신 조회를 편집 문서로 변환할 수 없는 경우에도 저장된 문서로 복구하고 전송을 차단한다. 임시 저장과 전송 완료 조회의 잠금은 각각 유지하며 둘 다 끝나기 전에 입력을 열지 않는다. 저장 revision이 바뀌면 전송 상태를 다시 확인한다. 계정이나 로컬 revision, 상품·옵션 식별자, 권한·수정 가능 상태가 달라지면 입력을 유지하고 재조회·재준비한다.

실행은 계정 임대와 중복 방지 키를 사용한다. 성공한 단계는 재실행하지 않는다. UNKNOWN·ACCEPTED는 새 전송을 막고 결과 확인을 우선한다. 실제 전송 직전의 전문은 attempt에 기록하며, 이전 전송 전문·해시·키를 수정하지 않는다. 역사적 형식은 조회·결과 확인에 사용하며 새 수정은 schemaVersion 4 미리보기로 준비한다. 이전 형식의 재쓰기는 새 미리보기를 요구한다. 즉시 응답·자동 조회·새로고침·결과 확인은 같은 완료 처리로 연결한다. 확인된 단계의 수정만 제거하고 새 미저장 입력은 보존한다. 서버 편집 세션도 마지막으로 확인한 미완료 의도를 보관하므로 목록 갱신 전 임시 저장이 완료된 가격 등을 되살리지 않는다. 같은 필드에 새로 입력한 다른 값은 유지한다. 이전 세션 형식은 저장 입력을 유지한 채 새 세션으로 갱신한다. 신규 등록 완료 후 작업본은 UPDATE가 된다.

이전 목록 전체 수정처럼 행별 의도를 확정할 수 없는 입력은 저장 문서로 보관하고 자동 전송을 막는다. 입력 내려받기·보관 후 최신 값으로 다시 준비하는 동작을 제공하며 사용자가 필요한 수정을 다시 지정해야 한다.

현재 API는 `/api/coupang/working-copies`의 목록·생성·조회·저장과 `/api/coupang/submissions`의 준비·실행·재시도·입력 수정·결과 확인이다. 편집 세션은 진입·저장·전송 준비에서 관리한다. 중복 edit-data·검증·세션 갱신과 연결·내부 기준 저장·비교 해결·중복 등록 저장 API는 제거했다. 입력 Enter 규칙은 [공통 규칙](../ui-interaction-rules.md)을 따른다.

옵션 빠른 수정의 `GET /api/coupang/products/{id}/options/{vendorItemId}/quick-edit`는 기존 편집 조회의 `currentInventory`로 가격·재고를 함께 반환하며 `currentValue`도 유지한다. 선정 매입처 재고는 최신 정상 확인값 또는 동일 선정 판매글의 마지막 정상 확인값을 사용한다. 실패·조회 중은 이전 정상값을 지우지 않으며, 전체 매입처 옵션 수와 재고 후보의 `previous`·`checkedAt`을 별도로 반환한다. 단일 옵션만 자동 입력하고 다중 옵션은 직접 선택한다. 자동 입력·미저장 직접 입력·저장 의도를 구분하고 직접 비운 입력도 재조회·재진입에서 보존한다.

같은 경로의 `/history?kind=PRICE|STOCK&page=0&size=20`는 DB만 읽어 해당 옵션·항목의 확인값·작업본 저장·전송 이력을 최신순으로 반환한다. `OptionEvent`는 식별자, 종류, 전후 숫자값, 사용자, 실행 ID, 시각만 포함하며 다른 항목의 전문은 노출하지 않는다. 기존 식별자로 확정할 수 없는 과거 기록은 추정하지 않는다. 이력은 모달 안에서 펼치며 조회·접기는 수정 의도나 쿠팡 요청을 만들지 않는다.

현재 DB 전환은 [V49 등록상품 보존 전환](../coupang-products-migration.md)이며, 이전 전환은 [V48 보존 전환](../coupang-intent-migration.md), 작업본 구조의 역사적 근거는 [V47 보존 전환](../coupang-working-copy-migration.md), 검증은 [테스트 안내](../testing.md)를 따른다. 실제 쿠팡 쓰기와 공용 R2 삭제는 일반 회귀 검증에서 실행하지 않는다.

중복 미디어의 ID 보존은 현재 편집기와 V47 오프라인 전환이 같은 함수로 처리한다. V47 보완은 백업·격리 복원 뒤의 유지보수 명령에 한정하며 현재 작업본 저장 요청에 전환용 형식을 허용하지 않는다.

선정 판매글 미발견의 품절 전환과 개별·일괄 재고 기본값은 [미발견 추천 계약](registered-products.md#정상-검색의-선정-판매글-미발견과-재고-제안)을 따른다. 정상 검색 근거와 시각을 fingerprint에 함께 보관하며, 과거 양수 매입처 재고로 서버의 0개 제안을 덮지 않는다. 저장 의도와 직접 입력은 계속 우선한다.

상품 정보 도구의 신규 등록 자동 입력·계정 기본설정·직사각형 경고와 V51은 [등록 준비 안내](../coupang-registration-prefill.md)를 따른다.

신규 등록의 브랜드 로고 설명 행은 선택적인 `Content.purpose=BRAND_LOGO`로 구분한다. 기존 UUID/IMAGE 설명을 사용하며 쿠팡 원문이나 전송 전문에 이 로컬 표시를 추가하지 않는다. 저장·재진입·미저장 복원에서 보존하고 일반 설명 행을 URL로 자동 분류하지 않는다. 자세한 선택·설정 계약은 [등록 준비 안내](../coupang-registration-prefill.md#브랜드별-상세설명-로고)를 따른다.
