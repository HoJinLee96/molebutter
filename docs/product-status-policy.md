# 상품 조회 상태와 선정 판매글 미발견

> 문서 유형: 현재 구현 안내. 2026-10-05 로컬 코드와 대조했다. 날짜가 붙은 적용·검증 문단은 당시 기록이며 현재 정책과 구분한다.

2026-09-29 구현. 상품 상태와 작업 제어, 실제 옵션의 구매 상태를 분리한다.

## 판정

- 상품 상태는 NOT_CHECKED(미조회), PENDING(대기), CHECKING(조회 중), SUCCESS(조회 완료), SOLD_OUT(품절), PARTIAL(일부 확인 필요), UNCONFIRMED(필수 입력 확인 필요), FAILED(검색 실패), CANCELLED(취소)다.
- 정상 검색에서 발견한 선정 + 선호 매입처만 집계한다. 선정하지 않은 비선호 추천은 종합 상태에 영향을 주지 않는다.
- 대상 없음은 SOLD_OUT/NO_TARGET_LISTINGS, 모든 옵션의 명시적 0 또는 구매 불가는 SOLD_OUT/ALL_UNAVAILABLE다. 상품의 종합 품절이 실제 옵션 재고를 0으로 바꾸지는 않는다.
- 실제 조회 오류·수량 미확인·부분 옵션·가격/배송비 누락은 PARTIAL을 우선한다. 전부 미확인이어도 품절이 아니다. 명시적 구매 불가는 수량이 없어도 구매 불가로 판정한다.
- 대표 재고의 의도적 생략은 정상 처리하되, 저장된 대표 근거가 무효이면 미확인으로 처리한다.
- JSON의 statusPolicyVersion=2와 statusReasons는 선택적 호환 필드다. 과거 누락/null은 허용한다.
- 내부 작업/개별 조회의 BLOCKED·STALE는 유지한다. 상품의 STALE는 NOT_CHECKED, 검색 최종 BLOCKED는 FAILED로 표시한다. 매입처 재고 제한은 PARTIAL이며 작업은 계속 BLOCKED다.
- 네이버 검색의 자동 대기 중 상품은 PENDING이다. refresh-status.active와 상세 activeRefresh가 실제 작업의 대기/처리 여부를 제공하므로 표시 상태가 FAILED/PARTIAL이어도 재개 제어와 폴링을 유지한다.
- NO_MATCH와 SOLD_OUT은 모두 대상 재조회에서 제외한다. 과거 NO_MATCH 응답은 상품 화면에서 SOLD_OUT으로 호환 표시하지만 과거 작업 이력을 덮어쓰지 않는다.

## 선정 판매글

Listing.selectedMissing / selectedSearchAt은 정상 검색 원본 searchKeys와 정확한 판매글 식별자로 계산한다. 목록의 선정 글들을 한 번에 조회하며 상품마다 검색 쿼리를 반복하지 않는다.

검색 실패·대기·취소·조회 버전 불일치·원본 키 근거 부족은 미발견으로 추정하지 않는다. 정상 검색에 있는 글의 상세 실패, 필터 제외, 상세 생략도 미발견이 아니다. 미발견은 삭제/판매 종료를 의미하지 않는다.

선정 ID·가격·재고·시각은 보존하며 목록과 상세에서 미발견 배지와 이전 확인값을 표시한다. 배지 클릭으로 검색 범위 밖 가능성과 검색 확인 시각을 볼 수 있다. 재등장하면 해제되며 검토 완료와는 독립적이다. 선정가 미확인 시 추천은 보류한다.

새 조회가 완료되면 과거 선호 판매글은 정상 비교 목록에서 빠진다. 실행/중단 대기 중에는 기존처럼 마지막 결과를 이전 확인값으로 보여주며, 사용자의 선정 변경 권한은 유지한다. 선호 설정이 바뀌면 마지막 최신화 기준임을 안내하고, 조회하지 않은 대상을 추정하지 않는다.

## 기존 상태 보정

`ProductStatusRepairCommand preview manifest.json application.properties db.properties`로 읽기 전용 트랜잭션에서 대상과 변경 전후를 확인하고 manifest를 저장한다. `apply`는 같은 manifest의 대상만 처리하며, 저장 직전 동일 결과·버전·작업 상태를 다시 검사한다. manifest에는 내부 조회 결과가 있으므로 외부에 공유하지 않는다.

활성/중단 작업 또는 개별 조회가 연결된 상품, 검색 정상 종료 근거 부족, 수동 매장 변경 등 연결을 확정할 수 없는 상품은 제외한다. 최초부터 판정할 수 없는 실패는 검색 실패로 추정하지 않는다. 현재 상태·안내·판정 버전과 상품 수정 버전만 갱신한다. 선정·가격·재고·확인 시각·과거 작업·조회 이력·변동/검토 기준은 보존한다. 같은 manifest는 중복 적용되지 않는다.

추가 테이블·마이그레이션·외부 재고 요청이 없다. 실행 코드는 서버 재시작 후 반영되며, 중단 작업은 임의 재개하지 않는다.

## 검증

ProductStatusPolicyTest 및 ProductFlowIT에서 미확인/품절/추천 제외, 선정 미발견·검색 내 상세 실패·재등장, 검토 완료 독립성, 보정 멱등성·이력 보존, 매입처 제한과 검색 제한, 취소와 버전을 검사한다. 브라우저 검증은 대표 상품 흐름으로 축소하며, 상태별 조건은 Java·JavaScript 테스트에서 유지한다. [테스트 안내](testing.md)의 검증은 실제 네이버에 요청하지 않는다.
