# 입력창과 Enter 키

입력 중 Enter는 검색·조회 또는 편집 중인 값의 추가를 실행한다. 공통 기준 저장, 마켓 저장, 등록, 삭제, 전송, 업로드, 입고 등 실제 저장 작업은 버튼을 직접 눌러 실행한다. 버튼에 초점을 둔 뒤 Enter·Space를 누르는 키보드 사용은 유지한다.

## 허용하는 동작

| 입력 위치 | Enter 동작 |
| --- | --- |
| 브랜드명 | 연결된 브랜드 검색 버튼 |
| 검색어·조회 조건 | 해당 검색·조회 버튼 |
| 편집 중 이미지 주소 등 | 해당 편집 화면의 값 추가 버튼 |
| 로그인·이메일 찾기 | 로그인·찾기 버튼 |
| 인증 메일·인증번호 | 발송·확인 버튼, 처리 중 중복 요청 차단 |
| 일반 입력·저장용 입력 | 값과 초점 유지, 작업 없음 |
| 여러 줄 입력 | 줄바꿈 |
| 한글 조합·선택 상자·날짜·시간·자동완성 목록 | 브라우저 기본 동작 |

‘추가’라는 이름이어도 설정 브랜드 등록, 판매처 등록, 입고 확인처럼 서버에 바로 저장하는 버튼은 입력창 Enter에 연결하지 않는다. R2 업로드와 마켓 전송도 같은 규칙이다.

## 구현

공통 head에서 `/js/form-actions.js`를 페이지 스크립트보다 먼저 읽는다. 사이드바가 없는 인증 페이지에도 같은 규칙이 적용된다.

- `FormActions.bindEnter(input, button)`: 특정 입력창을 실제 버튼 클릭에 연결한다. 검색 팝업 열기·규격 조회·편집 중 값 추가에 사용한다.
- `FormActions.bindEnterSubmit(form, button)`: 로그인·검색·조회 폼의 기본 버튼을 지정한다. 기존 조회용 submit 처리와 브라우저 입력 검사를 유지한다. 입력창별 연결이 있으면 그 버튼을 우선한다.
- `FormActions.bindExplicitSubmit(form, button, handler)`: 쓰기 버튼을 `type="button"`으로 바꾸고 클릭에만 처리 함수를 연결한다. 폼의 submit은 실행을 막는다. 폼 밖의 `form=` 버튼도 실제 폼과 함께 전달한다.

명시적 쓰기 처리 함수는 `currentTarget`·`target`에 폼, `submitter`에 실제 버튼을 받는다. `originalEvent`는 클릭 이벤트다. 기존 코드처럼 `preventDefault()`를 호출할 수 있다. 비동기 작업을 반환하거나 기다려야 처리가 끝날 때까지 중복 클릭 잠금이 유지된다. 페이지가 관리하던 비활성 상태와 오류 안내는 그대로 유지한다.

기본 입력 검사는 `reportValidity()`로 수행하며 폼의 `novalidate`·버튼의 `formnovalidate`를 따른다. 필요하면 기존 업무 검사를 처리 함수 안에서 이어서 수행한다. 등록을 반복해도 같은 버튼에 처리 함수를 중복 설치하지 않는다. 동적 입력을 다시 만들었으면 새 입력창에 연결한다.

공통 처리는 한 줄 입력의 기본 Enter 제출을 막는다. 연결된 버튼이 활성 상태일 때 한 번 클릭하므로 브라우저 기본 submit과 중복되지 않는다. 길게 누르기, 숨겨진 버튼, 비활성 버튼, 처리 중 버튼을 건너뛴다. 버튼 문구나 가까운 위치로 동작을 추측하지 않는다.

숫자 입력의 브라우저 증감 화살표는 공통 CSS에서 숨긴다. `type="number"`와 기존 `min`·`max`·`step` 검증은 유지하고 키보드 기본 숫자 입력 동작은 변경하지 않는다.

## 검증

`node --test src/test/js/*.test.cjs`로 공통 동작과 기존 페이지 회귀를 검사한다. 폼의 입력 검사, 처리 중 중복 실행, 동적 입력 재연결, 폼 밖 버튼, 실패 후 입력 유지도 확인한다.

PC와 모바일 브라우저에서는 실제 렌더링 화면에 모의 API를 연결해 입력 Enter와 직접 버튼 Enter·Space를 각각 검사한다. 브랜드 검색, 조회, 편집 중 추가는 실행되고 저장·전송·업로드는 입력 Enter로 실행되지 않아야 한다. 한글 조합·여러 줄 입력·자동완성 기본 동작을 훼손하지 않는다. 검증 중 실제 판매 상품이나 R2 객체를 변경하지 않는다.

## 모달과 스크롤

공통 head의 `modal-scroll.js`가 정적·동적 native dialog와 `role=dialog, aria-modal=true` 화면을 감지한다. 모달이 열린 동안 배경을 현재 위치에 고정하고 모달 내부만 스크롤한다. 중첩 모달은 마지막 모달이 닫힐 때까지 배경 잠금을 유지하며, Escape·닫기·dialog 폼·DOM 제거 모두 원래 배경 위치를 복원한다. 모달의 스크롤 경계에서 배경으로 휠/터치 스크롤이 이어지지 않게 공통 CSS로 제한한다.

모달 안의 스크롤·포커스·입력 Enter 규칙과 이미지 확대·크롭의 개별 스크롤 설정은 유지한다. 배경 스크롤바가 사라질 때 본문 폭을 보정한다. 잠금 중 목록 이동 상태를 저장할 때는 `ModalScroll.position()`의 원래 페이지 좌표를 사용한다. 페이지 이탈 시 잠금을 해제하고 복귀 시 열린 모달에 맞춰 복원한다.

## 표의 전체 선택

행 선택 체크박스가 있는 표는 공통 `TableSelection.create`를 사용한다. `controls`는 PC·모바일 전체 선택 입력, `checkboxes`는 현재 페이지의 행 체크박스를 반환하는 함수, `onToggle`은 활성 행들의 업무 선택 키를 갱신하는 콜백이다. 다시 그린 뒤 `sync()`로 전체·일부·미선택 표시와 빈 목록·처리 중 비활성 상태를 맞춘다. 비활성 행과 다른 표의 설정 체크박스는 포함하지 않으며 조회 전용 표에 선택 기능을 자동 추가하지 않는다.

선택은 현재 페이지로 제한한다. 목록 반영 시 `TableSelection.reconcile(selection, items, key)`로 사라진 ID를 제거하고 Map의 객체·revision도 현재 행으로 갱신한다. 검색·필터·페이지·페이지 크기 변경 시 선택을 초기화하며 조회 실패 시 이전 목록과 새 행 자료를 섞지 않는다.

실행 직전 해당 표의 활성 체크박스와 현재 행을 `TableSelection.snapshot(selection, items, key, checkedKeys)`로 대조한다. 화면 밖 ID와 체크 해제된 ID는 제외하고 빈 선택은 거절한다. 빈 배열을 ‘전체’ 작업으로 확장하지 않는다. 삭제·브랜드 지정 확인 화면은 열 때 대상 ID·revision을 고정한다. 목록 조회 중에는 선택 작업과 체크 변경을 막는다.

이전 전송 복구 자료는 새 선택을 대체하지 않는다. 선택 밖 미완료 전송은 대상을 표시하고 별도 결과 확인을 요구한다. 복구 화면은 새 수정을 준비하지 않고 기존 실행·준비 ID와 중복 방지 키만 사용한다. `UNKNOWN`·`ACCEPTED` 보호와 복구 자료를 삭제하거나 우회하지 않는다.
