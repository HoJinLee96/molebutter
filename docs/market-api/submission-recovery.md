# 판매 마켓 전송 실패 복구

- 결과 확인의 권한·계정·스냅샷 버전 검사 실패는 기존 외부 전송의 실패를 뜻하지 않는다. 기존 UNKNOWN/ACCEPTED 결과와 쓰기 잠금을 유지하고, 확인 시도의 실패는 execution attempt에 기록한다. 권한 검사는 유지한다.
- 미지원 스냅샷의 첫 WRITE가 거절되면 후속 대기 WRITE는 NOT_EXECUTED로 종료한다. 이미 미확인인 단계나 결과 확인 작업을 실패한 쓰기로 바꾸지 않는다.
- 재시도는 현재 초안 버전과 실행 버전이 같고 서버에서 허용한 실패에만 제공한다. 미확인·접수 상태는 먼저 결과를 확인한다.
- 쿠팡·스마트스토어 수정·등록 화면의 입력 수정은 기존 실행 기록을 보존한다. 미실행 단계만 종료한 뒤, 작성 중인 값과 원래 관찰값으로 새 변경 확인을 준비한다. 성공·미확인 등록을 신규 등록으로 다시 보내지 않는다.
- V38은 실행의 입력 수정 완료 여부와 담당자를 기록한다. 과거 API 생성자와 실행 기록은 호환된다.
- 업로드 입력창의 Enter나 암묵적인 폼 제출은 업로드하지 않는다. 명시적 확인 버튼과 버튼에 초점을 둔 Enter/Space는 기존 검사·중복 방지 아래에서 동작한다.

- 새 탭에서 실행 이력을 불러올 때 허용되는 페이지 크기 10을 사용한다. 이력 확인 중에는 새 전송을 준비하지 않으며, 늦은 이전 조회가 새 관찰값이나 수정 전환을 덮어쓰지 않는다.
- 공통·쿠팡·스마트스토어 편집 폼은 명시적 저장 버튼만 실행한다. 이미지 상품코드 조회와 브랜드 검색에는 Enter 조회를 명시적으로 연결한다.

## 검증 (2026-10-10)

PR #32 기준의 별도 체크아웃에서 관련 Java 단위 테스트 34개, 임시 MySQL·Redis 통합 테스트 33개(전송·기존 DB 업그레이드), 전체 JS 테스트 181개가 통과했다. 모듈 분리 작업본에서도 관련 Java 40개와 전체 JS 244개가 통과했다.

실제 마켓 쓰기, 실제 R2 업로드, 운영 DB 변경 및 배포는 수행하지 않았다. 첫 수정에서는 브라우저 키보드 동작을 DOM 이벤트 테스트로 검증했다.

### 입력 복구·Enter 재검증

쿠팡 신규 등록의 확정 실패 → 입력 수정 → 새 준비, 성공·미확인 등록 차단, 중복 수정 요청, 늦은 응답 차단과 새 탭의 이력 복원을 보강했다. PR #32 체크아웃의 전체 JS 193개와 관련 Java·Thymeleaf 렌더링 37개, 전체 작업본의 JS 256개가 통과했다.

렌더링된 실제 템플릿과 페이지 컨트롤러를 사용하고 초기 조회·전송을 모의 처리한 Chrome의 1440px·390px 화면에서 공통·쿠팡·스마트스토어 입력 Enter의 무저장, 저장 버튼에 초점을 둔 Enter·Space, 이미지 상품코드 Enter의 단일 조회를 확인했다. 실제 마켓·R2 쓰기나 운영 DB 변경은 하지 않았다.
