## 자료와 현재 앱의 범위

[패키지 README](../../marketplace-api-docs/README.md)의 11번가 수집일은 **2026-10-08**이다.
판매자 KOR 공통 API 명세 109개, 공지 240개, FAQ 26개, 가이드 8개, 공개 API 4개로 총 387개다.
109개 명세에는 판매불가처리 1638의 중복 수록이 있어 `api_seq` 기준 108개다.
387개 노트 검수 완료와 변환 누락 0은 제공 패키지의 기록이며, 이번 프로젝트 작업에서 전수 검수를 다시 실행한 결과가 아니다.
물류 API·ENG 명세·공지의 CSV/XLSX 등 첨부파일은 포함되지 않는다.

읽기 순서는 [OVERVIEW](../../marketplace-api-docs/11st/OVERVIEW.md) →
[INDEX](../../marketplace-api-docs/11st/INDEX.md) → 대상 SOURCE → 관련 FAQ·공지 SOURCE →
[KNOWN-ISSUES](../../marketplace-api-docs/11st/KNOWN-ISSUES.md)다.
원문은 `_raw/st11/api/`의 렌더링 HTML·명세 JSON과 `_raw/st11/faq/`·`notice/` 등에 있다.
소비용 `11st/`와 원문 `st11/`의 철자를 구분하며 `_outline/`을 원문으로 대신하지 않는다.

현재 코드의 채널 ID는 `ELEVENST`다. `molebutter-marketplace-elevenst`가 상품 목록·상세, 카테고리·주소·발송마감 템플릿 조회와 상품 전송 어댑터를 제공한다. 주문·브랜드 검색은 비활성이다.

`/marketplaces/elevenst/products/new`와 `/marketplaces/elevenst/products/{prdNo}/edit`는 기존 공통 상품과 같은 HTML·제어 코드를 사용한다. 공통 상품 탭의 11번가 폼도 같은 컴포넌트를 쓴다. 단독 상품은 명시적 가져오기·기존 공통 상품 연결, 사용자가 지정한 공통 옵션 UUID ↔ `prdStckNo` 대응표를 사용한다. 다른 연결 마켓은 해당 탭의 최초 클릭에서 조회한다. 임시 변경은 기존 편집 세션과 보관된 변경 저장소를 사용한다. 단독 신규 초안은 `ELEVENST_REGISTRATION`이며, 사용자 공통 상품을 자동 생성하지 않는다.

첫 쓰기 범위는 국내 고정가 새 상품의 옵션 없음·싱글 선택 옵션이다. 예약·중고·해외·계산형·작성형·추가구성 상품과 유형 미확인 상품은 조회만 지원한다. 기존 옵션 추가·삭제·이름·추가금 변경, 기존 카테고리 변경은 차단한다. **1620 공식 조회 응답에는 판매방식·상품상태·유형·주소·이미지 등 일부 필드가 없다.** 실제 응답에도 이 값이 없으면 등록 당시 입력으로 현재값을 꾸미지 않으며, 유형은 읽기 전용, 전체 수정은 보존값 미확인으로 차단한다. 전용 가격·재고·설명 수정도 먼저 지원 상품 유형을 확인한다.

서버 설정 `marketplace.elevenst.api-key`는 기존 `11st_api_key` 또는 `ELEVENST_API_KEY`에서 런타임으로 읽는다. 인증값·원본 외부 오류는 브라우저와 기록에 전달하지 않는다. 실제 연결은 고정 HTTPS 호스트 `https://api.11st.co.kr`, 리다이렉트 금지, 호출 완료 뒤 최소 1초 간격이다. 공개 카테고리 호출에는 키를 보내지 않는다. EUC-KR XML, DTD/외부 엔티티 차단, 크기 제한 응답 읽기를 적용한다.

- **인증·인코딩:** 등록 1003·수정 1619는 `openapikey` 헤더와 XML body를 명시한다. 샘플은 `text/xml`·EUC-KR이며 URL의 한글 검색어는 [FAQ 020](../../marketplace-api-docs/11st/faq/개발가이드/020-Open-API의-요청-URL에-한글-검색어를-사용하려면-어떻게-해야-하나요.md)의 UTF-8 안내를 따로 확인한다. 카테고리 1001·1617은 키가 필요 없다고 적혀 있다. 키 주입은 기존 런타임 설정을 사용한다.
- **호출 IP:** [FAQ 014](../../marketplace-api-docs/11st/faq/개발가이드/014-인증된-IP가-아닙니다.-등록된-IP-정보를-확인하십시오.-라는-리턴메시지가-나와요.md)는 API관리의 셀링툴 또는 IP 직접 입력을 안내한다. 로컬 설정에 키가 있다는 것만으로 호출 권한을 보증하지 않는다.
- **식별자·조회:** 상품 `prdNo`, 옵션 재고 `prdStckNo`, 판매자 관리코드는 분리한다. 1007의 목록은 `limit`·`start`·`end` 방식이다. 다른 마켓의 페이지 번호·토큰 규칙을 대입하지 않는다. 1876은 최대 7일·3,000건 조회를 명시하므로 주문 수집의 기간 분할과 누락 감지는 후속 설계 대상이다.
- **등록 필드:** 1003의 `Product.dispCtgrNo`는 최하위 카테고리, `prdNm`은 상품명이다. 브랜드는 `brand` 텍스트와 `apiPrdAttrBrandCd` 코드를 구분하며 코드가 텍스트보다 우선한다. 표의 필수 표시와 조건 설명을 함께 읽고 이 요약을 전체 필수 필드 목록으로 사용하지 않는다.
- **응답 판정:** 등록·수정의 `ClientMessage.resultCode`는 일반 성공 200·신규 성공 210을 설명한다. 반면 `AuthMessage.resultCode=200`은 사용자 정보 없음 오류다. HTTP 상태나 숫자만으로 성공을 판정하지 않고 XML 루트·필드·API별 의미를 함께 검사한다. `message` 설명과 코드 표의 충돌은 KNOWN-ISSUES와 실제 응답으로 확인한다.

## 이미지·수정·브랜드의 적용 주의

**상품 이미지는 파일 multipart 업로드가 아니라 XML의 URL 필드로 전달한다.**
1003·1619의 `prdImage01`은 대표 이미지, `prdImage02`~`prdImage04`는 추가 이미지다.
11번가 서버가 URL을 내려받으며 이미지 HTTP 응답의 `Content-Type`이 없으면 다운로드되지 않는다고 명시한다.
[FAQ 015](../../marketplace-api-docs/11st/faq/개발가이드/015-상품-등록-수정-요청-시-이미지-등록에-문제가-있어요.md)는 URL의 한글·공백 제거를 안내한다.
프로젝트 이미지 연결 시 소유권 검사 후 발행한 공개 URL을 사용하고, 파일 경로나 내부 blob ID를 외부 전문에 넣지 않는다.

[추가이미지 삭제 공지](../../marketplace-api-docs/11st/notices/182492053-상품수정-API-추가이미지-삭제-기능-추가-안내.md)는
`<prdImage02></prdImage02>`처럼 빈 요소를 보내면 삭제, 요소 자체가 없으면 기존 이미지를 유지한다고 설명한다.
[대표·목록이미지 통합 공지](../../marketplace-api-docs/11st/notices/195641209-상품-대표이미지-목록이미지-통합-공지-07-22.md)는
2024-07-22부터 `prdImage05`를 입력해도 반영하지 않고 대표이미지를 목록에도 사용한다고 안내한다.
확장자·최소 크기는 명세와 과거 공지가 충돌하므로 KNOWN-ISSUES를 확인하고 실계정에서 검증하기 전 허용 범위를 단정하지 않는다.

1619의 덮어쓰기 안내를 단순 PATCH로 해석하지 않는다. `optUpdateYn` 생략은 N(옵션 미수정),
출고지·반품지 주소 생략은 수정 당시 기본주소 재설정으로 설명한다. 필드별 유지·삭제·재설정 의도를 별도로 매핑해야 한다.
수정 문서의 코드 샘플은 등록용 POST를 사용하므로 Method·URL은 SOURCE의 수정 본문·URL 표를 기준으로 한다.
[FAQ 013](../../marketplace-api-docs/11st/faq/개발가이드/013-상품-등록-시-상품등록실패-상품-재고-등록-옵션개편-오류-무결성-제약-조건상품-TMALL.IX2_PD_STOCK_PTNR_INFO-에-위배됩니다-라는-메시지가-발.md)은
`colSellerStockCd` 중복을 다른 상품에서 사용된 값까지 검사한다고 안내한다.

수집한 INDEX에는 브랜드 검색 API가 확인되지 않는다. 관리 브랜드 코드는
[2024-12-18 기준 코드 공지](../../marketplace-api-docs/11st/notices/198344974-11번가-관리-브랜드-코드-업데이트-2024.12.18.md)의 CSV 첨부로 제공되지만 파일 자체는 패키지에 없다.
[2018 공지](../../marketplace-api-docs/11st/notices/107007559-11번가-관리-브랜드-목록-코드.md)의 텍스트 브랜드 검색/필터 지원 변경 예정과 현 명세의 텍스트 입력 설명도 함께 확인해야 한다.

## 앱 API와 전송 동작

- 인증된 `GET /api/marketplaces/elevenst/products`, `/products/{id}`, `/categories`, `/addressbooks?kind=outbound|return`, `/shipping-templates`, `/schema`를 제공한다. 상품 목록의 외부 POST는 읽기 요청이다. 목록은 `limit/start/end`로 조회하고 확정할 수 없는 전체 개수를 만들지 않는다.
- 등록은 `POST /rest/prodservices/product`, 가격·기본즉시할인은 `POST /rest/prodservices/product/priceCoupon/{prdNo}`, 선택 재고는 `PUT /rest/prodservices/stockqty/{prdStckNo}`(`optWght` 보존), 상세설명은 `POST /rest/prodservices/updateProductDetailCont/{prdNo}`다.
- 전체 PUT은 최신 필수값·이미지·고시·인증과 보존 가능한 응답 항목을 모두 확인한 경우에만 준비한다. 미확인 값이나 보존 불가능한 항목이 있으면 차단한다. `optUpdateYn=N`으로 옵션·재고를 제외한다. 추가 이미지 삭제는 빈 요소를 명시하며, 실행 직전에는 전체 기준값이 변경되지 않았는지 다시 확인한다.
- 공통 정상가 128,000원·최종가 87,000원은 `selPrc=128000`, `dscAmtPercnt=41000`, 원 단위 `01`, 옵션 추가금 0으로 전송한다. 조회 응답의 조건부 할인 금액·단위로 할인 여부를 확인하며 `cuponcheck`가 없어도 할인된 옵션 가격을 복원한다.
- 대표·추가 이미지는 최대 4장, 새 원본은 앱 정책 JPG·PNG 및 최소 600×600px를 검사한다. 쿠팡의 정사각형 조건을 적용하지 않는다. 상세설명은 별도 정책이다. 기존 11번가 CDN WebP는 실제 디코더로 검사한다. R2 원본과 서버 편집본 공개 URL을 XML에 사용하며, `prdImage05`는 전송하지 않는다.
- 등록 응답에서 받은 상품 ID와 서버 조회한 옵션 ID만 연결한다. 응답 유실을 판매자 코드 검색으로 복구하거나 자동 재등록하지 않는다. 승인 대기·옵션 미확인·응답 유실·반영 확인을 구분한다. 준비·실행·결과 확인은 기존 `MarketplaceSubmissions`를 사용한다.

## 연동 재검토 — 2026-10-14

실행 직전 조회·간격 대기·XML 인코딩이 실패하면 상품 요청을 보내지 않은 실패로 처리한다. 실제 dispatch 기록은 대기와 인코딩을 마치고 transport 호출 직전에 남긴다. 요청 이후 통신 실패는 계속 결과 미확인으로 유지한다. 이미지 변경 비교는 앱 UUID·자산 ID를 제외하고 공개 URL·대표 지정·전송 순서를 사용한다. 상세설명의 편집본 경로도 공개 URL로 비교한다.

[2025-09-08 공식 공지](../../marketplace-api-docs/11st/notices/201492694-11번가-OpenAPI-상품-이미지-조회방식-변경-내용-공유.md)는 저장 이미지를 WebP로 전환하여 조회한다고 안내한다. 외부 조회 URL이 전송 URL과 다르면 URL만으로 같은 이미지임을 단정하지 않는다. 나머지 선택값은 반영되었고 이미지만 자동 비교할 수 없을 때 `IMAGE_REVIEW_REQUIRED`로 판매자센터의 이미지 확인을 안내하며 자동 완료·재전송하지 않는다. 성공 응답이 실제 반영을 보장하지 않는다는 FAQ 018도 함께 확인했다.

등록·수정 응답의 업무 코드가 없거나 알려진 성공/거절 코드가 아니면 미확인으로 유지한다. `ClientMessage`의 200·210 성공과 500 거절, `AuthMessage`의 인증 거절을 구분한다. 코드 없는 등록 응답을 확정 실패로 간주하여 같은 상품을 다시 등록할 수 있게 하지 않는다.

## 등록·수정 선택값 조회 보강 (2026-10-14)

공통에서 선택한 11번가 주소가 서버의 초안 정규화에서 거부되던 누락을 수정했다. 출고지·반품지 코드가 임시 저장 후에도 유지되며 신규 입력 `addrSeqOut`·`addrSeqIn`에 적용된다. 개별 탭에서 변경한 값은 계속 보존한다. 탭에는 기존 실시간 카테고리·주소·발송마감 템플릿 조회와 함께 브랜드 검색, 택배사 선택, 원산지 지역 선택을 제공한다.

추가 읽기 전용 API는 `/api/marketplaces/elevenst/brands?name=&page=1`, `/delivery-companies`, `/origins`다. 권한은 기존 관리자 상품 조회 기준을 따른다. 택배사 115개는 1003 SOURCE의 enum, 원산지 456개는 SOURCE에 연결된 공식 `https://i.011st.com/openapi/area.xlsx`를 2026-10-14 실제로 읽은 코드다. 원산지 코드표에는 국내/해외 분류 열이 없으므로 이름·번호로 국가 구분을 추정해 자동 선택하지 않는다. 코드표 조회를 실시간 API 조회로 표시하지 않는다.

관리 브랜드는 공식 공지의 CSV 배포 방식으로 연결한다. `ELEVENST_BRANDS_FILE`로 비밀 설정 디렉터리 밖의 CSV 경로를 지정한다. 머리글은 `apiPrdAttrBrandCd,brand` 또는 `브랜드코드,브랜드명` / `brandCode,brandName`을 지원한다. UTF-8(BOM 포함)·CP949, CSV 따옴표·쉼표, 전체 목록 검색 및 100개 페이지를 지원하며 파일 변경 시 다시 읽는다. 임의 열 순서를 추측하지 않고 중복 코드의 이름 충돌·손상된 파일은 오류로 반환한다. 기존 자격 증명은 그대로 런타임 설정에서 읽는다.

파일 미설정은 `available:false`와 안내로 구분하며, 검색창에서 브랜드명을 **텍스트로 사용**할 수 있다. 공식 코드 조회로 가장하지 않는다. 공통 선택의 이름·코드는 네이티브 입력·개별값 상태에 보관하고 재진입 후 복원한다. 브랜드명을 직접 변경하면 이전 관리 코드를 지워 코드 우선 적용으로 다른 브랜드가 전송되는 것을 방지한다.
