## 통합 편집기와 명시적 상품 연결 (2026-10-13)

입력 검증은 `/api/marketplaces/editor/validate`에서 서버의 신뢰할 수 있는 조회값과 현재 변경을 합친 뒤 실제 이미지 파일을 검사한다. 쿠팡·스마트스토어의 대표·추가·상세설명을 용도별로 판정하며 오류 또는 미확인이 있으면 완료로 표시하지 않는다. 미구현 마켓은 검증 미지원이다. 입력 변경과 전송 준비 시 이전 완료 결과를 숨기며, 늦은 검증 응답은 버린다. 검증은 상품 저장·네이버 이미지 업로드를 수행하지 않는다. 전송 준비의 오류는 앱 사전 검사 결과일 수 있으며 마켓 상품 쓰기 응답과 구분한다.

공통 기준과 각 마켓의 구역 이동 메뉴(상품 정보·옵션 목록·이미지·상세설명 등)는 표시하지 않는다. 상단 공통/마켓 탭은 유지하며 각 구역의 입력과 이미지·상세설명 편집 기능도 유지한다.

공통·쿠팡·스마트스토어의 기존 등록·수정 주소는 모두 `common-marketplace-editor.html`과 `common-marketplace-editor.js`를 사용한다. 서버가 진입 목적·마켓·상품/초안 ID를 HTML 데이터 속성으로 전달하고 `/api/marketplaces/editor/entry`가 실제 계정·연결·초안 종류를 판정한다. 기존 전용 HTML·화면 제어 파일은 호환 검사 자료로 남아 있으나 실제 화면 경로에서 로드하지 않는다. 마켓 폼과 모델은 공유하고, 기존 마켓별 등록·수정 API도 유지한다.

공통 진입은 공통 기준부터, 마켓 진입은 해당 마켓부터 표시한다. 공통 연결이 없는 단독 상품과 전용 신규 초안은 해당 마켓만 활성화한다. 연결된 단독 상품은 공통 기준과 이미 연결된 마켓만 활성화한다. 다른 마켓 신규 입력은 공통 상품 경로에서 진행하며 미구현 마켓 전송은 차단한다. 전송 체크는 최초 마켓만 기본 선택한다. 기존 실행 엔진의 한 번에 한 마켓씩 확인·전송하는 절차는 유지한다.

세션의 `UNLOADED`는 연결된 UPDATE 대상의 미조회 상태다. 공통 진입은 외부 상품을 조회하지 않고, 마켓 진입은 최초 마켓만 조회한다. 다른 연결 마켓은 최초 탭 선택에서 기존 refresh API로 조회하며 탭 왕복은 재조회하지 않는다. 처리 중 저장·탭 전환을 잠그고 실패 시 입력을 유지하며 재시도를 제공한다. 임시 저장 시 미조회 대상을 CREATE로 바꾸거나 보관된 변경을 비우지 않는다. 전송 체크를 해제해도 설정된 쿠팡·스마트스토어 입력은 별도로 보관한다. 실패·세션 갱신 후 아직 저장하지 않은 다른 탭의 변경은 저장 전에 해당 대상만 다시 조회하며, 조회 실패·충돌이면 입력을 유지하고 저장을 중단한다.

단독 상품의 첫 내부 저장 후 연결 검사는 저장 응답에 사용한 최신 관찰값을 기준으로 한다. 저장 이후 실제로 외부에서 바뀐 값은 계속 충돌로 판정한다. 최초 조회가 실패한 단독 내부 초안은 재조회 성공 시 연결용 관찰 토큰도 다시 받아 가져오기·연결 버튼을 복구한다.

단독 상품의 첫 내부 저장은 `MARKET_ONLY` 초안을 만든다. 이 초안은 공통 목록에서 제외하며, 상품을 열기만 해서는 초안을 만들지 않는다. `새 공통 상품으로 가져오기`에서 내부 상품코드를 직접 입력하여 승격하거나, 기존 공통 상품을 검색하여 연결한다. 기존 `COMMON` 기록은 생성 경위를 추정해 재분류하지 않는다. 전용 신규 초안은 `COUPANG_REGISTRATION`·`NAVER_REGISTRATION`을 유지하고 옵션별 입력을 첫 옵션 값으로 합치지 않는다.

기존 공통 연결에서는 모든 마켓 옵션의 대응을 직접 지정한다. 자동 추천·이름 분해·배열 위치 매칭은 하지 않으며, 같은 공통 옵션의 중복 선택은 차단한다. 새 공통 옵션 추가는 해당 옵션만 추가하고 기존 공통 기준·다른 마켓은 보존한다. 네이버 추가금은 공통 옵션의 전체 가격으로 환산하며 네이버 입력 자체는 그대로 유지한다. 무옵션 네이버를 새 공통 상품으로 가져오면 기본 옵션 하나를 만든다.

연결 토큰은 서버 관찰값·관리자·계정·상품·10분 만료를 묶는다. 저장 전 단독 상품도 재조회할 수 있으며 옵션 UUID와 작성한 변경을 유지하고 관찰 토큰을 교체한다. 만료 토큰은 저장·연결에 사용할 수 없고 최대 24시간 동안 읽기 재조회로 새 관찰을 받는 용도로만 사용할 수 있다. 연결 확정 전에 상품을 다시 읽어 옵션 ID·채널 ID·외부 변경과 공통 revision을 확인한다. DB 트랜잭션에서 연결 중복·진행 중/결과 미확인 실행을 차단하고 옵션 UUID를 재매핑한다. 다른 공통 상품에 이미 연결된 상품의 이동·연결 해제는 지원하지 않는다. 단독 내부 초안을 기존 공통 상품으로 연결하면 보관된 변경과 상속 UUID를 이전하고 세션을 폐기한다. V40의 `marketplace_editor_history_link`로 이전 실행을 새 공통 상품에서 조회하되 실행 전문·식별자는 변경하지 않고 이전 기록의 재시도는 차단한다. 실제 마켓 쓰기는 연결 동작에 포함하지 않는다.

## 화면 흐름

2026-10-13 단독·공통 마켓 폼 공용화: 이전 배치 정리는 쿠팡의 두 렌더러를 남겨 인증 선택·구매 제한·판매기간·추가 설정의 구성이 달랐다. 이 차이는 등록·수정에 필요한 차이가 아니었다. 이제 `coupang-product-form.js`가 기본정보, 옵션 표, 이미지 카드·분류, 상세설명 카드, 상품주요정보, 인증·구비서류, 상품고시, 배송·반품과 출고 소요일 배치를 만든다. 단독 컨트롤러와 공통 컨트롤러는 같은 렌더러에 입력값과 바인딩만 전달한다. 항목 순서·선택지·설명·공통 배치는 이 파일에서 수정하며, 컨트롤러에 별도 화면을 복사하지 않는다. 쿠팡 선택값 이름도 `CoupangEditorModel.choiceNames`를 공유한다.

등록·수정은 같은 배치를 사용한다. 기존 상품의 식별자 표시, 카테고리·브랜드·구매옵션 권한에 따른 잠금은 유지한다. 공통 편집의 상속·개별값·비교·저장 절차는 별도로 유지하며, 여러 옵션의 개별 설정 대상을 고르는 제어는 공용 상품주요정보 패널 밖에 둔다. 인증 유형·번호·서류 추가와 구매 제한·판매기간 설정도 기존 옵션 UUID와 설정 경로에 기록한다. 출고 소요일은 기본 입력을 실제로 수정할 때 모든 옵션에 적용하며, 옵션별 입력은 각각의 UUID에 저장한다. 화면 재구성만으로 값을 합치거나 덮어쓰지 않는다.

스마트스토어의 두 진입 경로는 기존 `NaverProductForm` 하나를 계속 사용한다. 공통 화면에 남아 있던 과거 쿠팡·스마트스토어 대체 입력 분기를 제거했다. G마켓·옥션·롯데ON·11번가는 현재 공통 준비 입력 경로에서 관리하며 별도의 단독 폼 복사본이나 외부 전송 기능을 추가하지 않았다. 새 마켓 편집기를 연결할 때도 마켓별 공용 폼을 두 진입 경로에서 함께 사용한다. 기존 화면 주소와 저장·전송 API는 유지한다.

2026-10-13 쿠팡 입력 검증 보완: 판매기간의 체크는 한국 시간의 현재 시각과 `2099-12-31T23:59:00`을 설정한다. 공통 탭과 단독 쿠팡 화면에 제공하며, 날짜는 기존 설정 필드로 저장한다. `freeShipOverAmount`는 조건부 무료배송 기준 금액이다. 무료·유료배송의 빈 기준 금액은 서버의 유효 입력·최종 전문에서 0으로 처리하며, 화면에서 무료배송으로 전환하면 배송비·기준 금액을 함께 0으로 설정한다. 조건부 무료배송은 기준 금액을 필수로 검사한다.

공통 입력 검증도 R2 URL의 실제 객체를 읽어 JPG·PNG, 크기·용량·정사각형 조건을 확인한다. URL이라는 이유만으로 ‘규격 확인 필요’로 분류하지 않는다. 같은 검증 요청의 중복 URL은 한 번만 읽고, 규격 위반은 파일명과 실제 크기·용량을 표시한다. 삭제된 객체·R2 읽기 실패는 해당 오류를 표시한다. 기존 쿠팡 조회 원본의 같은 옵션에 포함된 CDN 이미지는 유지한다. 전송 준비와 실행 경계의 이미지 검사는 계속 수행한다.

2026-10-12 마켓 탭의 입력 배치를 단독 편집 화면 기준으로 맞췄다. 쿠팡은 같은 항목 이동 순서, 레이블·입력 행, 옵션 표의 모바일 세로 배치, 옵션별 이미지·상세설명 탭, 별도 구비서류 영역, 주소록 요약과 배송·반품 영역을 사용한다. 택배사 목록과 배치 스타일은 단독 화면과 공유한다. 스마트스토어는 기존 공용 `NaverProductForm`을 계속 사용하며 바깥 화면에도 동일한 스타일 범위를 적용한다. 공통 화면의 기준값 적용·변경 비교·전송 대상·저장 버튼은 유지한다. 쿠팡 설정의 옵션 선택은 개별 옵션 UUID를 유지하며, 배치 변경으로 모든 옵션에 값을 일괄 덮어쓰지 않는다.

판매 마켓의 공통 상품 탭에서 신규 등록 또는 저장된 초안 편집으로 진입한다. `/marketplaces/products/new`와 `/marketplaces/products/{draftId}/edit`는 같은 화면을 사용한다. `/marketplaces/coupang/products/new`는 쿠팡 전용 신규 등록 화면이며 기존 공통 초안 진입 경로도 유지한다. 쿠팡 조회 모달은 유지하고 개별 수정도 통합 화면을 사용한다. 스마트스토어는 `/marketplaces/naver/products/new`와 `/marketplaces/naver/products/{originProductNo}/edit`에서 전용 문서를 작성하며, `NAVER_REGISTRATION` 초안은 이 화면으로 재진입한다.

상단에서 공통 기준 정보 또는 마켓을 선택한다. 공통 기준과 미연동 마켓은 기본 정보·옵션 판매, 이미지·설명·고시, 배송·반품, 기타 설정의 네 구역을 사용한다. 쿠팡 입력은 아래의 상품 작성 순서로 나눈다. 공통 기준에서는 신규 등록과 명시적 공통 적용에 사용할 참조값을 입력한다. 마켓 화면에서는 연결된 상품의 최신 조회값 또는 신규 등록 입력, 카테고리와 고유 항목을 표시한다.

공통 옵션의 가격과 수량은 ‘기본 판매가·기본 판매 수량’이다. 연결된 상품에는 자동 적용하지 않고 사용자가 공통 적용을 선택한 항목만 이번 변경으로 지정한다. 기존 연결에서 변경을 취소하면 해당 세션의 관찰값으로 복원한다. 신규 대상은 공통 기본값과 마켓 개별값을 사용하며 명시적인 빈 문자열·0은 값이 없는 경우와 구분한다. 옵션과 마켓 선택을 바꿔도 입력은 유지한다. 브라우저 저장소에는 상품 데이터·연락처를 저장하지 않고 목록 복귀 상태만 보관한다.

임시 저장은 미완성 입력을 허용한다. 서버에서 구조·길이·참조를 검사하고 수정 버전을 사용한다. 같은 버전으로 다시 저장하면 충돌을 표시하며 현재 입력은 보존한다. 일반 상품·매입처 조회·보유 재고를 생성하거나 수정하지 않는다.

### 쿠팡 입력 배치 (2026-10-06)

쿠팡 탭과 쿠팡 개별 편집 페이지는 상품 정보 → 옵션 설정 → 옵션 목록 → 대표·추가 이미지 → 상세 설명 → 상품 주요정보 → 검색어 → 검색필터 → 상품정보제공고시 → 배송 → 반품/교환 순서로 표시한다. 상품 정보에서는 브랜드·노출상품명·등록상품명·카테고리를 먼저 입력하고, 제품명과 식별자 등은 추가 정보에 둔다. WING 화면은 배치 참고이며 필드 범위와 수정 제한은 Open API SOURCE를 따른다.

옵션 목록에는 품번(MPN)·정상가·판매가·재고수량·판매자상품코드를 모은다. `Manufacturer Part Number` 속성과 `modelNo` 모델번호, 판매자상품코드는 다른 항목으로 보존한다. 승인된 정상가는 읽기 전용이며 최신 가격·수량의 미확인을 0으로 표시하지 않는다. 상품 단위 수량 모드의 신규 대상은 실제 `productQuantity` 입력 하나를 사용한다. 주요정보·검색어·검색필터·고시는 선택한 옵션의 값을 편집하고 ID 연결을 유지한다.

이미지는 대표·추가 그룹을 분리하고 기존 순서·옵션 소속과 HTML 격리를 유지한다. 신규 대상이 사용하는 공통 이미지·설명은 읽기 전용으로 함께 미리보기하며 공통 기준 화면에서 수정한다. 공통 대표 이미지가 있으면 옵션에서 새로 추가한 이미지는 추가 이미지로 처리한다. 쿠팡의 이미지·설명 적용은 옵션별로 선택하며 공통 미디어 전체 적용은 선택하지 못한다. 신규 대상의 공통 미디어는 공통 기준 저장 후 세션에 반영된다. 업로드 중에는 편집 대상 전환과 재조회를 차단한다. 공통 기준 정보의 배치 개편은 이번 작업에 포함하지 않는다.

## 계약과 소유권

`MarketplaceDrafts`는 공통 편집 문서·내부 저장·검증·쿠팡 가져오기, `MarketplaceEditing`은 최신값을 읽은 편집 세션·공통 참조 저장·마켓 재조회, `media.api.ImageAssets`는 원본 이미지 업로드·인증 조회, `MarketplaceSubmissions`는 외부 저장의 미리보기·실행·결과 조회를 제공한다. app은 HTTP·Thymeleaf 화면을 소유하고 marketplace는 JDBC 초안·실행 저장을 소유하며 마켓별 검증·외부 어댑터는 marketplace-coupang·marketplace-naver, 이미지 소유권·참조·발행은 media로 분리한다. 외부 쓰기 전문을 편집 문서와 동일한 타입으로 만들지 않는다.

API는 기존 ApiResponse를 사용한다. 초안·실행 목록에는 PageResponse를 사용하고 외부 쿠팡 목록의 토큰 페이징은 변경하지 않는다. 초안·자산·전송 API와 화면은 최신 ADMIN 권한을 확인하며 내부 쓰기에는 CSRF를 적용한다. 워커는 전송 직전에 실행한 관리자의 최신 권한도 다시 확인한다. 비밀값·외부 응답 전문·파일시스템 경로는 공개하지 않는다.

초안은 `marketplace_draft`, 원본 파일 메타는 `marketplace_asset`, 참조는 `marketplace_draft_asset`에 저장한다. V31 마이그레이션이 기존 업무 테이블과 관계 없는 새 저장 구조를 만든다. 초안 ID는 문자열로 응답하고 옵션·이미지·콘텐츠는 안정적인 UUID로 연결한다. 모든 ADMIN이 저장된 초안을 편집할 수 있고 작성·수정자를 기록한다.

V32는 미리보기·실행·마켓 대상·실행 단계·시도 기록·외부 상품 연결·계정 실행 잠금·이미지 발행과 전송 참조 테이블을 추가한다. 외부 연결은 마켓·계정·상품을 구분하며 계정 식별자는 업체코드의 SHA-256 해시다. Access Key와 Secret Key는 이 테이블에 저장하지 않는다. 요청 전문과 외부 기준값은 서버의 실행 스냅샷에만 보존하고 브라우저에는 구역별 변경값과 고정된 결과 분류만 보낸다.

V33은 작성자·계정·초안 revision·외부 연결·만료 시각을 묶은 `marketplace_edit_session`, 미리보기의 세션 ID, 실행 시도의 실제 요청 스냅샷을 추가한다. 세션은 시작한 ADMIN만 사용하며 다른 ADMIN의 공통 참조 저장은 기존처럼 가능하다. 세션 만료·재조회·계정 및 연결 변경·다른 화면의 revision 변경 뒤에는 이전 확인을 실행하지 않는다. 전송 전에 병합한 실제 요청은 짧은 DB 트랜잭션에서 시도 기록에 저장하며 외부 HTTP 대기는 DB 트랜잭션 밖에서 처리한다.

## 공통 참조와 마켓 최신값

저장된 공통값은 신규 등록 기본값과 명시적으로 적용할 참조값이다. 연결된 상품의 편집 시작에서는 최신 쿠팡 상품과 옵션 현재 가격·수량을 다시 읽는다. 과거 가져오기와 공통 참조를 현재 쿠팡 값으로 대신하지 않으며, 최신 조회 실패는 수정 대상의 오류로 표시한다. 실패한 연결 상품을 신규 등록으로 바꾸지 않는다. 가격·수량 미확인은 빈 값으로 유지하며 0원·0개와 구분한다.

신규 쿠팡 대상은 공통값과 마켓 개별값을 조합한다. 기존 대상은 사용자가 선택한 `changes`만 변경 의도로 받는다. 공통 참조를 저장하는 동작은 마켓에 쓰기를 보내지 않는다. 변경되지 않은 옵션 가격·수량·이미지·고시와 다른 필드는 최신 외부 전문에서 유지하며, 전송 직전에 다시 읽은 대상값과 선택값을 병합한다. 사용자 선택 필드가 확인 이후 외부에서 달라졌으면 기존 확인을 재사용하지 않는다. 현재 어댑터가 지원하지 않는 옵션 구조·구매 속성 변경은 조용히 제외하지 않고 차단한다.

재조회는 이전 세션과 그 세션의 미리보기를 폐기한다. 새 세션도 최초 만료 시각을 유지한다. 공통 참조 저장은 같은 세션의 revision만 갱신하고 기존 연결의 당시 관찰값을 바꾸지 않는다. 신규 대상은 갱신한 공통 기본값을 사용한다. 기존 연결과 동일한 값만 선택하거나 선택 변경이 없으면 외부 작업을 만들지 않는다. 새 전송을 준비하려면 세션 ID가 필요하며, 세션이 없는 과거 확인 화면은 실행할 수 없다. 선택 변경 의도가 없는 과거 대기 작업도 쓰기를 차단하지만 기존 실행 이력과 결과 확인은 유지한다.

## 이미지와 설명

`marketplace.assets.directory`의 기본값은 `./data/marketplace-assets`다. JAR 외부 런타임 디렉터리이며 Git에서 제외한다. 배포 시 DB와 함께 백업할 영구 경로로 설정한다. 이번 구현은 배포·마운트 변경을 수행하지 않는다.

JPG·PNG 원본은 최대 10MiB·2,500만 픽셀까지 저장한다. 실제 포맷과 디코딩을 확인하며 쿠팡의 정사각형·3MiB 제약은 쿠팡 검증에만 적용한다. 파일은 UUID로 보관하고 이미지 조회는 인증 API와 no-store/nosniff를 사용한다. HTTPS URL은 그대로 입력·미리보기하며 서버는 임의 URL을 다운로드하지 않는다.

작성자는 자신이 업로드한 미저장 자산을 초안에 넣을 수 있다. 다른 ADMIN도 이미 초안이 참조하는 이미지를 사용한다. 참조 교체와 정리는 같은 자산 행을 잠가 경합을 막는다. 참조가 없는 자산만 마지막 참조 해제 또는 업로드 이후 24시간이 지나면 시간 단위의 제한된 배치로 정리한다. 공유 참조가 남으면 삭제하지 않는다.

대표·추가 순서와 옵션 소속을 보존한다. 이미지·옵션 개수 초과를 조용히 잘라내지 않는다. HTML과 IMAGE 콘텐츠는 입력 원문을 보존하고 기존 sandbox iframe·CSP 정책으로 미리보기한다. 쿠팡의 전송 변환과 다른 마켓의 이미지 업로드 계약을 공통 원본 저장과 구분한다.

## 외부 판매 이미지 경로

원본 이미지의 `/api/marketplaces/assets/{id}`는 관리자 인증 경로다. 쿠팡 다운로드용 주소로 이 경로나 브라우저의 blob 주소를 보내지 않는다. 서버는 저장된 초안이 참조하는 자산에 한해 예측하기 어려운 64자리 토큰을 발급하고 별도의 `GET /marketplace-images/{token}` 경로로 이미지 바이트를 제공한다. 자산 ID·저장 경로·상품 데이터·연락처를 응답에 포함하지 않는다. 원본 관리 API의 권한을 완화하지 않는다.

`marketplace.assets.public-base-url`은 `MARKETPLACE_PUBLIC_IMAGE_BASE_URL` 환경 변수로 설정한다. 인증서와 외부 접근이 가능한 HTTPS 주소를 사용하며, 요청의 Host나 전달 헤더에서 자동 생성하지 않는다. 값이 없으면 로컬 자산의 외부 전송을 차단한다. 프로젝트의 prod 프로필은 HTTPS 프록시 신뢰 정책만 제공하며 인증서·공개 DNS·프록시 배포를 만들지 않는다. 이 단계에서 배포 설정이나 실제 공개 주소의 도달 가능성을 검증하지 않았다.

공개 주소는 실제 전송 이미지에만 사용한다. 이미지는 쿠팡이 비동기로 내려받을 수 있으므로 전송 실행이 있는 스냅샷의 자산 참조를 유지한다. 실행하지 않은 미리보기는 만료 후 24시간이 지난 뒤 시간별 배치에서 전송 참조를 해제하며, 실제 초안과 다른 실행의 참조가 없을 때만 원본 정리 정책이 적용된다. 보관 디렉터리와 DB를 함께 백업한다. 직접 입력한 HTTPS 이미지 URL은 서버가 임의로 다운로드하지 않으며 형식 확인과 쿠팡의 실제 다운로드 성공을 구분한다.

## 외부 저장 미리보기와 실행

임시 저장은 내부 초안만 저장한다. 마켓 저장은 초안 ID·revision·편집 세션과 사용자가 선택한 마켓별 변경값을 기준으로 작업을 준비한 뒤 확인 화면을 연다. 쿠팡 신규 등록·승인 필요 수정은 저장 뒤 판매 승인을 순차적으로 요청하며 별도 승인 선택은 제공하지 않는다. 화면에는 대상 마켓·신규/수정·변경 내용·실행 단계·오류를 표시하고 외부 요청 전문이나 인증 값을 전달하지 않는다.

미리보기는 10분 동안 유효하며 초안 버전을 포함한다. 변경되거나 만료된 미리보기로 실행하지 않는다. 실행에는 멱등 키를 사용하고 결과를 서버에 기록한다. 같은 확인 요청의 응답을 잃어도 같은 키로 조회·재확인하며 새 실행을 중복 생성하지 않는다. 마켓·상품·옵션별 외부 ID와 실행 단계는 서버에서 관리한다. 상품 정보, 배송·반품, 옵션 현재 가격과 판매 수량은 서로 다른 쿠팡 요청으로 나누며 중간 실패로 앞선 외부 변경을 되돌린 것처럼 표시하지 않는다.

| 상태 | 의미와 후속 동작 |
|---|---|
| `QUEUED` / `RUNNING` | 대기 / 처리 중. 화면은 진행 중인 이력을 2초 간격으로 조회 |
| `SUCCEEDED` | 준비한 변경의 반영을 확인. 최종 판매 승인과 구분 |
| `ACCEPTED` | 요청 접수 후 반영 확인 필요. `결과 확인` 제공 |
| `PARTIAL` | 일부 단계 완료. 성공 단계 유지, 실패와 미확인 단계 구분 |
| `FAILED` | 확인된 거절·실패. 조건을 다시 확인한 뒤 실패 작업 재시도 |
| `UNKNOWN` | 응답 유실·중단 등으로 결과 미확인. 쓰기 재시도 대신 `결과 확인` 제공 |

접수는 최종 판매 승인이나 전체 변경 확인과 같지 않다. 결과 미확인을 자동 성공·실패로 확정하거나 신규 등록을 반복하지 않는다. `ACCEPTED` 또는 `UNKNOWN` 단계가 남으면 같은 상품의 다음 쓰기를 대기하고 읽기 확인만 허용한다. 반영을 확인한 뒤 아직 대기 중인 단계를 진행한다. 재시도는 확인 가능한 실패 단계만 대상으로 하며 이미 성공한 단계는 다시 실행하지 않는다. 초안 버전·계정·외부 기준값이 달라졌으면 새 미리보기가 필요하다. 워커 중단 뒤 실행 결과가 불명확한 단계도 미확인 상태로 복구해 신규 등록을 반복하지 않는다.

확정 실패한 실행에는 `입력 수정`을 제공한다. 기존 성공·실패 이력과 작성 중인 입력은 유지하고 `/revise`로 아직 실행하지 않은 단계만 종료한 뒤 새 변경 확인을 준비한다. 초안 버전이 바뀌어 기존 재시도가 불가능해도 이 경로를 사용할 수 있다. `UNKNOWN`·`ACCEPTED`·실행 중인 단계가 있으면 입력 수정으로 잠금을 해제하지 않는다.

`marketplace.submissions.worker-enabled`의 기본값은 `true`다. 실행을 접수한 뒤 계정별 잠금을 사용해 한 단계씩 처리한다. 자동 재전송은 실제 HTTP 429에 대한 제한된 한 번만 허용하며 인증 실패·타임아웃·5xx·잘못된 성공 응답은 맹목적으로 반복하지 않는다. 공통 편집기에서 쿠팡·스마트스토어는 각각 별도의 마켓 연결과 관찰값으로 준비한다. 한 확인·실행에는 한 마켓만 지정한다. G마켓·옥션 등 미연동 문서를 전송 대상으로 지정하면 차단한다. 아직 실제 5개 마켓 분산 전송·계정별 어댑터와 결과 분리가 완성된 것은 아니다. 상세한 쿠팡 요청과 공식 근거는 [쿠팡 쓰기 규격](coupang-wing.md#쿠팡-쓰기-규격-대조-2026-10-06)을 따른다.

## 마켓별 검증과 가져오기

공통의 판매가는 옵션별 목표 판매가이며 정상가는 별도 참조값이다. 기본 판매 수량은 신규 등록과 명시적 공통 적용을 위한 참조값이며 연결된 상품의 현재 수량과 구분한다. 실제 판매 옵션과 서비스 선택지, 상품 공통 수량과 옵션별 수량도 구분한다. 미확인 값은 0으로 바꾸지 않고 판매 수량을 보유 재고로 취급하지 않는다.

쿠팡은 카테고리 메타정보를 읽어 필수·그룹 속성·고시·인증 등의 조건을 확인한다. ESM은 문서 기반 형식과 입력을 확인하되 계정·카테고리별 동적 규격 확인은 미연동으로 남긴다. 스마트스토어 공통 탭과 전용 화면은 네이버 카테고리·브랜드·고시·인증·속성·주소록 조회와 전용 저장 검증을 사용한다. 검증 결과의 errors와 unverified를 구분하고 규격 미확인을 외부 등록 가능으로 표시하지 않는다. 마켓별 상태에는 오류·문서 검증·규격 확인 필요를 표시한다.

네이버는 원상품 설정과 스마트스토어 채널 상품명을 구분하고 쇼핑 등록 여부·채널 전시 상태를 보존한다. 정적 가격·수량 제한은 [원상품 SOURCE](../../marketplace-api-docs/naver/schemas/원상품.md), 채널 필드는 [스마트스토어 채널상품 SOURCE](../../marketplace-api-docs/naver/schemas/스마트스토어-채널상품-정보-구조체.md), ESM 가격·수량·이미지 규격은 [020 상품 API SOURCE](../../marketplace-api-docs/esm/api/상품API/상품관리-API/020-상품등록-수정-전환-조회-API.md)를 따른다. ESM 반품 주소번호는 반품·교환 주소를 가리키며 자체 반품 정책 ID로 해석하지 않는다.

쿠팡 가져오기는 버튼으로 명시적으로 실행한다. 계정·상품 일치 확인 후 편집 초기 데이터를 내부 초안에 보존한다. 외부 상품·옵션 ID와 수정 제한을 서버에서 유지하고 같은 계정·상품을 중복 가져오면 기존 초안을 반환한다. 가져온 값을 다른 마켓에 자동 반영하거나 쿠팡에 저장하지 않는다. 원문 JSON 대신 기존의 한정된 편집 DTO를 보존한다.

검색어(`items[].searchTags`)는 각 옵션의 등록 설정에 한 번만 보존한다. 추가 옵션 설정을 합칠 때 검색어를 다시 넣거나 상품·배송 설정에 옮기지 않는다. 선택 변경 비교는 전송할 검색어 배열을 기준으로 하므로 쉼표 뒤 공백 차이만으로 재전송하거나 외부 변경 충돌로 처리하지 않는다.

## 초안 편집 단계 검증

2026-10-06 가짜 자료·격리된 DB·로컬 이미지·모의 외부 응답으로 구조/저장/권한/규격/화면 흐름을 검증했다. Java 단위·경계 297개, JS 79개, 선택 통합 24개와 데스크톱·모바일 대표 흐름을 통과했다. 실제 계정의 등록·수정은 실행하지 않았다. 실행 범위와 명령은 [testing 문서](../testing.md#공통-판매-상품-편집-검증)에 기록했다.

## 외부 전송 단계 검증

합성 API로 전송 확인 화면과 실행 이력의 1440px·390px 흐름을 검증했다. 미리보기 취소 시 무전송, 실행 중 중복 제출·닫기 차단, 부분 완료 후 성공 단계 보존, 실패 재시도, 미확인 결과 확인, 응답 유실 후 같은 멱등 키 재확인, 미연동 마켓 차단과 이력 페이지 이동을 확인했다. 내부 옵션 UUID를 옵션명으로 바꾸고 변경 항목을 한국어로 읽을 수 있는지 확인했다. 공통 편집과 기존 쿠팡 개별 편집도 두 화면 크기에서 다시 통과했고 JS 83개를 통과했다. 실제 계정의 상품 등록·수정이나 공개 이미지 도달 가능성은 이 모의 검증으로 확인하지 않았다. 실행 명령과 서버 검증 결과는 [전송 검증 문서](../testing.md#판매-마켓-전송-검증)에 기록한다.

편집 세션 추가 전 전송 단계에서 Java 단위·모듈 경계 330개를 통과했다. 당시 선택 통합 검증은 39개 중 35개를 통과하고 명시적인 실제 계정 읽기 4개를 비활성화했다. 전송·공통 편집·쿠팡 개별 편집·요청 취소·상품 UI의 5개 브라우저 스크립트는 각각 1440px·390px에서 통과했다.

## 편집 세션과 선택 변경 검증

2026-10-06 최신 관찰값과 공통 참조를 분리한 뒤 전체 Java 단위·모듈 경계 353개, JS 100개, 편집 세션·전송·초안·업그레이드의 격리 DB 통합 34개를 통과했다. Java에는 쿠팡 선택 변경 33개, 실행 서비스 20개와 과거 JSON 호환 2개가 포함된다. 공통 편집은 1440px·390px에서 localhost와 일반 LAN HTTP 모두, 전송 UI는 일반 LAN HTTP 두 크기에서 통과했다.

현재 값 각각의 null/0 구분, 선택한 가격만 실행, 선택 변경 없음의 무전송, 최신 조회 실패 및 옵션 식별자 변경 차단, 작성자·revision·만료·재조회 뒤 이전 확인 차단을 확인했다. 설명만 수정할 때 준비·실행 모두 추가 재고 조회와 가격·수량 요청이 없으며, 현재값이 미확인인 항목의 변경은 차단한다. 선택한 현재값의 재검증에서는 미선택 값이 누락돼도 0으로 대체하지 않는다. 동시 신규 등록 한 건만 접수, 접수 후 읽기 확인까지 다음 쓰기 대기, 실제 요청의 서버 한정 기록, 생성된 연결의 재가져오기 중복 방지도 포함한다.

공통 참조 저장과 전송 접수의 동시 처리, 신규 쿠팡 옵션 기본 설정, 실제 쓰기 전문을 재사용한 결과 확인도 검증했다. V31·V32의 공통 JSON·외부 연결·미리보기·미확인 실행 기록·이미지 참조가 V33에서도 보존되고 과거 문서를 현재 타입으로 읽을 수 있는지 확인했다. 실제 계정 쓰기는 실행하지 않았다. 상세 명령과 범위는 [현재 검증 기록](../testing.md#최신-조회-편집-세션과-선택-변경-검증)을 따른다.

2026-10-07 쿠팡 단독 수정 화면도 동일한 편집 세션·미리보기·실행·재시도·결과 확인 엔진을 사용한다. 단독 화면은 관찰 토큰을 전달하고 첫 준비에서 내부 초안 연결을 생성하거나 재사용한다. 공통 입력 저장 없이 별도 관찰값과 선택 변경만 전송하므로 기존 공통 참조를 보존한다. ORIGINAL_PRICE 단계를 추가했고 과거 Image JSON은 type 누락을 허용하는 호환 생성자로 읽는다. 승인 대기 상품 정보는 마지막 단계에 배치한다. 상세 계약은 [쿠팡 화면 안내](coupang-wing.md#단독-수정-화면-실제-저장-연결-2026-10-07)를 따른다.


### 2026-10-07 기존 공통 편집기 신규 등록 점검

기존 공통 편집기 `/marketplaces/products/new?market=COUPANG`에서도 신규 등록할 수 있다. 공통 기준에서 상품·옵션·이미지·설명·배송 기본값과 검색한 브랜드를 입력하고 `공통 기준 저장`으로 내부 초안을 만든 뒤 쿠팡 탭의 카테고리 규격·필수 속성·고시·인증·서류 등을 완성한다. 공통 기준 저장은 외부 등록이 아니다. `마켓에 저장`은 세션의 선택 변경을 서버에서 검증해 확인 창을 준비하며, 확인 후 신규 상품 CREATE POST 한 번을 전송한다. 기존 승인 옵션의 전용 가격·재고 수정 단계와 구분한다.

2026-10-14부터 쿠팡의 별도 승인 체크박스를 제거했다. `쿠팡에 저장`을 누르면 `requested=false`로 저장한 뒤 별도 APPROVAL PUT을 수행한다. 가격·재고·배송 전용 수정은 승인 요청을 추가하지 않는다. 요청 접수 및 상품 ID 확보와 판매 승인완료를 분리했으며 승인 요청한 신규 상품은 실제 승인 상태 확인 전까지 ACCEPTED로 남는다. 응답 유실 복구도 연결 ID를 확보한 뒤 승인 대기를 보존한다. 결과 확인은 실행 기록의 결과 확인 기능을 사용한다.

확인된 결함을 보완했다: 구매 옵션 조합 중복과 자동 가격 최소가 조건을 입력 검증·최종 CREATE 구성에서 함께 검사한다. 검색필터 NONE는 구매 조합 비교에서 제외한다. 카테고리 조회 자동 입력은 전송 변경에 기록한다. 고시 유형을 변경하면 선택한 유형의 필드만 보이고 전송한다. 이전 유형 값은 유형 변경 시 교체된다. 가격·재고 증감 화살표는 신규 공통 화면에서도 제거했다.

기존 공통 편집기는 공통 입력 구조를 유지한다. 그 경로에서 옵션 추가는 공통 기준 탭에서 하며, 쿠팡 입력은 해당 탭에서 확인한다. 신규 등록에 대한 실계정 실행 검증은 아직 하지 않았다.


### 쿠팡 전용 신규 등록 화면

`/marketplaces/coupang/products/new`는 기존 개별 수정 컴포넌트를 사용한다. 브랜드 선택·카테고리 규격 조회, UUID 기반 옵션 추가·삭제와 구매 속성 기반 옵션명, 옵션별 이미지·설명 및 공통 주요정보·검색·고시·배송·반품 입력을 제공한다. 카테고리 변경 전에 제외되는 값에 대해 확인하고 동일 규격 항목 값만 유지한다.

`/api/marketplaces/coupang/product-registrations/drafts`의 POST, GET `/{id}`, PUT `/{id}`, POST `/{id}/prepare`로 내부 초안을 생성·조회·버전 저장·전송 준비한다. 입력에는 외부 상품·옵션 ID와 원본 응답을 허용하지 않는다. 초안은 작성자·쿠팡 계정에 묶이며 `editor_kind=COUPANG_REGISTRATION`으로 목록에서 전용 화면으로 재진입한다. V37은 기존 초안에 `COMMON`을 기본 적용한다. 공통 편집기 저장은 전용 초안을 덮어쓰지 못한다.

임시 저장은 불완전한 입력도 보관하며 외부 등록을 수행하지 않는다. 저장은 필수 검증 및 자산 업로드 완료 후 초안 저장과 확인 창을 준비한다. 쿠팡 신규 저장은 CREATE POST(`requested=false`)와 APPROVAL PUT 두 단계로 준비한다. 확인 전 외부 쓰기는 없다. 두 단계 모두 기존 실행 엔진의 계정 잠금·호출 간격·429 정책·중복 방지·결과 확인을 재사용한다. 응답 유실 시 동일 요청 키로 접수를 확인하며 새로고침 후 실행 기록을 불러온다. 등록 ID 연결 및 승인 대기 후에는 신규 POST를 막고 결과 확인·기존 상품 수정 화면 링크를 제공한다.

신규 화면의 공통값은 첫 옵션의 공통 주요정보·검색필터·선택 고시·인증을 서버에서 모든 옵션에 복사한다. MPN·GTIN·구매 속성·이미지·설명은 해당 옵션 UUID로 유지한다. 업로드 자산은 기존 서버 자산 기능으로 실행 시 공개 HTTPS URL을 확보하며 `blob:`는 저장·전송에서 거부한다. 실제 판매 상품 신규 등록은 별도 실행 요청 전까지 수행하지 않는다.

### 공통값 상속과 마켓별 준비 입력 (2026-10-09)

신규 쿠팡 탭은 공통 기준을 저장하기 전에도 입력한 기본값을 즉시 표시한다. 상품명·브랜드·옵션 UUID별 이름·판매자상품코드·판매가·재고, 공통 이미지·설명과 배송 입력을 신규 문서에 투영한다. 쿠팡 탭에서 직접 바꾼 항목은 이후 공통값 변경과 첫 임시 저장·세션 생성에도 유지한다. 명시적인 빈 문자열·0도 개별값으로 처리하며, 삭제한 옵션의 개별 변경은 제거한다. 연결된 기존 상품은 계속 최신 조회값을 사용하고 명시적으로 선택한 공통 적용만 변경한다.

신규 공통 구매 속성은 같은 이름의 쿠팡 구매 속성(`EXPOSED`)에 연결하며 검색 속성(`NONE`)은 보존한다. 카테고리 코드·브랜드 ID처럼 마켓별로 다른 코드는 서로 복사하지 않는다. 공통 이미지·설명의 상속은 화면 전환 때 바로 보이며 저장·전송은 기존 자산 검증과 서버 요청 구성 절차를 따른다.

스마트스토어 탭에 브랜드명·브랜드 ID·검색 버튼을 제공한다. 기존 관리자 API `GET /api/marketplaces/naver/metadata/brands?name=`가 공식 `GET /external/v1/product-brands?name=`를 호출하며 `{id, name}` 목록을 반환한다. `int64` ID는 브라우저의 정수 정밀도 손실을 막기 위해 문자열로 전달한다. 검색 결과 선택은 `markets.NAVER.overrides.brand`와 `markets.NAVER.naver.brandId`에 보관하며, 브랜드명을 직접 바꾸면 네이버 ID를 해제한다. 쿠팡 ID는 별도 설정에 유지한다. 인증·호출 간격은 기존 네이버 gateway를 사용하고 브랜드 검색의 404는 빈 목록으로 처리한다. ### 통합 브랜드 선택 (2026-10-09)

공통 기준 정보에는 공통 브랜드명과 브랜드 검색 버튼을 둔다. 검색창 하나에서 같은 검색어로 쿠팡·스마트스토어·롯데ON을 조회하며 각 마켓의 후보·기존 선택·오류를 구분해 표시한다. 검색 결과를 자동으로 확정하지 않고 사용자가 마켓마다 적합한 이름·ID를 직접 선택한다. 쿠팡의 다음 페이지 조회도 다른 마켓의 선택을 유지한다. 롯데ON은 항상 최대 100개 조회 제한과 검색어를 구체화하라는 안내를 표시한다.

검색·후보 선택·선택 해제는 확인 창 내부의 임시 상태다. `선택한 브랜드 적용`을 눌러야 공통 입력에 반영되며 취소·닫기·Esc는 문서를 바꾸지 않는다. 검색 실패가 다른 마켓의 선택을 지우지 않고, 닫거나 새 검색을 시작한 뒤 도착한 이전 응답은 반영하지 않는다. 기존 선택은 직접 바꾸거나 해제할 때까지 유지한다. 연결된 쿠팡 상품은 검색·해제를 잠그고 기존 브랜드를 보존한다.

공통 브랜드명은 판매자가 사용하는 기준 이름이고 마켓별 선택 이름은 해당 API가 반환한 정확한 이름이다. 예를 들어 공통 이름 `닥스`와 마켓 결과 `DAKS`를 같은 필드로 덮어쓰지 않는다. 공통 이름만 변경할 때 그 이름을 상속하던 선택 ID는 해제하고, 정확한 개별 이름과 함께 저장한 선택 및 잠긴 쿠팡 브랜드는 보존한다.

| 마켓 | 선택 이름의 내부 저장 위치 | 선택 ID의 내부 저장 위치 |
|---|---|---|
| 쿠팡 | `markets.COUPANG.overrides.brand` | `markets.COUPANG.coupang.settings.brandId` |
| 스마트스토어 | `markets.NAVER.overrides.brand` | `markets.NAVER.naver.brandId` |

브랜드 ID는 서로 복사하지 않으며 스마트스토어 `int64`도 문자열로 보관한다. 기존 쿠팡 개별 선택을 통합 창의 기존 선택에 표시하고 신규 쿠팡 문서에도 같은 이름·ID 쌍을 투영한다. 내부 초안 저장은 기존 revision 검사를 사용한다. 선택 적용 자체는 외부 상품 저장이 아니며 다른 마켓의 준비값을 부분적인 네이버 전용 `editorInput`이나 쿠팡 ID로 변환하지 않는다.

G마켓·옥션은 ESM 공용 브랜드 검색 준비 상태이며 추가 JWT 인증 설정이 필요하다. 사이트별 탭과 전송 결과는 계속 분리한다. 11번가는 수집 범위에 브랜드 검색 API가 확인되지 않았고 공지의 브랜드 코드 첨부파일도 없어 검색 요청을 만들지 않는다. 등록의 텍스트·코드 입력 계약과 검색 연결 여부는 [11번가 안내](11st.md)에서 구분한다. 롯데ON은 조회 ID 길이 12와 등록 `brdNo` 길이 7의 차이를 해결하기 전까지 선택값을 등록 가능 코드로 보증하지 않는다. 실제 계정 호출·상품 등록 검증은 별도다.


## 스마트스토어 공통 폼·원자 임시 저장 (2026-10-09)

공통 상품의 스마트스토어 탭과 전용 신규·수정 페이지는 `NaverProductForm`을 함께 사용한다. 상품 정보 → 가격·옵션 → 이미지 → 상세설명 → 상품주요정보 → 인증정보 → 검색어 → 검색필터 → 상품고시 → 배송 → 반품·교환 순서와 주소록·규격 조회·고시 선택·이미지 업로드 동작이 같다. 상세설명 미리보기는 PC 480px·모바일 360px이다. 각 호스트의 ID와 조회·팝업·업로드 상태는 분리한다.

- 신규 대상은 공통명·판매자 상품코드·선택한 마켓 브랜드·제조사·모델·A/S 안내 등 지원하는 공통값을 상속한다. 공통 옵션 UUID를 네이버 조합 행에도 유지하고 옵션명은 하나의 속성축으로 시작한다. 행 추가·삭제는 공통 기준에서 수행하며 스마트스토어 탭은 속성명·값·추가금·재고를 편집한다.
- 공통 옵션의 절대 판매가 중 최소값은 네이버 기본가, 각 차이는 추가금이다. 가격을 직접 바꾸면 가격 묶음 전체가 개별값으로 전환된다. ‘공통 가격 다시 적용’으로 다시 계산할 수 있다. 공통 재고 모드가 PRODUCT이고 옵션이 여러 개면 각 옵션의 수량을 직접 배분해야 한다.
- 이미지·설명은 서로 독립적으로 공통 입력 또는 옵션 UUID를 선택한다. 공통 미디어가 없으면 첫 옵션을 자동 선택하지 않는다. 원본 옵션이 사라졌거나 출처가 없으면 원본 재선택 또는 ‘현재 편집값 유지’가 필요하다. 업로드 중/실패 파일이 남으면 전송 준비를 막고 입력·파일을 보존한다.
- 연결된 상품은 네이버 최신 조회값이 기준이다. 공통값 수정만으로 덮어쓰지 않으며 ‘공통값 적용’으로 선택한 항목만 변경한다. 그룹상품·비지원 옵션·비지원 고시 제한, 수정하지 않은 필드와 상세설명 보존은 전용 화면과 같다.

네이버 설정의 `editorInput`과 버전 1 `editorState`는 타입이 있는 화면 입력과 상속 상태다. 기존 준비 입력·속성·고시 등은 삭제하지 않고 미매핑 안내를 보존한다. 원산지 자유문구나 쿠팡 주소번호를 네이버 코드로 추정하지 않는다. `editorInput`만 있는 과거 초안은 기존 개별값을 유지한다. COMMON 초안은 네이버 가져오기 상품이어도 공통 편집기로 재진입하고 NAVER_REGISTRATION 초안은 전용 화면으로 진입한다.

`PUT /api/marketplaces/edit-sessions/{id}/draft`는 `{reference, targets}`를 받아 공통 기준과 쿠팡·네이버 임시 변경을 한 트랜잭션에 저장하고 `{reference, session}`을 반환한다. revision과 마켓별 서버 바인딩을 검사한다. UPDATE의 최초 관찰값·옵션 연결·변경값은 별도 임시 변경 저장소에 보관한다. 재진입 때 최신값과 세 방향으로 비교하고 처음 조회값·최근 조회값·내 변경값을 표시한다. 충돌은 ‘최신값 사용’ 또는 ‘내 변경 다시 적용’으로 해결하며 후자는 `resolvedConflicts`의 경로·옵션 키로 명시 확인한다. 충돌을 확인하지 않은 임시 저장으로 전송 제한을 우회할 수 없다. 최신값이 이미 원하는 값이면 그 임시 변경을 정리한다.

저장은 기존 `MarketplaceSubmissions`를 사용한다. 신규는 네이버 CREATE POST, 연결 상품은 UPDATE PUT으로 구성하며 쿠팡 승인 요청 설정을 적용하지 않는다. 결과 미확인·반영 대기는 기존 실행 잠금을 유지하고 결과 확인으로 처리한다. 결과에서 확보한 원상품 번호로 전용 수정 화면을 열 수 있다. 실제 마켓 쓰기는 별도 실행 요청이 있을 때만 수행하며 이번 구현 검증은 모의 응답과 격리 DB로 제한한다.

### 마켓별 브랜드 유지와 변경 비교 (2026-10-10)

쿠팡 신규 탭의 브랜드 선택은 공통 브랜드 검색어와 다른 마켓 선택을 수정하지 않는다. 브랜드명·ID는 탭 재구성 시 함께 복원하며, 임시 저장에는 공통 기준과 분리한 마켓별 변경 기록을 사용해 재진입 값을 보관한다. 외부 변경 경로와 API 계약은 유지한다.

변경 내역은 신규 대상의 최신 공통 투영값과 마켓 적용값을 비교한다. 기존 상품은 조회값과 적용값을 비교한다. 브랜드명과 ID는 한 행으로 표시하고, 설정 배열의 다른 변경은 달라진 하위 항목별로 표시한다. 브랜드 취소와 설정 한 항목 취소는 다른 설정을 보존한다. 묶음 변경에 외부 충돌이 남아 있으면 일부 항목 취소만으로 확인 잠금을 해제하지 않는다. 빈값·0을 구분하며 긴 값은 펼쳐보기로 확인한다. 모바일은 비교값을 세로로 표시한다.

스마트스토어도 브랜드명·ID 변경을 ‘브랜드’ 한 행으로 묶어 비교하고 함께 취소한다. 이름만 또는 ID만 다른 경우도 한 쌍으로 표시한다. 취소 시 두 필드의 개별 상속 설정을 함께 해제하며 다른 상품 입력은 보존한다. 공통·전용 화면이 공유하는 스마트스토어 폼의 브랜드명·ID 입력은 읽기 전용이며 검색 결과 선택으로만 변경한다. 검색창의 검색어는 계속 직접 입력할 수 있다. 외부 전송은 기존 두 필드 변경 경로를 유지한다.


### 개별 입력과 상속 상태 저장 (2026-10-10)

- 모든 탭의 임시 저장은 공통 기준과 편집 가능한 쿠팡·스마트스토어 입력을 함께 저장한다. 신규 초안은 최초 생성 후 편집 세션을 열고 동일한 저장 API를 사용하며, 이후 저장이 실패해도 확보한 초안 ID와 화면 입력을 유지한다.
- 쿠팡 CREATE의 모든 허용 변경은 `marketplace_draft_target_edit`에 보관한다. 변경 키의 존재가 개별값을 뜻하며, 최신 공통값과 같아져 변경 비교에 나타나지 않는 개별값도 저장한다. 설정·배송 설정·옵션 등록 설정은 하위 필드별 키로 상속을 분리한다. 공통 입력·다른 마켓을 덮어쓰지 않는다. 카테고리는 신규 대상에서만 변경을 허용한다.
- 스마트스토어는 `editorInput`과 `editorState`를 함께 보관한다. 재진입 시 개별 입력을 복원하고 비교 기준은 새 공통 투영으로 구성한다. 변경 취소는 입력과 해당 필드·묶음의 개별 상속 표시를 함께 복원하며, 폼도 즉시 다시 표시한다.
- 쿠팡 UPDATE도 네이버와 동일하게 최초 서버 관찰과 변경을 보관한다. 다시 조회할 때 외부 변경을 확인하며, 저장된 변경을 화면에서 취소하고 재조회해도 취소한 값이 다시 나타나지 않는다. 승인·응답 미확인 잠금은 기존 정책을 따른다. CREATE 기록은 서버의 등록 완료 revision이 확인된 뒤 정리한다.
- 마켓에만 추가한 업로드 이미지도 초안 자산 참조에 포함한다. 공통 기준 저장으로 정리 대상이 되지 않으며 변경 취소 후 참조를 해제한다. 임시 저장은 외부 마켓 쓰기를 실행하지 않는다.

공통 상품명은 쿠팡 신규 등록의 등록상품명과 노출상품명에 함께 상속된다. 제품명은 별도 필드로 유지하며, 쿠팡에서 직접 수정한 각 상품명은 공통값 변경이나 탭 이동으로 덮어쓰지 않는다.

쿠팡 신규 등록의 판매자상품코드는 공통 옵션별 판매자상품코드만 상속한다. 공통 상품코드를 대신 채우지 않으며 옵션 코드가 비어 있으면 빈값으로 유지한다. 쿠팡에서 개별 수정한 판매자상품코드(명시적 빈값 포함)는 공통값 변경·탭 이동·임시 저장 후 재진입에도 유지되며, 변경 취소 시 최신 공통 기준을 다시 상속한다. 기존 등록상품의 판매자상품코드는 조회값을 유지한다.

### 공통 카테고리 선택

공통 기준 정보의 ‘카테고리 검색’은 같은 검색어로 쿠팡·스마트스토어 목록을 검색하고 마켓별로 따로 선택한다. 선택 적용은 내부 입력만 변경하며 외부 등록·수정 요청을 보내지 않는다. 쿠팡은 `GET /api/marketplaces/coupang/categories`가 공식 전체 카테고리 트리에서 ACTIVE 종단 항목을 전체 경로와 함께 반환한다. 기존 인증·계정 호출 간격·429 대기·취소 처리를 재사용한다. 스마트스토어는 기존 `GET /api/marketplaces/naver/metadata/categories?last=true`를 사용한다. 결과는 대화창 안에서 캐시하고 검색어·코드로 필터링하며 200개 초과 시 검색어를 좁히도록 안내한다.

마켓별 선택 코드는 `markets.{market}.categoryCode`에 저장한다. 탭에서 직접 수정한 값은 기존 개별 변경 상태로 유지하며 임시 저장·재진입 후에도 복원한다. 네이버 `leafCategoryId`는 개별 수정 표시가 없는 경우 최신 공통 선택 코드를 상속한다. 연결된 기존 상품의 공통 카테고리 선택은 잠그고, 등록 전에는 각 탭에서 새 규격·필수 구매 속성·고시·인증을 확인한다. G마켓·옥션·롯데ON·11번가의 통합 카테고리 검색은 연결 준비 중으로 표시한다.

근거: [쿠팡 카테고리 목록 SOURCE](../../marketplace-api-docs/coupang/api/categories/how-to-get-category-list.md), [네이버 전체 카테고리 SOURCE](../../marketplace-api-docs/naver/api/product/get-v1-categories.md). 실제 계정 호출 검증과 구분한다.

공통 상품명은 스마트스토어 신규 등록의 원상품명(`originProduct.name`)과 노출상품명(`smartstoreChannelProduct.channelProductName`)에 함께 상속한다. 스마트스토어에서 직접 수정한 각 이름은 별도 편집 상태로 유지되며 공통값 변경·탭 이동·임시 저장 후 재진입에서도 덮어쓰지 않는다.

### 공통 정상가와 판매가 분리 (2026-10-12)

공통 옵션은 옵션명·판매자 상품코드·정상가·판매가·수량을 한 행으로 표시한다. 내부 옵션의 기존 `price`는 판매가로 유지하고 선택 필드 `originalPrice`를 정상가로 추가했다. 기존 초안은 정상가를 빈 값으로 읽으며 기존 판매가를 정상가로 재해석하지 않는다. DB 구조 변경 없이 초안 JSON에 저장한다.

신규 쿠팡 대상은 정상가를 `originalPrice`, 판매가를 `salePrice`로 매핑한다. 쿠팡 개별 정상가·판매가 수정은 기존 변경·상속 관리로 보존한다. 기존 상품에는 공통값 저장만으로 자동 적용하지 않고 명시적 적용과 기존 수정 경로를 사용한다.

브라우저와 서버는 같은 계산으로 저장·전송 전문을 구성한다. 스마트스토어에서 공통 가격 상속 시 정상가가 있으면 공통 정상가 최댓값과 현재 스마트스토어 판매가 중 큰 값을 기본 판매가로 사용한다. 즉시할인은 사용자 입력을 유지하며 옵션 추가금을 `공통 옵션 판매가 − (기본 판매가 − 설정한 즉시할인액)`으로 계산한다. 정액·정률 모두 적용한다. 정상가가 모두 비어 있는 기존 초안은 기존 최소 판매가 기준을 유지한다. 직접 바꾼 옵션 추가금은 개별 가격 상태로 보존한다. 신규 등록에서 즉시할인 금액 또는 단위를 변경하면 현재 판매가와 공통 옵션 판매가로 모든 옵션의 추가금을 다시 계산하고 공통 가격 상속 상태로 복원한다. 할인 이외의 입력은 개별 추가금을 바꾸지 않는다. ‘공통 가격 다시 적용’으로도 자동 계산을 복원할 수 있다. 기존 등록상품은 조회값을 유지하며 명시적 공통 가격 적용에서만 계산한다.

할인 계산은 입력된 할인 설정을 기준으로 한다. 할인 기간에 따른 시점별 실제 결제금액이나 추가 쿠폰까지 동일하다는 보장은 하지 않는다. 원 미만 계산 결과를 임의 반올림·절사하지 않고 자동 추가금을 미확인으로 두며 입력 확인 안내와 저장 전 검증으로 차단한다. 마켓의 가격 범위 검증은 유지한다.

공통 기준 정보의 이미지·상세설명은 하나의 영역으로 유지하고 상품고시 기본 정보(소재·제조국/원산지·제조사·A/S)는 별도 영역과 이동 메뉴에 둔다. 이미지·설명 적용 대상 선택은 고시 입력에 영향을 주지 않는다.

공통 편집기의 공통 기준·마켓 선택 탭은 상단에 고정한다. 공통 기준 정보의 입력 구역 바로가기 메뉴는 표시하지 않는다. 쿠팡·스마트스토어의 입력 구역 메뉴는 마켓 탭 아래에 배치하며 탭 높이에 맞춰 겹침을 방지한다. 이번 전송 대상 선택은 하단 고정 작업 영역의 취소 버튼 왼쪽에 두고, 모바일에서는 버튼 위에 배치한다. 하단 영역 높이에 맞춰 문서 여백을 확보한다. 상단 저장 여부 안내 문구는 표시하지 않으며 미저장 입력 이탈 확인은 유지한다.

## R2 이미지 원본 선택 (2026-10-12)

공통 등록과 쿠팡·스마트스토어 단독 등록·편집에서 파일 업로드 버튼을 R2 이미지 조회·선택으로 교체했다. 상품 정보 도구의 업로드는 유지한다. 조회 코드는 공통 상품코드를 기본값으로 쓰되 별도로 수정할 수 있으며 상품코드·판매자상품코드를 바꾸지 않는다. 조회 후 상품코드의 루트에서 실제 하위 폴더명을 표시한다. 폴더를 클릭하면 그 안의 하위 폴더와 이미지를 표시하고, 상위 폴더 버튼으로 돌아간다. 조회 상품코드의 중복 버튼은 표시하지 않는다. official·processed 같은 고정 분류 버튼이나 기본 폴더 자동 진입은 사용하지 않는다. 선택 순서는 기존 대표 지정·정렬·옵션별 적용 기능으로 편집한다.

조회 입력 Enter는 조회만 실행하며 저장·전송을 실행하지 않는다. 조회·객체 확인 중에는 중복 실행과 편집 대상 전환을 막고 조회 및 선택 검증 실패 시 입력과 선택 목록을 유지한다. 이전 조회의 응답은 새 목록에 적용하지 않는다. 직접 URL 추가도 서버의 R2 객체 확인을 거친다. 이미지 UUID·옵션 UUID와 기존 마켓별 개별값·상속 상태를 그대로 저장하므로 탭 전환·임시 저장·재진입에서도 원본 URL과 순서가 유지된다.

쿠팡의 새 대표·추가 이미지는 검증된 R2 URL을 vendorPath로 보낸다. 스마트스토어는 전송 준비에서 R2 바이트를 이미지 API로 보내고 반환 URL을 해당 실행 전문에만 적용한다. 공통 문서를 네이버 URL로 덮어쓰지 않는다. 기존 CDN URL은 유지한다. 기존 로컬 자산의 표시·임시 저장·참조 보호는 유지하지만 이미지 추가·교체나 상세설명 이미지 전송에는 R2 재선택이 필요하다. 이미지·설명을 바꾸지 않는 기존 상품 수정은 해당 자산 때문에 차단하지 않는다.

목록·검증 API는 [R2 저장소 안내](../r2-storage.md)를 따른다. 기존 자산 업로드 API와 공개 토큰 설명은 과거 초안 호환 계약이며 현재 상품 편집 UI는 신규 로컬 파일을 업로드하지 않는다. ESM·롯데ON·11번가의 상품 전송은 이번 변경으로 활성화하지 않는다.

### 공통 탭의 마켓별 주소록 선택

- 배송·반품 구역의 `주소록 조회·선택`에서 쿠팡과 스마트스토어의 출고지·반품/교환지 목록을 조회하고 각각 선택한다. 선택 후 적용을 눌러야 공통 초안이 바뀌며 주소록 자체를 생성·수정하지 않는다.
- 선택은 `markets.{마켓}.addressBook.outbound/returns`에 저장한다. 주소 ID를 다른 마켓에 복사하지 않으며 공통 상품코드나 배송비는 변경하지 않는다.
- 쿠팡 신규 입력은 선택한 출고지 코드와 반품지 코드·연락처·주소를 배송값의 기준으로 사용한다. 스마트스토어는 `shippingAddressId`와 `returnAddressId`의 기준으로 사용한다. 마켓 탭에서 개별 수정한 값은 기존 상속 설정에 따라 유지한다.
- 기존 등록상품은 공통 주소 선택으로 덮어쓰지 않는다. 해당 마켓 탭의 주소록 기능으로 변경한다. 공통 등록의 쿠팡 탭에도 출고지·반품/교환지 조회 버튼을 제공한다.
- 사용 불가 쿠팡 주소는 제외하며 네이버는 출고/반품 주소 유형을 구분한다. 페이지 이동·실패 시 재조회·취소 시 미적용을 지원한다. 오래된 조회 응답은 닫힌 창이나 새 창을 덮어쓰지 않는다.
- G마켓·옥션·롯데ON·11번가 주소록은 이번 화면에서 연결 준비 상태로 표시한다. 기존 상품 전송 연결 범위를 확장하거나 롯데ON 배송지 번호의 불명확한 변환 규칙을 추정하지 않는다.

### 2026-10-12 주소록 조회 간격·접근 오류 보완

- 공용 `CoupangRead`는 같은 화면의 조회를 직렬 처리하며, 앞선 요청이 끝난 뒤 최소 1초를 기다린다. 주소록 모달의 출고지·반품지 자동 조회, 개별 재조회와 페이지 이동에도 적용한다. 대기 중 취소한 요청은 서버로 보내지 않는다. 이는 브라우저 화면 단위의 순서 제어이며 다른 사용자·브라우저까지 전역 직렬화하는 기능은 아니다. 서버의 기존 동시 실행 차단·호출 제한은 유지한다.
- 스마트스토어 출고지·반품지의 같은 페이지 조회는 진행 중 요청 하나를 공유한다. 성공·실패 후 재조회는 새 요청으로 실행하며 모달 종료 시 진행 중 요청을 취소한다.
- 네이버 403 응답의 알려진 오류 코드만 고정 안내로 변환한다. 외부 오류 메시지·임의 코드는 사용자에게 전달하지 않는다. 401 `GW.AUTHN`의 기존 1회 토큰 갱신과 403의 재시도하지 않는 정책은 유지한다.
- 실제 계정 읽기 검증: 토큰 발급 성공 후 `/v1/seller/addressbooks-for-page?page=1`은 **403 / GW.AUTHN**, 동일 토큰의 `/v1/categories/50003982`는 **200**이었다. 따라서 전체 인증 실패로 단정하지 않으며, 주소록이 속한 판매자정보 API 그룹의 실제 권한과 연동 계정 확인이 필요하다. 콘솔의 권한 누락 여부는 아직 확인하지 않았다. 공식 게이트웨이 안내의 401 GW.AUTHN과 실제 403 응답이 다르므로 HTTP 상태도 함께 판단한다. 실제 상품·주소록 변경은 수행하지 않았다.
- 참고: [네이버 공식 문제 해결](https://apicenter.commerce.naver.com/docs/trouble-shooting), [공식 지원의 403 GW.AUTHN 및 API 그룹 권한 확인 사례](https://github.com/commerce-api-naver/commerce-api/discussions/3802).

### 2026-10-12 첫 등록 전 점검 보완

- 공통 기준의 제조사·제조국·소재·A/S 안내 입력은 상품고시 기본 정보에서만 편집한다. 기타 설정의 중복 입력을 제거해 같은 필드 ID가 두 번 생성되지 않게 했다.
- 마켓 탭의 입력 검증은 해당 작업 문서의 변경을 서버 조회값과 합쳐 검사한다. 쿠팡·스마트스토어 모두 실제 이미지 검사 결과까지 확인하며, 다른 마켓의 이전 공통 준비 필드가 해당 탭의 검증 결과에 섞이지 않는다.
- 쿠팡 택배사는 표시명이 아닌 API 코드로 입력한다. 예: CJ대한통운은 `CJGLS`. 신규 등록 준비에서도 한글 이름·공백이 포함된 값을 차단한다. 이 검사는 코드의 실계정 사용 가능 여부를 보장하지 않는다.
- 두 마켓을 전송 대상으로 선택했어도 마켓 탭의 저장은 현재 탭 한 곳을 대상으로 한다. 공통 기준 저장은 내부 저장이다. 마켓 저장은 내부 초안 저장 → 전송 준비 → 확인창 → 명시적 실행 순서이며, 스마트스토어 이미지 업로드는 전송 준비 단계에 포함된다.
- 무료배송의 무료배송 기준은 `0`으로 입력해야 한다. 색상·사이즈는 해당 카테고리 구매옵션에 입력하고 옵션 이름을 분해해 추측하지 않는다. 판매 종료일시는 실제 운영할 기간으로 확인한다.


## 실제 이미지 검사와 서버 자르기 (2026-10-13)

입력 검증·전송 준비·실행 직전은 `ImageRules`와 `ImageInspection`을 사용한다. 입력 검증에서는 같은 URL/자산 파일을 한 번 읽고 사용 위치별로 검사 결과를 반환한다. 응답의 `images`에는 마켓·용도·옵션 UUID·이미지 ID·실제 픽셀·바이트·PASS/FAIL/UNVERIFIED·근거·권장사항이 포함된다. 쿠팡 대표·추가는 3MiB 이하, 500~5000px 정사각형 JPG/PNG와 대표 1개·추가 9개·중고상태 4개 제한을 적용한다. 상세설명에 상품 이미지의 정사각형 조건을 적용하지 않는다. 스마트스토어 1000×1000px는 권장 안내이며 필수 해상도로 차단하지 않는다. JPG/PNG·파일당 10MiB·25M 픽셀은 현재 앱 처리 제한으로 구분한다. HTML의 img src를 검사하고 srcset·배경·SVG·picture 등 지원하지 않는 참조는 미확인으로 안내한다. 기존 CDN 이미지 읽기 실패는 입력 검증 완료를 막지만, 이미지 변경 없는 가격·재고 전송을 새로 차단하지 않는다.

이미지 카드·설명 이미지·HTML 이미지 썸네일의 편집 버튼은 인증된 서버 미리보기와 원본 픽셀 좌표를 사용하는 공용 자르기 모달을 연다. 쿠팡 상품 이미지는 정사각형, 설명은 자유 비율로 시작하며 사용자가 비율을 선택할 수 있다. 이동·크기 조절·좌표 입력과 결과 크기 표시를 제공하며 자동 확대·축소·보정은 하지 않는다. 입력 Enter는 확인을 실행하지 않는다. 취소·오류 시 이전 입력을 보존하고 처리 중에는 중복 확인과 대상 전환을 막는다.

- GET `/api/marketplaces/image-edits/source`: R2 URL 또는 서버 편집 자산 ID로 원본 토큰 발급.
- GET `/api/marketplaces/image-edits/source/{token}`: 사용자에게 묶인 10분 만료 PNG 미리보기.
- POST `/api/marketplaces/image-edits`: 토큰과 `{x,y,width,height}`로 서버에서 정확한 범위 자르기. 원본 스냅샷과 PNG 편집본을 앱 서버에 보관한다.

V41 `marketplace_image_edit`에 원본 URL·스냅샷 ID·SHA-256·좌표·처리 버전을 보관한다. R2 객체는 변경하지 않는다. 재편집은 서버에 보관한 원본과 지문을 사용하고 원본 복원은 원래 R2 URL로 돌아간다. 기존 로컬 업로드와 달리 이 서버 생성 자산만 새 외부 이미지로 허용한다. 설명 IMAGE에 nullable assetId를 추가했으며 HTML의 내부 자산 참조도 초안·실행 기록의 정리 보호에 포함한다. 편집본을 참조하면 원본 스냅샷도 함께 보호한다. 미참조 편집본·원본은 기존 유예 정리 정책을 따른다.

이미지 UUID·대표·순서·옵션 소속을 유지한다. 쿠팡에서 상속된 공통 이미지/설명을 편집하면 sourceId로 원래 항목을 가리키는 해당 옵션의 개별 사본을 만들고, 같은 위치의 공통 항목만 대체한다. 다른 옵션은 원래 공통 항목을 사용한다. 변경 취소는 사본을 제거하여 상속을 복원한다. 개별 설명도 원래 설명 위치를 유지한다. 스마트스토어에서 편집하면 네이티브 이미지/설명 개별값으로 저장하며 공통 원본은 바꾸지 않는다.

쿠팡 상품·상세설명과 스마트스토어 상세설명의 편집본은 기존 `/marketplace-images/{token}` 공개 경로를 사용한다. `MARKETPLACE_PUBLIC_IMAGE_BASE_URL`의 기본값은 `https://molebutter.link`이며 별도 주소로 재정의할 수 있다. 실제 공개 HTTPS 응답이 보관한 편집본 바이트와 일치해야 통과한다. 네이버 대표·추가는 편집본 바이트를 기존 이미지 API에 전송하고 반환 URL을 실행 전문에만 적용한다. 실행 재시도에서는 준비한 네이버 URL을 재사용하며 파일 규격을 다시 확인한다. 실제 마켓 업로드·등록·수정은 명시적인 전송 실행에서만 수행한다.

## 마켓 최신 조회값과 앱 저장값의 양방향 처리 (2026-10-14)

쿠팡·스마트스토어·롯데ON·11번가는 같은 비교 영역을 사용한다. ‘마켓 최신 조회값 / 앱 저장값’과 현재 미저장 편집·전송 준비 변경을 구분한다. 차이만 발견됐을 때 자동으로 수정 전송하지 않는다.

**마켓 조회값을 앱에 저장**은 선택한 필드만 해당 마켓의 개별 저장값으로 반영하고 해당 보관 변경을 정리한다. **앱 저장값으로 수정 준비**는 저장 의도에서 선택한 필드만 UPDATE 변경으로 만든다. 공통 기준·다른 마켓·미선택 미저장 입력은 보존한다. 실제 전송은 기존 입력 검증·전송 확인을 거친다. 저장 의도를 확인할 수 없으면 ‘앱 저장값 없음’, 실제 관찰값이 없으면 ‘조회 미확인’으로 표시한다.

`POST /api/marketplaces/editor/resolve`는 서버 비교 토큰과 항목별 선택만 받아 최신 관찰값·연결·revision을 다시 검사한다. V43에 마켓·계정·연결 세대별 저장 문서와 항목별 선택 근거를 보관한다. 판매 시작/종료 설정은 각각 확인하며 브랜드 이름/ID만 함께 처리한다. 내부 선택 저장은 이전 실행 결과를 성공으로 바꾸지 않으며, 새 외부 실행에는 기존 실행 중·결과 미확인 차단이 유지된다. [구조·제한과 실행 검증](../verification/2026-10-14-marketplace-value-comparison.md)을 참고한다.

후속 실화면 검증에서 CREATE의 외부 ID 미발급 옵션 연결 틀을 기존 연결로 오인한 복원 오류를 수정했다. 실패 대상의 대량 미확인 비교를 억제하고, 저장값 없는 항목은 접어 표시한다. 쿠팡이 조회하지 않는 공통 제조국·소재·A/S를 빈값으로 채택하지 못하게 하며 스마트스토어 전용 설정의 다른 탭 노출도 차단한다. WCWA705R2의 실제 내부 저장·재진입과 시험 변경 복원 결과는 [실측 기록](../verification/2026-10-14-marketplace-comparison-live-fixes.md)에 있다.

비교 정책 v2는 내부 옵션명·미지원 공통 항목을 제외하고, 속성명/구매·검색 구분 및 옵션별 최종 이미지·설명을 비교한다. 파일 또는 픽셀 지문으로 확인된 CDN 변경은 차이가 아니며 동일성을 입증하지 못한 파일은 확인 정보다.
